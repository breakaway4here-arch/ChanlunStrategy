## 1. 产品定位：热点不等于推荐

用户贴文的长处是信息组织：先让人知道有哪些方向，再看每个方向有哪些股票、各自发生了什么。系统应学习这个组织方式，不把帖子里的全部结论直接复制成事实。

明确区分三个集合：

- **市场热点样本**：当日报告已经取得的涨停/活跃行情、明确关联股票的事件等，可以包含系统没有选中的股票。
- **系统已入池对象**：现有同日统一清单；继续保留主推、罗姐、等确认、基础候选等真实身份。
- **两者交集**：在热点卡上叠加“命中N池”和彩色来源标签。热点卡出现本身不增加一个命中池。

不能仅把当前80只候选分组后命名“全市场热门TOP30”。也不能因为用户原帖列了30只，就永久硬编码这30只，或每日只换日期。

本期只有12只可展示就显示12只。正式主推0只不妨碍热点模块有内容；热点数据缺失也不妨碍主推和日报发布。

## 2. 第一版界面：一张地图，两种读法

### 2.1 放置与导航

在现有“今日决策”的摘要或快捷入口加“热点地图”锚点。完整模块放在现有资金主线／涨停生态相邻区域；复用原始证据入口，不在首页堆三份相同信息。

不增加第二套“正式推荐／优先推荐”导航，不改变唯一“主推”入口。保留完整大盘依据和到候选工作区的直接入口，不把主推推到很长页面的最底端。

### 2.2 地图模式

按已有、能说明来源的题材/行业关系分组。每组使用固定色的标题条，组内股票使用等大小卡片。

卡片默认可见：股票名称与代码、可用的当日涨跌幅、已核实的涨停/连板状态、系统命中数量及池标签。原始分析文字放在详细清单或点击后的详情，避免把每张卡撑成长文章。

**颜色分工必须固定：**

| 视觉元素 | 含义 |
|---|---|
| 股票卡数值及轻背景 | 有可靠报价时按涨/跌/平显示；无报价用灰色，不填0% |
| 分组标题色 | 识别不同题材，不表示该题材收益更好 |
| “命中N池”徽标 | 复用现有彩色来源规格，表示实际来源池数，不表示涨幅或胜率 |
| 原文/事件标签 | 区分原始评论、已记录事实及模型归纳，不用统一“已确认催化”盖章 |

首版股票卡面积相同，不按猜测的热度、市值或“龙头等级”缩放。小屏改成单列题材、组内两列股票；名称、命中数量不依赖悬停，不裁掉风险。

### 2.3 清单模式

与地图共用同一集合，按列展示：股票、所属方向、行情及其时点、事件/原文依据、系统入池关系。

切模式不改变名单。搜索、题材筛选、只看系统命中均为阅读过滤，不改变底层池或排行榜顺序。

### 2.4 原帖四组如何使用

原型保留用户原文的四组：光通信10只、半导体5只、电子硬件8只、短线轮动7只。这仅是参考内容的组织，不表示系统已验证全部产业归属。

生产版不固定只有这四个题材，也不能将接口的“电子”全部改叫“PCB”、将“通信设备”全部改叫“CPO”。先显示来源提供的原始行业；已有明确题材关系时再作映射，并保留映射来源。没有细分关系时显示宽行业或“题材待补”，不阻断发布。

## 3. 自动内容来源：复用现有数据，不要求每天手工写长文

本次已核查的仓库能力：

| 现有数据/组件 | 可直接承担的责任 | 本次不推断的内容 |
|---|---|---|
| `sector_heat` / `sector_flow` | 已取得板块的涨幅、资金、成分引用和覆盖状态 | 不能把少数已抓取板块的排名称为全市场人气排名 |
| `limit_up_snapshot.items/theme_groups/leaders` | 涨停样本、行业分组、连板和已有领涨记录 | 不能把只含涨停的样本当成全行业涨跌分布 |
| `events` / `decision_brief` | 已有关联方向、原新闻文字、来源引用和分析 | 不把模型的影响推断直接当作已证实涨停原因 |
| 同日报告的 `decisionWorkbench` | 股票身份、各来源、状态、评分、现有详情引用 | 不因热点显示给研究对象升级正式身份 |
| 现有来源摘要组件 | “命中N池”、来源色签、派生榜单收录 | 不能把题材数量、页面数量加到命中池数里 |

### 3.1 数据模式必须可区分

**自动日报模式（生产默认）：**根据当日已有报告字段形成热点样本和事实摘要；按每次实际报告刷新，不依赖新增远程调用。

**外部名单模式（可选、可后续做）：**将用户提供的名单按原来源日期保存为只读参考。股票身份明确且有同日行情时叠加事实；分类与原文始终带外部来源标记，不覆盖自动数据。

本次交互原型属于第二种演示，用于看布局。不能直接把原型的固定名单或测试数据接进日常自动生产。

### 3.2 第一版不伪造TOP30

初版标题建议“今日热点地图”，旁边标“展示N只 · 当前数据覆盖范围”。30是可配置展示上限，不是必须凑满的数量或经过验证的全市场排名。

列表按已有可信源顺序/原名单顺序展示；需要“按涨幅”“按连板”时，按钮明确写该字段，缺值放到对应未知区。不要混算一个新的“热度总分”，也不要拿选股决策分当人气分。

若后续要真正自动生成“全市场热门TOP30”，需另行确定市场范围、行情覆盖、热门定义和排序口径。首版不用等它完成；也不承诺现有少量数据能覆盖中际旭创等所有未涨停的人气股。

### 3.3 简短盘面小结

第一版使用确定性短句足够，例如：

> 在本次取得的涨停快照中，X方向有N只记录；本系统清单命中M只。部分股票的新闻原因尚未补齐。

能算就算，缺什么只省略相关分句。板块完整成分未齐时，用“已取得样本中”，不写全行业平均或全市场覆盖。

已有LLM分析可以作为独立的“模型归纳”折叠说明；不新增一次必须成功的LLM请求，不以“AI小结生成失败”阻止地图或日报。

## 4. 股票点击与原文解释

### 4.1 分开事实、事件和解释

用户原帖有“回购加持”“海外大单”“机构持续加仓”“游资主导”等不同性质的表述。不能仅凭末尾风险提示，就当作全部可核验数据。

| 内容 | 展示约定 |
|---|---|
| 当日价格、涨跌幅、连板 | 优先显示已取得快照数值、行情日期和时点 |
| 公司业务/产业链归属 | 来源明确时作分类；外部名单分类独立注明，不用模型常识静默改写 |
| 公告或新闻事件 | 保留事件日期、发布时间和来源；旧公告不能在今天重新写成“今日突发” |
| 资金流数值 | 必须带实际字段含义和单位；不推出交易者身份 |
| “龙头”“游资抱团”“机构加仓”等评论 | 放在“外部原文／未核验评论”，不能转换成系统确定性结论 |
| 涨停原因 | 只有相关背景时写“关联事件／市场解读”；相关不等于已证实触发因素 |

无需把全部评论核实齐才显示股票。没有原因就写“原因未补”，其他行情继续展示；来源冲突在详情并列，不自动选择更乐观的说法。

### 4.2 详情入口

- **同日、同证券身份有现有系统对象**：调用已有桌面/手机详情入口，复用正确来源的K线、风险、评分和池标签。
- **有行情身份，但本期未入池**：只读热点详情，展示行情、关联事件和“本期系统清单未入选”；不得偷偷加进主推、全部或观察池。
- **仅外部名称，身份未解析**：原文仍可读，显示“身份/入池待关联”，不靠相似名字错配股票。
- **没有可靠K线**：不显示图或显示局部缺图说明，不跨来源借图，也不为了点击成功调用生产选股。

行情时间与报告时间分开；不把9月16日盘后快照当作此刻实时价。旧报告始终显示旧日期，不能随打开当天更新。

## 5. 最短实现路径与范围

主要改动：`chanlun/report_assets/report-v2.js` 的一个局部只读模型与热点渲染块、`report-v2.css` 的局部 `.hotspot-*` 样式，以及现有资源发布流程。

现有定位点包括 `buildFundingMainlineModel`、`renderFundingMainline`、`renderLimitUpEcologyCard`、`renderDecisionDirections`；按最新工作树定位实际函数，不要求硬套旧行号。它们原有数据定义和校验不重写。

建议分为两个小提交：

| 小批次 | 交付结果 | 不等待什么 |
|---|---|---|
| H1：地图与清单 | 用已有快照显示分组卡片、搜索、模式切换、日期/来源与局部空态；快照无个股时仍可显示已有板块信息 | 不等新数据源、人气排名、完整文章归因 |
| H2：系统来源联动 | 同日身份匹配、复用彩色池标签、只看系统命中、正确桌面/手机详情 | 不等评分研究或历史T+5 |

若来源摘要任务正在改同一个JS文件，由当前负责人在安全节点串行集成，不能两个执行者各自覆盖。H1独立通过可以先交付；新任务不能扣住已经验收好的主推/标签版本。

不建新的证券主表、全市场实时服务、泛化图谱、多合同归约系统或新推荐算法。首版优先普通HTML/CSS卡片；确需矩形树图时可复用已有ECharts，但图表库异常时清单仍可用。不要让这个小模块引入另一套大图表依赖。

## 6. 缺失和失败的处理——不提高上线门槛

| 情况 | 允许且应当出现的结果 |
|---|---|
| 没有个股涨幅 | 灰色卡片／“报价暂缺”，仍显示名称与已有来源 |
| 没有完整题材映射 | 用源行业或待分类，不伪造CPO/PCB成员 |
| 没有解释/LLM失败 | 行情和板块继续展示，不生成推测理由 |
| 热点模块整体失败 | 仅模块暂不可用，原主推、观察、图表和当日日报继续 |
| 部分来源缺失 | 当前有效样本继续，披露样本范围；不自动从昨日借来充数 |
| 少于30只 | 显示实际N，不加补数或重跑任务 |
| 已入池来源标签未适配 | 该行“来源待补”，不清空股票、不改变原入池状态 |
| 数据出现身份/日期错配 | 关闭错误映射或具体字段，不输出假行情；不扩大成其他有效内容的阻断 |

不新增“至少30只”“所有热门股都必须有K线”“全部原因核验完成”“必须有2池命中”“整套市场分析齐全”等发布条件。不扩分钟预算、不重跑生产、不写库/账本、不新增推送或自动加自选。

## 7. 本批只验八件事

1. **集合**：同一题材内同证券去重；跨题材可重复展示但总人数去重统计，题材归属数与股票数分开；默认主分类不按未来表现改变。外部名称未解析不伪装成独立证券数。
2. **日期与事实**：过期/不同日期的报价不装成当日，未知不填0%；正常字段不因其他字段缺失一起丢掉。
3. **来源**：原帖评论和事实分区；重复榜单收录不增加来源池命中数；主题分类不增加命中池。
4. **名单保护**：热点未入池对象仍能查看，但不会进入系统主推/全部清单；没有证据不自动加“已确认”“可执行”。
5. **交互**：搜索、清空、题材筛选、只看入池、图表/清单切换用同一模型；实际点击的名称、日期、来源正确，返回不丢当前筛选。
6. **小屏**：1440与390宽度不横向溢出，名称/数量/池名实际可见，不靠hover；详情开关正常，长原文可滚动。
7. **局部降级**：人为断开热点数据或分析，主要候选、图表及日报发布不受影响；不新增发布校验字段。
8. **发布**：新JS/CSS与实际资源一致、记录线上代码版本和数据日期；测试原型及其原帖固定名单不能覆盖正式HTML或原始日报。

原型目前已完成上述搜索、筛选、地图/清单、详情与两种视口的独立交互检查；这不是仓库集成、全站或生产发布验收。实际回执只需说明本批完成、局部缺失、版本/数据日期和未做项。

## 8. 本次交互原型说明

`热点地图_交互原型.html` 为单文件、无外网请求的可交互演示。用户原帖30个名称和全部说明保持原意；原帖编号重复不作为排序分数使用。

数值报价只从已上传的16日涨停快照按确定名称取得，共20/30；10只保持缺失。本期冻结系统清单可匹配6只已入池：光迅科技、有研硅、中晶科技、晶升股份、致尚科技、民德电子。这个交集不是全市场覆盖率，更不是当前候选召回率。

原帖和冻结行情不互相替代：原帖称某股涨停但快照没有该股时，不能推断其未涨停；没有命中证券身份时不推断未入选。已关联股票的“16日清单未入选”仅相对于那份80只冻结清单。

原型用于确认视觉与阅读路径，不是生产模块。不连接真实图表、不改自选或持仓，全部来源和限制可点开查看。
