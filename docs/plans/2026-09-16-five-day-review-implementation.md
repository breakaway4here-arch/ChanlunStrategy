## 1. 五日证据支持什么，不支持什么

五日复盘记录了3条正式来源信号，均有普通30分钟形态与“回踩确认”加分的语义疑点，且缺完整执行条件；复盘价格集合还漏掉9条罗姐来源的代码。[S1：第四、七节]

这些证据支持**修语义、修消费者覆盖、明确状态**。它们不证明新排名能赚钱，也不证明取消市场限制更好。前三名后续落后只是小样本迹象，不能反向排序。[S1：第五、八节]

保留以下口径：

- 132条是当前发布归档的展示记录，不是132次成交，也不声称恢复了每个日期最初发布时的全部状态。
- 冻结输入截止9月15日收盘：前四组101条已到T+1，其中91条有价格对、10条缺失；9月15日31条在该输入内尚无完整T+1结果。
- 后续补到9月16日数据时另记结果更新时间，不能覆盖冻结名单或把新结果倒灌为当时已知信息。
- 旧版与decision-v2分开。当前版本不能冒充旧版引擎重放；显示的原分数不是统一的胜率尺度。
- “62→47”仅是既定条件下移除15分贡献的敏感性算术，不是本方案要求硬凑出的生产结果。

## 2. 最重要的约束：把三类门槛拆开

### 2.1 日报发布、交易条件和新功能验收，不用同一个开关

| 层次 | 决定什么 | 不得用来决定什么 |
|---|---|---|
| **日报发布** | 正确日期下，已通过现有必需校验的内容能否生成和发布 | 不等所有研究输入、复盘端点和新策略实验齐全 |
| **某股/某策略的执行条件** | 该对象是否有对应策略所需的有效依据 | 不能因为一只股票缺价位就阻止其他股票或整份日报 |
| **本批功能交付** | 新代码是否实现预定行为、是否破坏旧功能 | 不要求历史全量测试、未启用增强、未来T+5全部完成 |

**继续显示数据 ≠ 宣布可以交易；正常发布 ≠ 全部数据完整。**

### 2.2 本批固定的降级裁定表

| 情况 | 必须保留 | 降级动作 | 是否阻挡其余有效日报 |
|---|---|---|---|
| 罗姐15分钟整体不可用 | 其他正式/研究/日线结果 | 使用已有不可用合同，罗姐不产生新的研究候选，页面说明缺失 | **不阻挡**；沿用已授权逻辑 |
| 罗姐部分核验 | 已逐股核验的合法研究结果及缺口 | 继续partial，未核验部分不冒充有效 | **不阻挡**；不要求补到100% |
| MA、量能、成交额、非必要市值缺失 | 有效K线、价格和其他理由 | 对应字段“未提供”；不新增整股冲突 | **不阻挡** |
| 股票缺执行参考价、失效位 | 原策略结果、评分、行情与已有理由 | 显示“执行条件未完整”，保留原身份 | **不阻挡**；不自动形成执行计划 |
| 复盘缺某端点价格、T+3/T+5未到期 | 完整样本行、原名次、身份 | 对应结果留空，分别写缺价/未到期 | **不阻挡** |
| 复盘索引读不到、分析脚本超时或失败 | 主报告及已生成的有效内容 | 复盘模块暂不可用；保留错误与旧索引原日期 | **不阻挡** |
| R1离线实验失败、旧版本不能重放、没有收益结论 | 现行生产策略、原报告 | 只停用该实验结果，继续定位 | **不阻挡** |
| 正式结果合法为0 | 日期、质量说明及所有其他有效内容 | 显示“本期无正式推荐”；不填观察票凑数 | **不阻挡** |
| 某条错误身份、跨价基混用、未核验价被用于计算 | 其他可靠字段及其他股票 | 隔离错误引用/该计算，原值只读并标明用途 | **不阻挡已隔离后的其余内容** |
| 必需正式输入不符合现有正式发布合同 | 可追溯原始产物和明确错误 | 不伪装为正式有效；按现有诊断或上期有效结果处理，日期不改 | **沿用原保护，不在本批偷偷关闭** |
| 整份报告日期/身份串乱、隐私泄露、产物不可原子发布 | 最近一次有效发布及其真实日期 | 停止替换线上产物；修共享问题 | **阻挡该发布**，不能假装局部缺失 |

**本批不新增“复盘覆盖率低于X就不发布”“至少N只候选”“T+5齐全”“所有评分都能完整解释”之类规则。**

已有CI和正式数据保护继续生效；过时测试按本批已确认需求改预期并解释，不靠忽略退出码、删失败用例或一律返回True放行。

### 2.3 失败应有结果回执，不能一小时后才说没上

在现有任务日志/执行回复里分开记录：`代码部署`、`目标交易日报告生成`、`目标交易日报告发布`、`当前线上数据日期`、`局部降级项`。

一旦确认发布失败，立即说明卡在哪一层和是否仍有可安全发布的部分；不要等所有可选任务重试完才汇报。不得把“新JS已上线”说成“新交易日数据已上线”。

示例（格式建议，不要求新建通知系统）：

```text
目标交易日：YYYY-MM-DD
代码部署：已完成 / 未完成
报告：已生成 / 未生成
数据发布：已发布 / 未发布；线上数据日期：YYYY-MM-DD
局部限制：罗姐15分钟不可用；复盘T+3未到期
真正阻断：无 / <具体必需输入或产物错误>
```

不无限重试。复用现有请求超时和重试预算；本批新增复盘默认不请求外部行情。授权范围外的资源消耗、补数和写入才另行确认。

## 3. R0：守住“可用数据先发布”的现有路径

### 3.1 代码落点

核对 `scripts/validate_today_report.py` 的 `_luojie_partial_contract_is_safe()`、`_luojie_unavailable_contract_is_safe()` 与 `validate_report_contract()`；检查 `chanlun/report_generator.py` 到 `write_comparison_index()` 的调用及实际发布入口。

固定基线已经包含“罗姐明确不可用、候选为空且禁止研究/正式动作时，可以局部降级”的处理，不重写它。[S3]

### 3.2 最短实施方式

1. 先运行第7节R0的4组定向场景。通过则只补缺失的回归，不改生产发布条件。
2. 新增复盘分析放在独立的只读执行入口，优先作为主报告发布后可单独运行的任务；不把它插进必经评分/选股链。
3. 若发现原复盘索引调用的I/O错误确实向上阻断主报告，仅在该可选调用边界捕获可解释的异常，写明复盘失败；必需日报校验异常仍向上传递。
4. 新索引以临时文件验证后原子替换。失败保留旧文件的原日期，不用旧结果冒充本期；页面发现索引日期落后，显示其覆盖截止日。
5. 新复盘不做外部补数，不能通过等待更多行情来拖住发布。若需要隔离可能挂住的本地工作，使用已有任务预算/独立进程边界，不在主进程无限等待。

**不合格做法：**外围包一个大`try/except`把全部错误吞掉；把正式输入失败标为verified；把非空非法研究池清空后声称健康；把所有模块改成disabled来通过。

### 3.3 本任务完成条件

“有效主报告＋可选缺失”能够通过现有合法发布路径；“必需输入确有错误”仍被正确识别；日志分别说明代码与数据发布。**不要求当天一定存在正式推荐。**

## 4. R1：两处评分语义，先做可交付的小实验，再独立切换

### 4.1 范围与输出

主要代码：`chanlun/decision_engine.py` 的 `_calc_structure_score()`、`_is_confirmed_by()`、`_is_sector_hot()`；直接调用者的字段适配；`report_view_model.py` 正式准入消费者仅用于检查变化。

先冻结实际生产输入和版本，在隔离目录输出：

```text
日期、标的、策略与版本、原有输入
候选规则、采用的确认类型/资金语义及来源
原分项、候选分项、差值、原决策、候选决策
可重放 / 仅敏感性算术 / 版本或输入不足
```

建议在已有测试/实验框架内增加纯函数或窄适配器；候选逻辑的默认生产入口不启用。不为这两处规则新建统一策略平台。

**离线对照不写正式报告、正式账本和通知。不将缺字段替换成一个方便计算的值，再宣称重现了原评分。**

### 4.2 R1-A：回踩加分只给已证明属于回踩的确认

固定候选规则如下；这是本方案提出的实现规则，不声称当前代码已满足。

| 已有输入 | 候选处理 |
|---|---|
| 同一来源明确、可信的回踩确认真值，且没有相互矛盾的声明 | 保留原回踩贡献+15，不增加额外指标门槛 |
| 明确回踩未确认/为假 | 不给该项+15；其他信号和贡献继续计算 |
| 只有“30min确认”“两阳夹一阴”等通用形态，回踩未声明 | `unknown`，不冒充回踩；不领取该项+15，保留分钟形态 |
| 既有结构化确认类型能按当前定义明确映射为回踩 | 按经审查的有限映射处理，并保留来源；不得根据自由文本猜测 |
| 真/假冲突、来源不对应 | 该贡献无法确认，保留原因；不把整个候选清空 |
| 其他启动/突破策略不使用回踩加分 | 维持它们的原逻辑，不增加“必须等回踩才有候选”的新准入 |

实施时先列出当前直接调用者真正使用的明确字段/枚举；缺少这些字段的旧记录保持未知。**不要求为了给一个现有真值加分，补齐全套分钟、量能、合同、历史指标。**

不要全局改变 `_is_confirmed_by()` 的“是否有一般确认”含义，以免其他合法消费者退化；回踩专用判断放在最短需要的位置。

不把未知写成false回传生产；不保留+15仅改名为“分钟确认”冒充语义修复；不事后补造星德胜的回踩记录。

### 4.3 R1-B：原始资金金额不参加标准化强度阈值比较

1. 在调用边界核对 `sector_flow` 的生产者与单位。只跟踪相关链路，不要求全仓资金字段统一迁移。
2. 原始金额、单位未知的旧值，不直接与`0.6`比较；不能根据数值大小自动猜它是元、亿元还是强度。
3. 保留已有明确热点标签与排名规则的有效分支。固定基线的“前8名”分支不在本批改权重或改阈值。
4. 只有当已有字段明确代表标准化强度、定义与阈值匹配时，才继续该强度分支；没有现成可证明字段，就让这一分支暂不提供热点依据。
5. 金额仍可按真实单位显示，不因此清空板块、股票池、其他评分贡献或正式输入健康状态。
6. 继续保留原热点贡献的权重；仅纠正何种证据能触发它，不为让样本落选临时调分。

**不合格做法：**一律除以一亿；一律将正流入作为强板块；一律删除板块加分；给缺字段补假强度；把没有强度改成行情抓取失败。

### 4.4 固定输入验证，不要求五日样本证明赚钱

两处规则分别运行单因素对照，再看组合变化。先验证现行引擎能够重现相应版本的原分项；不能重现则标明原因，暂不出该条候选总分。

旧版引擎不可取得时，旧样本只作字段审计或明确标注的贡献敏感性分析。**不要求先恢复全部旧版环境，才允许修复现行版本的明确错误。**

对受影响记录输出所有升降变化；保留不受影响的正常正例。不只挑三只亏损股，也不只挑能降低分数的输入。132条适合作固定观察集合，但不能代替各版本完整原始评分输入。

### 4.5 什么情况下可以切换生产规则

由实施者提交两张简短表：字段/语义规则表、固定输入变化表。明确本次是“纠正已确认语义错误”还是“策略偏好调整”，两者不混同。

纠正明确错误的通过标准是：预先声明的贡献变化正确、正常正例不退化、相关调用者一致，且不产生额外发布阻断；**不以五日平均收益提高、三只全部落选或所有未来T+5到齐为条件。**

经有效策略变更授权后，一次切换一个修正并记录生效日期和新策略版本；旧报告、旧分数、旧推荐身份不重写。样本仍不支持新排序或盈利保证，不把正确性修复宣传成收益优化已验证。

未得到切换授权、对照未通过或研究尚未完成：保留现行版本并明确受影响评分依据正在复核。**评分修复任务可暂缓；正常日报不能因此停跑。**

## 5. R2：补复盘覆盖，价格取不到也要把对象留下

### 5.1 要交付的结果

固定五日样本能按原范围登记132条日期×标的；同日跨视图不重复算新标的，118只不同股票保持可核对。9月14日遗漏的9只罗姐代码进入登记及本地价格查询集合；华之杰仍缺价格时保留缺失。**登记完整不等于价格完整。**[S1：第二、七节]

这些是冻结样本的验收数，不是以后每天必须凑够的生产数量。

### 5.2 唯一需要改的消费者路径

重点检查 `chanlun/report_comparison.py` 的 `_source_views()`、`_comparison_report_dates()`、`_read_report()`、`build_comparison_index()`、`_read_final_prices()`；读取同报告展示投影的窄适配，以及现有复盘显示消费者。[S2]

采用以下顺序，不用最新策略重算历史名单：

**第一选择：**生成/发布时已有的、同日同版本有效 `decisionWorkbench.items`，记录来源快照标识。对已有归档，通过仓库既有HTML bootstrap读取方法静态提取，不执行网页脚本、不保存访问配置或私人字段。

**兼容路径：**无法得到该展示投影时，使用同日报告原workspace，并注明“旧视图口径，覆盖未确认”。不静默把它当完整全集，不因此令整个日报失败。若能证明另一个保存层是同一发布事件的有效投影，才补入；不直接把所有raw候选并入正式样本。

**一致性要求：**获取新展示全集后，不再因为旧workspace某视图非空就提前返回。登记集合来自确定的快照；价格查询集合可以合并原索引已有合法代码以保兼容，但这些额外代码不自动成为本期样本。

若同日报告有原始发布快照和后修展示快照，分别记 `snapshot_kind`，不得混成“当时用户一定看到”。缺首次发布时间就留空，不倒填。

### 5.3 不破坏现有索引合同

优先在现有索引增加兼容的登记/诊断字段；旧 `views`、`prices`、交易身份与既有正式样本排除规则不能被重定义。确实无法兼容时，单独写一个可选复盘旁路文件，旧入口不变；不要为了本批把全前端迁到新schema。

**正式样本健康/事故排除与观察登记分开。**被正式绩效规则排除的行可保留只读追溯及排除原因，不能因它存在于展示全集就重新计入正式推荐收益。

数据去重键采用报告日期＋已验证证券身份；各来源策略、版本、原名次放在来源记录中。跨日同股保留为重复出现；身份无法消歧的记录留在异常清单，不强行合并，也不让其他正常对象消失。

### 5.4 每条最小复盘记录

以下是建议的派生输出字段，不是要求改正式报告schema。能复用已有字段就复用。

```text
report_date / snapshot_id / snapshot_kind
instrument_id / code / name
sources[]：原视图、角色、原名次、策略版本、原评分与原动作
current_execution_status：仅采用该快照已有状态
signal_date：已有则保留，缺失不自动当新信号
first_seen_in_window / occurrence_in_window / window_start
horizons[T+1,T+3,T+5]：目标交易日、成熟状态、端点价格、来源、价基状态、结果或缺失原因
```

这里只记录**窗口内首次出现**，不能写成上市以来首次或策略历史首次。再次入选也不等于新信号已确认；事件依据不完整就注明未核验。

### 5.5 端点与结果的规则

| 项目 | 实施规则 |
|---|---|
| 价格 | 只复用现有本地/发布的合法价格；不新增网络取数，不借不对应来源补洞 |
| 交易日 | 用已有可信交易日序列定位T+1/T+3/T+5；不能用“下一个有价格的日子”或“下一个有非空推荐的报告”替代 |
| 空选日 | 保留为真实交易日，不能因视图全空就在复盘日历里跳过 |
| 未到期与缺价 | 未到目标收盘＝pending；目标已到但无端点＝missing；日历不能确定＝maturity_unknown，分别显示 |
| 复权/身份 | 已知跨价基、错误身份或冲突时不计算该项；不自动复权或借价 |
| 旧索引元数据不足 | 保留旧值和来源；既有同索引、明确身份/日期、无已知冲突的内部诊断可以保留“内部口径、价基元数据未完整”标记，不升级成已核验收益。新的无法证明可比的配对只并列原值 |
| T+N含义 | 信号日收盘至目标日收盘的价格路径；不等于盘后可成交收益，不等于触发后交易利润 |
| 策略/个人收益 | 无预先固定的触发、成交与退出规则或无实际成交记录时不计算；本批不新建交易回测 |

不要因为本批新增元数据字段，让过去所有可读报价都消失；也不要为了图表饱满取消原有价基保护。缺失只影响相应计算。

### 5.6 分母、统计和首次/重复必须清楚

每组同时给出：总登记数、已到期数、可计算数、缺价/不兼容/未知数量、待到期数量。每条端点都有唯一主结果状态，详细原因可多个，汇总不能重复累计。

已到期样本的统计分母是实际可计算数，同时披露它占已到期样本的比例。缺失不填0、不删行；未成熟不算失败。覆盖不完整时允许给出“已覆盖子集”均值和中位数，不声称总体无偏。

正式/研究/基础按来源身份分别统计，混合角色保持可见；多源分组相加可能重叠，不能再相加成总股票数。不同策略版本分开；重复出现单列。没有正式信号时相关交易统计是“不适用”，不是0%或100%。

优先沿用现有视图和汇总展示，不新开大型看板。首次交付可以只有完整登记、明确缺失和简单摘要，T+3/T+5价格不全不阻碍交付。

## 6. R3：只收口用户会误解的几个地方

### 6.1 原结论、当前条件、后来结果三层显示

复用现有状态，不另建前端判分或准入规则：

```text
原策略结果：<日期、来源、原动作、原分数与版本>
当前执行条件：<该快照已有状态与具体缺项>
复盘结果：<观察周期、数据截止、可比状态；未到期/缺价则留空>
```

不可执行时，主提示不能继续无条件使用“可上车、偏执行优先”。原推荐不删除，放在有来源和日期的原结论中。缺价位时不补猜测止损，不把原策略身份改成研究以美化表现。

已修正确的文案只验收，不重做。此次修复不会强制每个研究对象具备完整交易计划才可展示。

### 6.2 排名和分数不暗示胜率

看点榜保留原名次，补短说明“研究阅读顺序，不代表次日收益排名”；不要反向排序或按今天涨幅给昨天的名单重新排队。

继续遵守既有正式分与研究原始分的显示边界。未校准分数不转成胜率；旧版92与新版62不跨版本排序。

### 6.3 已有风险与重复出现

把原快照中的核心风险放在关注理由附近，不只保留强启动标题；未知不写无风险。可增加“本窗口第N次出现”，与原信号日期分开。

这只是读取与解释，不改变选股。不要求为了显示风险接公告服务、重算所有MA或补齐分时。

## 9. 发布、回滚与历史保护

### 9.1 本批代码发布只检查四件事

1. 本批目标行为实现，直接上下游和已有关键使用路径不退化。
2. 新增缺失/异常会局部降级，实际显示的信息没有错标的、错日期、错价格用途。

**不要求**：132条全部有价格或100%行情覆盖、完整分钟回放、T+5成熟、所有正式信号都上涨、实验胜率提高、全部旧增强功能完成。上述内容不能被临时加入发布前置条件。

### 9.2 数据刷新不等于重新选股

UI改动用现有静态资源同步流程；需要重建展示/复盘派生值时，只使用固定已存输入的只读路径。正式JSON、账本和历史推荐保持不动；只改允许的派生输出，并记录构建版本。

没有足够源信息重建历史展示时，保留原页并注明本模块暂不可重建，不用截断JSON覆盖原完整页面。诊断包、脱敏样本禁止作为生产首页替换源。

自然日报按已有日程继续。未授权不手工触发生产补跑、下载更多分钟、写库或推送通知。

### 9.3 回滚只回本批错误代码/派生资源

失败的候选功能局部关闭或回退；不得回滚已新增的交易日报告，不用旧manifest/旧首页连带覆盖最新日期。需要重新呈现最新数据时，使用保留的最新合法数据与回滚后的兼容代码。
