# 榜单表现比对功能设计

## 目标

在现有日报首页和独立比对页中，提供“榜单日收盘价到历史报告日收盘价或当前价”的表现比对。功能覆盖主推、看点 Top10、观察 Top5、加速、罗姐池、等确认、高弹性观察 Top10、基准八个榜单，首先回答实际涨跌，再用沪深300同期涨跌和超额收益提供市场背景。

## 已确认口径

- 榜单基准价：榜单日收盘价。
- 历史对比价：所选对比报告日的收盘价。
- 当前对比价：用户点击“刷新对比价”后批量取得的当前价。
- 实际涨跌：`对比价 / 榜单日收盘价 - 1`。
- 沪深300同期涨跌：同一榜单日到同一对比时点的涨跌。
- 超额收益：个股或榜单实际涨跌减去沪深300同期涨跌。
- 榜单统计：平均涨跌、中位数、上涨比例、最大涨幅、最大跌幅、有效样本数和缺失数。
- 同一股票可分别计入多个榜单；“全部榜单汇总”按股票代码去重。
- 停牌或取价失败不进入收益统计，但必须显示缺失原因和数量。

## 日期与数据范围

- 网页端仅保留最近 26 个正式报告日，周末和节假日不占名额。
- 对比日期不得早于榜单日期。
- 本地共享数据库保留完整历史，不因网页保留窗口而删除数据。
- 发布到网页的数据只包含最近 26 个报告日八个榜单出现过的股票及沪深300，不发布全市场价格。
- 首页默认使用上一个正式报告日作为榜单日，对比目标为“当前”。

## 数据架构

1. 日报生成阶段从共享 SQLite 行情库读取正式收盘数据，生成轻量的 26 日榜单价格索引。
2. 历史比对完全由静态价格索引完成，不请求远程行情。
3. 页面初次打开不获取当前行情；当前价、沪深300当前点位和行情时间仅在用户点击按钮后通过 Cloudflare Worker 批量取得。
4. Worker 限制代码格式和单次代码数量，按行情源支持的批量大小分组请求，并返回逐项状态。
5. 刷新结果只更新浏览器当前页面状态，不覆盖历史日报或共享数据库。

## 页面设计

### 桌面端

- 顶部：榜单日期、对比日期、手动刷新按钮和行情时间。
- 总览区：去重股票数、平均涨跌、中位数、上涨比例、沪深300涨跌和整体超额收益。
- 图表区：八个榜单的实际平均涨跌横向柱状图，以沪深300涨跌作为统一基准线；不以超额收益替代实际涨跌。
- 主从区：左侧约 30% 显示八个榜单表现与切换入口，右侧约 70% 显示所选榜单的个股明细。
- 个股表格：股票、所属行业、当时排名、当时决策、榜单日收盘价、对比价、实际涨跌、沪深300涨跌和超额收益。

### 手机端

- 顶部控件纵向排列。
- 总览和榜单按单列卡片展示。
- 榜单明细使用股票卡片代替宽表格，避免横向滚动。

## 交互与状态

- 对比历史报告日时，按钮显示“开始比对”。
- 对比当前时，按钮显示“刷新对比价”。
- 未刷新当前价时明确显示“尚未刷新”，不得使用历史价格冒充当前价。
- 请求期间禁用按钮并显示加载状态；成功后显示行情时间。
- 部分股票失败时展示可用结果和失败数量；整体失败时保留已有结果并显示错误。
- 红绿颜色由实际涨跌决定，超额收益使用独立的小标签，避免“实际亏损但跑赢指数”被显示成上涨。

## 验收标准

- 首页和独立比对页都能完成最近 26 个正式报告日的比对。
- 页面打开时没有当前行情请求；只有点击刷新按钮才发起批量请求。
- 八个榜单、整体去重汇总、沪深300和超额收益计算均有自动测试。
- 桌面端采用宽屏主从布局，手机端无强制横向滚动。
- 数据缺失、停牌、接口部分失败和整体失败都有明确状态。
- 生成器、前端资源、Worker 和现有日报校验测试全部通过。
