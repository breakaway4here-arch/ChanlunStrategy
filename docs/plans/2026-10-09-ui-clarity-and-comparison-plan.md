## 0. 执行摘要与交付范围

用户反馈：H4 T+3、门控运行诊断、策略收益记分牌、PSY12 影子验证看起来没有数据或没有重点；“变化复盘”难以理解和使用。

本方案把这些问题拆成两批：

| 批次 | 本批必须交付 | 不要顺手做的事情 |
|---|---|---|
| A：纠正信息 | 正确选择上份比较快照；保留全部不可比较对象及原因；未比较不显示零；显示已有 PSY12；区分本期与历史运行；恢复同快照内已有名称和来源 | 不改正式策略、评分、风险、收益门槛；不补造数据 |
| B：改善使用 | 记分牌改成验证进度；研究实验简化；运行诊断折叠；“变化复盘”改为“名单变化”；当前/历史操作分流；差异明细就近显示 | 不换框架，不新建一套研究系统，不新增自动交易或生产通知 |

最终用户应能迅速回答：

1. 本期有哪些正式推荐、哪些只是研究观察，信息有什么限制？
2. 相比上份已发布报告，哪些对象加入、移出，哪些已核验条件发生变化？
3. 各研究模块是有结果、待到期、无样本、数据缺失、未启用，还是仅有历史记录？

**交付不是把所有模块都“做成有数据”，而是让已有数据可读、真实缺口明确、重要异常可见。**

## 2. 全批次不可退化的边界

### 2.1 业务与数据保护

1. 不改召回范围、资格、信号确认、评分、排序、参考价格、买卖条件、研究转正式规则。R1 评分切换不在本批。
2. 保留“正式 / 研究 / 基线 / 门控”身份，以及策略版本、政策版本、报告日期和价格依据。不能跨身份合并收益。
3. 缺失、未到期、未启用、未核验、异常和真实零值必须分开。`null` 不转为 `0`，也不能用 `Number(null)` 等隐式转换生成零值。
4. 同一代码、同一日期或仅剩一条记录，不足以证明可以跨来源借字段、借图、拼价格或合并版本。复用项目已有身份解析与严格核验。
5. 价格依据不足时，只关闭相关数值比较；原文、名称和其他有效字段继续可读。未核验价格不能画成正式参考线。
6. 不改已有正式日报原始事实、账本和历史登记；不全量回填，不为更新 UI 重跑生产日报、预跑或通知。
7. 保留上一轮已上线的 14:56 交付、预跑状态、页面读取、风险判断、日线修复、分钟最终采纳、研究观察和复盘快照保护。
8. 不通过完全关闭名单变化、删除实验数据或隐藏真实运行故障，伪装完成本次目标。

### 2.2 本期、今天、历史的统一用词

“本期”指当前打开报告所绑定的报告日期与运行身份，**不是浏览器今天的日期**。例如打开 10/8 报告时，门控摘要应写“本期 10/8”，不能暗示 10/9 已经正常运行。

预跑实时区域继续使用其独立时间、有效期及状态合同，不用静态日报状态覆盖它。历史版本不标为“今天正常”，也不因为缺本期记录就宣称“已停用”。

### 2.3 分批原则

优先复用现有 Python 投影、HTML 模板、JS 渲染与 CSS。允许最小局部 helper 和向后兼容的展示字段；不建通用兼容框架、新数据库表或全新的前端状态系统。

单项受阻时明确影响，可独立验证的其他增量继续交付。不能从失败工作树盲目挑文件上线，也不能要求所有历史报告补齐后才发布局部 UI 修复。

## 5. C01—C04：名单比较正确性

### 5.1 比较什么，先说清楚

默认比较：当前报告对应的已发布工作台，与上一份能够核验的对应已发布工作台。这里的“上一份”不是按自然日简单减一天，更不能借未来报告。

需要分别处理三个层次：

1. **成员比较：**同一可识别证券是否出现在清单中。
2. **策略/条件比较：**对应来源、策略身份与字段语义是否允许前后对比。
3. **价格比较：**价格用途及价格依据是否允许计算变化。

成员存在不等于价格可比；某个字段不可比也不等于该证券所有字段都不可读。不能为了价格缺失把有效成员比较一起关闭，也不能因为成员代码相同就开放策略或价格比较。

### 5.2 修正上份快照来源

主要入口：

- `chanlun/report_generator.py::_load_previous_full_projection`
- `chanlun/report_generator.py::_build_report_bootstrap`
- `chanlun/decision_workbench.py::_changes`
- `chanlun/report_comparison.py` 中现有严格归档/快照绑定能力（先检查可复用部分）。

当前入口会读取上一期 JSON，再用旧 `workspace` 重建 `workbench`。这会漏掉已发布工作台中的部分衍生观察收录，不能继续把它冒称为用户上次看到的完整清单。[E3]

最小修复要求：

1. 优先读取与上份报告**可证明绑定**的已发布 `workbench` 或已有等价完整快照。核对报告日期、阶段、快照/内容绑定、来源身份和已有完整性保护。
2. 复用现有严格读取与验证；不要单凭文件路径、日期或某个 SHA 字符串存在就认定一致。HTML 中提取 JSON 必须走安全解析，不能执行归档脚本。
3. 已发布成员清单是该次展示事实，不用今天的新规则重新跑旧策略来“还原”。不能用未经证明完整的日期×股票登记表替代完整工作台。
4. 查找最近可核验上份报告时若跳过了某份损坏/缺失报告，展示实际比较日期及“最近可核验报告”，不能宣称相邻交易日报告。
5. 若只有旧 JSON 视图，保留其可读信息，但标“与旧数据视图比较 / 无法核验上次完整展示”。没有完整性证据时，不断言全局新增/移出数量。可核验的局部字段仍可展示。
6. 若完全没有上份依据，显示“暂无可核验的上份报告”，当前清单仍正常工作；不把当前所有股票都标成新增。
7. 处理 HTML 被清理的生命周期：先检查上一轮快照保护是否已有完整所需数据，能复用就复用；不重新引入“HTML 一删，比较数据就消失”的依赖。缺失时只局部降级，不为补齐所有历史先建新存储系统。
8. 仅修改比较投影和必要的衍生展示信息，不修改原日报、旧策略记录或历史报价。

建议给展示层携带一个小型“比较依据”对象，复用现有字段优先。最少能说明：实际前后日期/阶段、来源类型、核验状态、是否完整、跳过/降级原因。**字段名称由现有合同确定；本文没有要求新增同名公共 API。**

### 5.3 核心反例

冻结 9/30 和 10/8 的同版本实际报告及已发布工作台：

- 原重建基准 27 只，已发布工作台 30 只。
- 翔丰华 `300890` 两期已发布工作台均收录，不能标为本期加入。
- 原审查中替换为真实已发布基准后出现 18/17，而原比较为 19/15。该数量差异仅用于定位问题，**禁止把 18/17 写死或补丁式替换计数**。
- 同样检查江特电机 `002176`、众生药业 `002317` 的旧期收录来源是否被完整保留；其本期分类必须由真实输入计算。

断言具体证券集合和来源依据，不只断言总数或“非空”。

### 5.4 不可比较对象必须完整保留

当前 JS 使用的两组为：

```text
changes.unavailable_codes / unavailable_reasons
changes.value_unavailable_codes / value_unavailable_reasons
```

修复 `report-v2.js` 中 `decisionChangeReason` 与变化分组读取：

- 合并两组证券，按现有证券身份规则去重。
- 为每个对象保留全部原因，分别标“策略/条件不可比”“价格不可比”。对象出现在两组时只计一只，但显示两类原因。
- 已经属于 `changed` 的对象仍要保留其其他字段不可比提示，不能从不可比清单过滤后就丢失证据。
- 两个原因映射都读取，未知枚举使用安全的通用提示，原值可放技术详情；不要一律说价基缺失。
- 旧载荷两组为 23 和 3、互不重叠时，并集为 26；另补一个有重叠的组合反例。**该消费者测试与 C01 的重新计算测试分开。**
- 前后联合范围、当前集合、当前可比较子集是不同分母，不能用“当前 42 - 不可比 23”反推已比较数量。
- 各分组可重叠，例如条件有变化同时价格不可比；界面不把全部分组数量简单相加称“共多少只”。

实现建议：在本模块内归一化成“证券 → 分类集合 + 原因集合 + 对应原始引用”的只读视图，供摘要、计数、列表、详情共用。不要分别计算四遍而造成口径漂移。

### 5.5 未比较不显示假零值

| 场景 | 成员摘要 | 其他字段 |
|---|---|---|
| 两份清单完整可核验，确实无成员变化 | 加入 0、移出 0 | 已比较无变化与未比较字段仍分别说明 |
| 成员可比，部分策略/价格不可比 | 显示已确定的加入/移出 | “部分字段未比较”，保留具体证券和原因 |
| 上份清单不完整或无法核验成员关系 | 加入 —、移出 —，附原因 | 保留可读记录及能够证明的局部对照 |
| 没有上份报告 | 尚无上份比较依据 | 当前记录照常展示 |
| payload 缺字段 / 状态未知 | 比较状态未记录 | 不因空数组或 JS 默认值判定为真零 |

`available/partial/unavailable` 的总状态不应被简单用来开启/关闭所有子项。优先读取现有分项证据；确有必要时增补小范围分项可用性信息，不改旧状态的含义，不弱化原保护。

### 5.6 名称、来源、阶段与身份

修改 `decisionChangeName` / `decisionChangeSource` 及其直接消费者：

- 当前存在的对象从当前已绑定规范对象读取名称、`strategy_results`、`source_refs` 等真实来源。
- 移出的对象从同一已核验上份快照读取名称与来源，不向当前列表盲查，也不跨日期查询其他快照来补齐。
- 名称确实缺失时显示代码和“名称未记录”，不要把代码同时当名称重复展示。
- 多来源分别保留；可把重复存储层折叠为“原始记录”，但只有证明是同一记录的副本才去重。不能把不同策略或版本误合并。
- `observation_top5` 等展示来源可以标“观察 Top5 收录”，不能自动解释为独立策略命中。
- `phase=formal` 是报告阶段，映射为“收盘报告”，不是“正式推荐”。交易/研究身份必须读取其本身字段。
- 固定 10/8 的 42 个 `watch_only` 对象不能因为在正式收盘报告中就被标成正式推荐。

```text

```

“已记录”“成熟”“待到期”“缺行情”“事故排除”按实际字段展示，不由不明集合相减推导。尤其不能用包含待到期样本的总体活跃日/月代替某周期成熟样本覆盖日/月。

- 数量够、日期/月不足：直接指出尚缺的维度。
- 没有信号：无样本，不写等待到期。
- 已有样本未到期：跟踪中，不写数据错误。
- 因缺价/事故排除：显示具体限制，不保证等几天就恢复。

### 7.4 结果展示与状态修正

- 补 `partial` 状态映射，例如固定样本中显示“部分可用 · 20 只已核验研究候选”，而不是“未记录”或“完全成功”。数量缺失时只显示部分可用，不猜 20。

- 无组过门时提示：“基准数据已取得；策略收益比较尚未达到样本要求。”
- 只在某完整身份、某周期的既有收益展示条件满足时，展示该周期收益和分母。其他周期照常保留等待/缺失状态。
- 至少补一个达标正例，确保本次“改成进度”不会永久隐藏未来合法收益结果。
- 研究组保持研究标签，展示收益不等于获准转正式；“上涨比例”不能随意改成“交易胜率”，收盘价路径不自动称为可实现交易收益。

主要入口：`report-v2.js` 的记分牌状态、基准提示及卡片渲染；`chanlun/strategy_review.py` 的必要展示摘要。只修展示状态，不改回合计算及评估门。[E6]

### 10.4 条件变化必须指出具体字段


字段名由本地真实合同决定，`change_details` 等名称仅是设计建议，不要求引入新的公共 schema。需要新增时只增补本模块必要字段并检查直接消费者。

具体要求：

- 只描述已保存事实，例如“观察说明更新”“待确认条件更新”；不新增买点判断，不推断“买入时机成熟”。
