# ChanlunStrategy 热点统一、选股表现回看与可读性优化实施方案

> **本地 Agent 实施任务书 · v2.0 · 2026-10-10**
> 产品目标：保留已经好用的选股池，让其他区域直接回答“今天热点是什么、哪些股票有值得注意的变化、过去选出的股票表现怎样”。
> 本轮不是继续改标题、折叠空卡：必须补齐 **T+1 / T+3 / T+5 / T+10 / T+20 / T+30** 的历史选股表现、各周期最好与最差股票、按题材及策略查看的统计能力。

## 0. 给执行 Agent 的摘要

### 0.1 用户要看到的最终结果

| 用户问题 | 必须交付的答案 | 不合格的替代品 |
|---|---|---|
| 为什么上面是 AI 应用，下面却是电池？ | 上方摘要、热点地图和默认题材筛选共用同份开盘啦题材与来源顺序 | 只改标题，仍从两套数据各算第一名 |
| 名单加入、移出到底有什么用？ | 展示本期新出现的股票、已核验的条件更新；上期未再出现的股票次要展示 | 一大串“加入当前集合／移出当前集合／身份合同” |
| 以前选得好不好？哪个题材表现好？ | 选择周期后，直接看到平均表现、最好／最差股票、入选日期、样本数量，并能按题材和策略查看 | 只有“成熟多少／覆盖多少／还差多少天”的准备进度 |

**完成标准：用户不用阅读项目文档、不用听 Agent 解释，就能找到某个周期表现最好／最差的股票及具体收益，并理解统计的是哪批股票。**

## 3. H：开盘啦成为主热点，统一整条展示链

### 3.1 共用一个只读热点模型

上方开盘啦摘要、主热点地图、题材快捷按钮、题材搜索及热点详情，都消费同一个按报告绑定的模型，不能分别读取两套数据独立排名。

建议复用现有热点模型并增加必要字段，不强制采用以下名字：

```text
报告日期 / 数据日期 / 获取时间
来源：kaipanla 或明确备用来源
状态：同日可用、部分可用、上一期、暂不可用
排序依据：来源展示顺序 / 来源明确排名 / 用户主动选择的辅助排序
题材：来源题材ID、原名称、source_order、来源引用、股票样本
股票：证券身份、名称、开盘啦原因、可用行情、与系统选股池的关联
```

**排名规则：** 当前接口未提供可核验的热度分数时，按来源返回顺序展示，写“开盘啦题材 · 来源顺序”，不得声称这是全市场量化热度分。若以后有真实排名字段，核验后使用该字段。不要凭涨停样本数量重新排默认第一名。

同份有效数据下，上方第一项和地图第一项必须一致。先补充更新开盘啦数据时，要使所有消费者使用同一更新版本，避免顶栏更新了而地图仍用旧模型。

### 3.2 市场热点与系统选股分开

题材来自开盘啦，不是从本系统候选池倒推。默认不得启用“只看本系统选中”。

AI 应用在开盘啦存在，即使系统命中 0 只，也继续展示该题材和取得的股票样本。写：

> 开盘啦收录 N 只 · 本期系统选中 M 只

N 是有效返回的去重股票样本，不是板块总成分，也不是未经验证的涨停家数。系统清单完整性不足时，写“已知选中 M 只／关联待核验”，不能把未知显示为确定 0。

在热点中点击股票：有当前候选就复用已修好的详情入口；不是候选则打开市场背景详情，不把它加入正式／研究选股池。点击“查看本系统相关股票”才改变选股池的阅读筛选，清除后恢复原集合和顺序。

### 3.3 不因缺字段抹掉题材

- 缺涨跌幅、连板数、新闻或选股池交集，不删除已有合法题材／股票。
- 题材元信息合法而有效股票列表为空时，保留紧凑题材状态，注明“股票明细暂缺”或确证的空列表，不冒称该题材不存在。
- 当前 `parse_themes` 只在有解析股票时加入分组。需要修此消费者问题时允许最小扩展解析输出，保留有效题材元信息与原来源位置；不把非法证券身份带入价格或选股关联。
- 重复股票在同一题材内去重；同股属于不同题材可分别展示。页面总股票数按证券去重，不累加各题材样本数。
- 原因直接显示“开盘啦题材说明／个股原因”；不要把接口原因扩写成已证实的事件因果。

### 3.4 行情补充与备用来源

其他现有行情仅作为补充：通过证券身份和同日报告时间核验后补涨跌幅、连板等字段。不能借另一来源的分组覆盖开盘啦题材归属；无法补价时保留名称、原因和缺价状态。

| 情况 | 应用行为 |
|---|---|
| 同日开盘啦可用 | 默认统一使用开盘啦；保留其顺序 |
| 同日只有部分有效题材 | 展示已取得部分，标“部分样本”；不混入另一套题材伪装完整 |
| 只有上一期数据 | 明示实际日期和“上一期参考”；不称今日热点 |
| 同日开盘啦不可用，原涨停统计可用 | 明示“备用：涨停分布”；不称开盘啦，也不与旧开盘啦合成同一排行榜 |
| 两者不可用 | 热点区局部提示；选股池照常工作 |
| 用户主动换成涨停数／连板排序 | 明示当前排序依据，并提供“恢复开盘啦顺序” |

旧资金流／行业条保留时，准确命名为“行业资金流”或“涨停分布”；不要再提供另一套没有来源说明的“主热点 Top1”。本轮改的是展示主来源，**不改变选股算法中的行业数据或策略评分输入**。

### 3.5 重点代码入口

`chanlun/kaipanla.py::parse_themes`；`report-v2.js` 中 `buildMarketHotspotModel`、`sortMarketHotspotGroups`、`filterMarketHotspotItems`、热点详情与上方开盘啦补充渲染。`buildFundingMainlineModel` 是相邻消费者，明确其用途是否仍为独立资金视图。函数行号按当前本地源码核对。[S2–S3]

## 4. C：名单变化改成“本期值得重看的变化”

### 4.1 比较对象必须可理解

模块头写明：

> 对比 YYYY-MM-DD 与 YYYY-MM-DD 两份报告中的「所选清单」。

“所选清单”必须具体，例如“全部已发布候选”“正式推荐”或“罗姐研究池”。默认沿用当前已核验的发布工作台范围，不静默把不同池混成一个比较。

同一明确范围、同一对日期中，一只股票的“新增”和“未再出现”互斥。不同来源发生进入／退出但总清单仍有该股，应显示“来源记录更新”，不能同时断言该股从总清单加入又移出。

### 4.2 展示顺序和标题

| 分类 | 用户文案 | 默认层级 |
|---|---|---|
| 已核验语义字段变化 | 条件有更新，建议重看 | 优先 |
| 上期无、本期有，成员依据完整 | 本期新出现 | 次优先 |
| 上期有、本期无，成员依据完整 | 上期有、本期未出现 | 默认折叠 |
| 只有不可比记录或旧视图 | 部分历史无法对照 | 一行限制，详情可展开 |

整个模块默认最多 5 只，先条件更新、再新出现。没有这两类时用一句“本期没有已核验的新出现或条件更新”，但只有真的完成相关比较才这样写；未知时写“本期可核验变化不足”。纯技术缺口不要顶替成五条“重点”。

数字来自完整集合。用户展开后再显示全部和分组数量，不把数量卡片作为默认中心。

### 4.3 每行必须有内容，不能只有标签

```text
股票名称 代码    本期新出现    研究观察
本期理由：读取已有的简短选股理由。
接下来核对：读取已登记的待确认条件，最多 2 条。
[查看个股]
```

```text
股票名称 代码    待确认条件更新
上期：已有原文。
本期：已有原文。
[查看个股] [展开本次变化]
```

同一行最多两个主要操作。原文较长先给短摘要，完整原文可展开；摘要只能从已经比较的字段生成，不让模型推断买卖信号或重算条件。上期没记录的字段写“本期补充了该字段”，不冒称策略刚发生变化。

“上期有、本期未出现”有明确的本期排除记录才显示原因。没有原因就写“本期清单未收录，未记录具体原因”；不自动等同于破位、卖出或已失效。

### 4.4 已有正确性和交互不得退化

继续使用完整发布快照绑定、成员与条件／价格分项核验、不可比原因并集、未知不等于零。清理 HTML 后有可核验的轻量登记就保留可用概览，不把它冒充完整历史条件。

当前入口必须处理空主推、目标在前 20 条之外、阅读筛选挡住目标等场景。历史入口就近展开，不改变当前候选筛选，不把历史对象塞进当前池。关闭返回原位置；迟到请求不得覆盖新股票或新报告。

历史详情默认只显示“上期理由／本期理由／真正变化／必要限制”。`workbench/workspace/raw` 的原始保存层、版本、哈希和重复技术记录放在“原始记录与依据”，不同来源仍分别保存，不为简洁强行合并。

## 5. P：选股表现页的目标与默认产品口径

### 5.1 这是历史选股表现，不冒充完整交易回测

本轮默认统计**当时实际发布的清单，在报告后不同交易日的价格表现**。不使用今天规则重新筛旧行情，不倒推当时不存在的推荐，也不计算虚构的账户净值。

页面标题用“选股表现”。说明用：

> 统计当时发布的股票，之后 N 个交易日的价格变化；不是实盘成交收益。

默认采用下文明确的“报告日收盘 → 第 N 个后续交易日收盘”观察口径。既有正式策略回测、延迟开盘入场和研究准入继续保留在独立评测身份内，不能被本次观察口径覆盖。

### 5.2 一次给定的默认选择

| 项目 | 本轮默认值 |
|---|---|
| 统计范围 | 全部已发布候选（含研究观察，按报告日＋证券去重）；不是全市场，也不是全部都属于正式推荐 |
| 日期筛选 | 入选报告日范围，默认截至所选报告日的最近 60 个交易日；实际历史不足则明示实际范围 |
| 结果截止 | 当前打开的报告所绑定的行情截点，不能用浏览器今天日期偷偷更新历史页面 |
| 默认周期 | T+1；六周期切换始终可见 |
| 默认视角 | 按题材，另有按策略、逐股明细 |
| 题材榜排序 | 所选周期平均价格收益降序；中位数、上涨比例和样本数同时展示 |
| 默认计数单位 | 观察笔数与独立股票数分开；同日同股多池只算一笔，不同日期仍是不同观察 |
| 数据有限时 | 展示已有可靠结果，清楚标小样本／低覆盖；不隐藏所有结果 |

“全部已发布候选”必须显式带“含研究”说明。用户切到“正式推荐”时只取当时真正正式的股票；正式池空就是空，不借研究股票填充。按策略时每一完整身份分别统计。

60 个交易日是显示默认范围，不是删除历史的保留期限，也不是强制后台补 60 天。支持用户在已经保存的范围内改日期。

### 5.3 页面布局

```text
选股表现
范围：全部已发布候选（含研究）  入选日期：起止日期
口径：报告日收盘 → T+N 收盘   行情截至：日期／收盘

[T+1] [T+3] [T+5] [T+10] [T+20] [T+30]

平均价格收益  中位数  上涨比例
最好的一笔：股票名／代码／收益／入选日期 [看明细]
最差的一笔：股票名／代码／收益／入选日期 [看明细]
已有结果 N 笔（S 只）· 待到期 W 笔 · 缺数据 M 笔

[按题材] [按策略] [逐股明细]
题材/策略 | 平均收益 | 中位数 | 上涨比例 | 最好股票 | 最差股票 | 已有结果/应有结果
```

用户切题材或策略后，顶部平均值、极值卡、数量和明细必须使用同一个筛选结果。最好／最差必须展示入选日期，不能只给股票名：同股可能在不同日期多次被选中。

六个周期可以另有紧凑概览表：周期、平均收益、最好、最差、结果笔数。没有结果的周期保留原因，不把整页做成六份重复长表。

## 6. P1：样本是什么，哪些历史可以使用

### 6.1 观察样本与旧回测账本分离

新“发布清单价格观察”的一笔样本：

```text
所选有效报告发布版本 + 报告日 + 证券身份
```

同份报告的同股出现在多个来源池：全局观察只算一笔，保存多来源关系。连续两天出现在报告：默认两笔观察，界面写“同股跨日重复入选分别记录，不代表两笔独立实盘交易”。同时显示独立股票数及覆盖报告日数，不能把相关重复样本当作独立统计证明。

旧记分牌已有“连续入选回合”去重与策略身份；**不改其计数语义**。新观察按报告日统计，与旧回合统计并列区分，不能用同一个旧字段偷偷改单位。

同日报告多次修订不重复计样本。优先复用已有有效发布版本选择规则，固定一个规范版本并保留引用；已归档的旧版本不能被新规则重跑替换。确有两个无法裁定的发布版本，隔离为版本待核验，不猜哪个是正式。

### 6.2 样本来源优先级

1. 已绑定的实际发布工作台／具有足够成员和来源事实的持久登记。
2. 能证明与该次发布相符的原报告记录。
3. 只有原始候选池而无法证明曾发布：保留为单独“原始候选资料”，不能混称已发布样本；本期主榜可以先不纳入。

轻量登记能证明“何日发布了哪只证券”，就可以支持本次独立价格观察，不要求它补齐所有旧策略合同、理由和参考线。缺原始条件不妨碍已核验的成员价格观察；缺成员身份／报告日期则不能算成一笔已核验结果。

事故排除、身份冲突、未曾发布的实验原始样本不混入主榜。展示可识别的排除数量和原因；不能因为后来亏损、退市或缺价格而悄悄从母集合删除。

### 6.3 不退回“今天还在池中的股票”

表现页必须从当时已发布记录形成样本，不只跟踪今天仍在池里的股票。即使某股后来从清单消失，它在先前日期的观察仍继续计算至 T+30。删除历史 HTML 不应删除已经保存的样本身份和引用。

当前 UI 的前 5／前 20／Top5／分页只是展示限制，不得截断回看母集合。历史存在只有部分成员的情况，写“已保存的部分清单”，不把剩余股票解释为当时没选。

## 7. P2：六周期价格计算合同

### 7.1 默认公式与交易日定位

设报告日为 D，所用交易所日历中 D 的索引为 i。D+N 指日历中的第 i+N 个交易日，不是自然日，也不是该股下一根可用 K 线。

```text
N ∈ {1, 3, 5, 10, 20, 30}
P0 = 报告日 D 的已确认收盘价
PN = D+N 的已确认收盘价
R_N = (PN / P0 - 1) × 100%
```

起止价格必须来自同一可核验证券、同一复权口径及相容价基；复用已有本地正规行情读取。两点都可以从同一条已核验的历史价格序列取得，**不要求它们必须与当年页面上未核验的原始参考线数值相等**。这是独立“收盘到收盘价格观察”，不是把旧策略参考价突然认定为有效入场价。

若复用现有 `immediate_close` 能得到同语义且有效的结果，可以直接复用；不能复用时用最小的观察结果 helper，不禁用旧参考价验证，也不污染正式回测。只比较数值相等、同为 `qfq` 字符串却无法确认序列身份与价基，不足以跨记录拼接。

报告日收盘以后发布的清单，用报告日收盘价起算是**观察基准**，不表示用户在收到报告后还可以买到该价。页面使用“价格收益／价格变化”，不称“实盘赚了多少”。

### 7.2 各种情况必须分别处理

| 情况 | 结果 |
|---|---|
| 起止价有效、已到目标交易日且目标日收盘已确认 | 计算 R_N；真实 0 正常显示 0.00% |
| 目标交易日尚未到，或尚未完成该日收盘 | 待到期，不算 0，不进入该周期平均值 |
| 目标日期已到，但行情缺失或无有效成交收盘依据 | 缺行情，不用后一根 K 线顶替，也不向前填充 |
| 起止价不合法或价基不能核验 | 价格不可核验，仅该样本／周期不计算 |
| 交易日历无法定位 | 日期未核验，不凭工作日或个股 K 线根数推算 |
| 缺板块／题材标签 | 个股结果照常显示，进入题材未记录组 |
| 缺沪深300等基准 | 绝对价格结果照常显示；只留空超额结果 |
| 中间路径缺某日，但起止价可靠 | 到期价格结果可算；期间最高／最低等路径指标单独降级 |

退市、停牌等没有可用目标收盘的记录保留在应跟踪样本中并注明原因，不从分母静默抹去。没有现成、已核验的现金兑付等口径时不编造替代终值。

结果以 `evaluation_as_of` 截断。打开历史报告不能无提示地用以后数据算出那时尚未知的结果。另行选择较新的结果截止日期时，必须可见地改变该字段；不能让历史页的原报告事实改变。

### 7.3 既有入场方式不能混算

保留原 `delay1_open` 与其他合法回测结果，按既有身份单独展示。切到该口径时标题写清“次日开盘起算”等说明，不能与默认报告日收盘观察放入一个平均值／排行榜。

T+1 在任何页面都指报告后第一个交易日目标收盘；“持有一整天／可执行买卖收益”不是同一概念。本轮不新增执行模拟、交易费用模型、账户复利、杠杆、年化收益或自动交易。

### 7.4 必须真正贯通六个周期

不要只把一个 `HORIZONS` 常量改长。沿实际调用链核查：

- 交易日历与行情窗口加载；覆盖到所需目标日期，不把旧 5 日取数边界保留在内部。
- 空结果映射、目标日期、结果状态、成熟／待到期分类。
- 返回字典、序列化、缓存键、聚合、极值、基准对齐、前端按钮和逐股明细。
- “是否全部完成”的终止条件不能继续只检查 `t5`；新观察以六周期真实状态决定待更新项。
- 历史样本读取不能被“最近 26 份报告”或“HTML 仅保留 5 份”截断。优先复用保存的样本登记和报告事实，而不是延长 HTML 保留去冒充解决。

建议新观察链用独立的六周期配置；旧正式评测仍可保留原三周期合同。不必为了新页面同时扩展每一种旧实验的内部周期。新配置必须成为本轮观察链生产者与消费者的单一周期来源，确保 T+10/20/30 真正可计算。

## 8. P3：平均、最高、最低及分母的精确定义

### 8.1 同一筛选结果，只生成一个聚合结果

先按报告日范围、样本类型、策略身份／题材与入场方式筛选，然后取所选周期的有效结果。顶部卡片、榜单、极值详情和导出如有实现，均消费同一个结果集合。

每个周期至少输出：

```text
total_observations       已登记并落在本次筛选范围的观察笔数
ready_observations       有有效价格结果的笔数
waiting_observations     未到目标日／目标收盘的笔数
missing_observations     已到期但缺价格或价基的笔数
calendar_unknown         无法定位目标日期的笔数
excluded_observations    有明确排除依据的笔数
unique_stocks            当前统计明确对应的独立股票数
report_dates             结果覆盖的入选报告日数
```

上面状态计数必须互斥，保证总数能核对。实现中可进一步拆分缺行情和价基不可核验，但不能重复计入主分区。公开摘要同时说明“结果 N 笔／应有结果 E 笔；另有 W 笔未到期”，其中 E 为可定位且已经到期、未明确排除的样本数，不能把未到期混入行情覆盖率。

无效身份导致连样本都无法建立的报告缺口另外记录，不猜证券数量；显示可核验报告范围和缺失报告数。

### 8.2 计算定义

令有效 R_N 集合为 V，n = |V|：

- 平均价格收益：V 的算术平均。
- 中位数：V 的中位数。
- 上涨比例：`count(R_N > 0) / n`；0 不属于上涨，不称交易胜率。
- 最好的一笔：`max(V)` 对应的观察记录。
- 最差的一笔：`min(V)` 对应的观察记录。
- 最好／最差同时带证券身份、名称、入选日、目标日、起止价和结果引用。
- n=0 时全部结果为 `null`，主界面显示“暂无已到期可核验结果”；不能显示 0%、0只赢家等假结论。
- n=1 时平均、中位数、最好、最差是同一笔，明确“仅 1 笔”；不为让卡片不同而拿其他周期凑数。
- 全部亏损时最好也可能是负值；写“最好的一笔 -1.00%”，不能显示成“最高涨幅 +1.00%”。

收益率和上涨比例的公开数值统一使用百分数单位（例如 10 表示 10%，不是 0.10）；字段名或 schema 明确单位。先用完整精度计算与排序，最后格式化百分比。同收益并列保留完整记录，默认显示一笔并写“并列 N 笔”；稳定选择按入选日、证券身份和样本ID排序。浮点等值规则在 helper 中固定并测试，不能把显示到两位小数相同就当然视为真实并列。

### 8.3 不得用错“最高／最低”

用户核心要求是**所选周期目标日的收益，哪只票最好／最差**，不是持有期间的盘中峰谷。

例如：某股报告日收盘 100，T+5 收盘 120，中间最高到过 160。T+5 结果为 **+20%**；“期间最高曾到 +60%”可在详情另列，但不能当成 T+5 收益。

不得复用旧 `period_high / period_low` 当最高／最低股票，也不得把旧“代表样本”直接当每个周期的真实极值。必须从该周期完整有效样本集合重新求极值。[S4]

### 8.4 有真实结果就展示，不等于承诺策略有效

**本轮允许展示未达到原 100/20/2 比较门的已核验样本结果。** 新增的是描述性价格观察，不修改旧 `metrics_publishable`、事故排除或正式策略晋级。

- 小样本也显示平均值、极值和明细，旁边明确 n、独立股票数及覆盖日期。
- 保留旧严格评测的就绪状态作为“能否据此评价策略”的详情，不把它作为查看客观结果的全局开关。
- 不依赖旧已被置空的收益网格；需要时从可核验的逐样本结果重新聚合。
- 不新增另一套“不到 N 笔一律隐藏”的硬门槛。可以做样本少提示，不能再次把页面变成积累进度页。
- 题材榜默认只是“所选样本中按平均价格收益排序”。样本少或行情覆盖不全时不得写“最强题材／策略已证明有效”。不同样本数量与日期分布要可见。
- 不把多次相关观察连乘成账户净值，不将样本平均收益年化。

## 9. P4：按题材、按策略，以及当时评分

### 9.1 按题材看的是“本系统当时选出的票”

主榜不是开盘啦全市场股票回测，也不是板块指数涨跌。标题写：

> 本系统入选股票 · 按入选当时题材看表现

题材成员必须来自入选报告当时可追溯的记录。开盘啦作为题材分类优先来源，但**今天有的题材标签不能用于重新定义过去的名单**。

可用路径：当时报告内已保存的开盘啦题材引用，或当时存档的同日题材快照，能核验其归属和所选发布版本的可知时间。后来独立补更的题材数据只有明确属于所选发布版本及时间范围时才用；无法证明就不称为入选时已知。

缺当时题材的股票统一进入“题材未记录”，保留收益；不要拿当前行业名模糊映射成开盘啦题材。未来报告在既有成功流程中保留题材快照引用或小型侧文件即可，不能为此重建数据库。

### 9.2 题材关系与多标签

- 优先用来源题材ID建立关系，保留原名称和来源日期。只有名称无ID时限定在同来源、同命名口径内，不跨供应商字符串合并。
- AI 应用、人工智能、软件服务不是默认同义词；没有明确对应关系就分别展示。
- 同股当时属于多个题材：每个对应题材内可各计一笔，但全局总体只算一笔。界面提示“题材可重叠，组间样本数不可相加”。
- 题材内部同日同股去重；对某题材求极值时必须限定在该题材样本中。
- 题材全缺失也要能打开“逐股明细”和“按策略”，不能使全页无结果。题材映射覆盖单独说明。
- 已有样本但尚无到期结果的题材列在无结果区域；不参加数值名次，不用 0 把它排到亏损题材前。

默认题材行：题材名、平均收益、中位数、上涨比例、最好票、最差票、结果笔数／应有结果笔数。覆盖不足时突出“部分结果”，不伪装完整榜。

### 9.3 按策略不能跨版本凑数

使用当时记录的完整策略身份、来源池、正式／研究角色和入场口径分组。同一股票多策略命中，可以分别出现在各策略组；总体不重复。

旧策略完整身份保留，默认用易读策略名与必要的版本区别；全哈希进入详情，不靠哈希字典序猜最新版本。不把一组研究结果标成正式推荐成绩。

“按策略”与“按题材”是两个明确视角。它们的组间可以交叉，不相加为总体，也不将题材热度名次解释成策略有效性。

### 9.4 用户提到的“哪个板块评分比较高”

本轮先交付可解释的**按所选周期平均价格收益排序**，不新造一个 0—100 的板块综合评分。热点顺序看开盘啦；历史表现排名看所选样本的结果，二者在不同页面说明清楚，不要求同一个第一名。

逐股明细保留“当时选股分数／分数名称／所属策略”，只能从入选时已保存记录读取。多个策略分数不同就分别显示；不能取最大的一个当成统一总分。

同一策略版本和同一分数定义下，支持按当时分数排序查看各周期表现。跨策略、跨分数范围的混合样本不要直接比较分数高低。评分分桶／新综合评分不是本轮必需，不拖住收益与极值交付。

## 10. 数据投影、更新与最短实现路径

### 10.1 推荐的数据流

```text
已发布报告／持久成员登记（不改原事实）
  + 当时的题材与策略来源引用
  + 本地正规历史行情（只读）
  + 交易日历与固定行情截点
      ↓
发布清单观察记录（按报告日＋证券去重）
      ↓
六周期逐样本结果（各自状态、日期和价格依据）
      ↓
同一筛选定义下的总体／题材／策略聚合与极值
      ↓
派生 JSON ＋现有前端选股表现页
```

本轮优先复用 `report_comparison.py` 的样本与快照读取、`MarketHistoryStore` 的行情、`strategy_review.py` 的交易日定位和数值保护。若旧三周期合同与新观察语义不同，允许一个小型独立 `selection_performance` 模块，不能借机统一重写所有实验。

**策略可靠性评测和发布清单价格观察保留不同身份。** 新描述性结果不能反向写入正式推荐、模型分数或旧账本。

### 10.2 最小派生数据合同

字段名可按现有架构调整，但以下信息不能丢失：

```text
数据集：
  schema_version / dataset_id / generated_at
  report_as_of / evaluation_as_of
  horizons: [1, 3, 5, 10, 20, 30]
  measurement: published_close_to_close
  cohort_policy: report_date_instrument_dedup

  observation_id / instrument_id / code / name

  theme_refs（当时题材及来源；缺失保留状态）
  price_series_ref / adjustment / price_basis
  outcomes:
    t1 ... t30:
      status / target_date / start_date / start_close / end_close

一个分组：
  group_id / label / grouping_type / identity_scope
```

不要求新数据库表。允许在现有派生数据目录增加小型版本化 JSON／侧文件；这是可重建展示产物，不是改写正式历史账本。旧消费者字段含义保持不变，新增字段向后兼容。

### 10.3 读取范围、性能和页面状态

- 价格按证券批量读取，一份价格序列计算六个周期，不为每只股票每个周期再请求一次。
- 首次用本地已有材料生成；缺行情列缺口，不自动全市场联网补数。
- 默认范围从实际保存的报告事实建立，市场数据需覆盖这些报告日及截至 `evaluation_as_of` 已到期的目标日期；未来目标不用联网“补”。
- 后续正常收盘流程增加独立、受控的表现更新步骤，刷新已到期项目和必要聚合；不要阻塞 14:56 预跑或让表现统计失败导致主日报无法发布。
- 当前产物已经存在时，更新失败保留旧产物并标“结果截至旧日期／更新失败”；不能换成全零或改成新日期冒充已刷新。
- 优先输出聚合摘要，明细按需读取。可先用小型单文件；数据大再复用现有分片／按报告日文件，不以建设服务端分页平台为前置。
- 摘要、极值和明细绑定相同 `dataset_id`、截止日期、筛选条件。切周期／题材时旧请求迟到不得覆盖新选择。
- 派生文件原子写入，必要时最后切换小清单／manifest；缓存键包含输入版本、计算版本、口径和行情截点，不能只用股票代码。
- 对新增六周期不要继续使用旧历史清理阈值删除未完成观察。已缺失的历史只明确范围，不为本次交付复活所有旧 HTML。

### 10.4 统计预览命令的交付要求

Agent 应提供一个可重复的**本地只读输入、输出到隔离目录**的构建／检查命令，并在交付说明里写实际命令。输入至少能指定：报告目录、行情数据库、结果截止、输出目录；不得默认连接生产写接口、拉新行情或发送通知。

本文不假装仓库已经存在某个新脚本。先检查已有命令能否复用；需要新增时限定为派生表现生成，不执行选股重跑。生产接入和部署仅在当前任务有效授权范围内进行。

## 11. PSY12 与其余低价值默认内容

### 11.1 PSY12 的最终呈现

建议标题：**近期上涨持续性**。默认一句：

> 最近 12 个有效观察日中，有 N 天指数平均上涨（上涨日占比 X%）。

X 是 `N/12×100`，读取已有生产结果与窗口；不是个股评分，不是下一天上涨概率，不新增超买超卖或买卖判断。项目当前使用多个有效指数涨跌的平均方向；文案不要偷换成“全市场有 X% 股票上涨”。[S5]

基础数据不足时写“有效观察记录不足，暂不统计”，其他市场信息继续显示。真实 0 可以显示，缺失不能填 0。

基础说明只放一次，别在两个页签重复占大卡。PSY12 影子综合分、正式分差值、权重、20日审计进入“实验与运行详情”。缺成交额时说明具体组件缺失，不能把有效的基础上涨日统计抹掉。

### 11.2 其他模块

- H4 实验、旧严格记分牌与门控运行保留，但默认不挡在选股成绩前面。
- 门控只回答运行与分流，不混入收益排行榜。
- 旧技术诊断正常折叠；影响本期正式选股的已知错误在原状态位提醒，局部表现缺口在表现页提醒。
- 无样本实验用一行真实状态，不补造收益、不放宽策略。不把“关闭整个实验／删除账本”作为消除空卡的方式。
- 技术错误、密钥、数据库路径不能泄露到公开 JSON 或用户页面；需要核验的原始信息保留在受控本地诊断。

## 13. 固定输入：六周期计算与极值对照

以下全部为**合成测试样本，不是真实股票收益，不得进入生产报告**。用虚拟证券甲、乙、丙，各有完整同价基行情。报告日收盘都为 100；交易日日历为 D0、D1……D30，实际测试须用日期并覆盖周末／休市跳转。

| 甲 | 100 | 110 | 105 | 120 | 130 | 110 | 140 |
| 乙 | 100 | 95 | 110 | 90 | 80 | 105 | 90 |
| 丙 | 100 | 100 | 100 | 110 | 90 | 95 | 100 |

在 D30 收盘后、三个样本都有效时：

| 周期 | 甲 | 乙 | 丙 | 平均收益 | 最好 | 最差 |
|---|---:|---:|---:|---:|---|---|
| T+1 | +10% | -5% | 0% | +1.6667% | 甲 +10% | 乙 -5% |
| T+3 | +5% | +10% | 0% | +5.0000% | 乙 +10% | 丙 0% |
| T+5 | +20% | -10% | +10% | +6.6667% | 甲 +20% | 乙 -10% |
| T+10 | +30% | -20% | -10% | 0.0000% | 甲 +30% | 乙 -20% |
| T+20 | +10% | +5% | -5% | +3.3333% | 甲 +10% | 丙 -5% |
| T+30 | +40% | -10% | 0% | +10.0000% | 甲 +40% | 乙 -10% |

必须补充以下变体：

- 删掉丙 D20 收盘且结果截点仍为 D30：T+20 两笔有效，平均 +7.5%；应有三笔、缺行情一笔；不能用 D21 替代。
