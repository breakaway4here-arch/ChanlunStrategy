# 统一决策清单、图表工作台与推送 Spec

版本：1.0 · 日期：2026-09-07 · 状态：可交付实施

**Goal：** 用户打开推送或日报后，10 秒内知道今天先看什么、为什么看、还等什么、什么情况下失效。

**Architecture：** 保留现有选股、正式动作和预跑隔离合同，在报告展示层增加确定性的统一决策投影，网页与通知复用语义。整合本地已有图表中心改版，修复理由混用产生的伪冲突；不重算策略、不改变正式股票池。

**Tech Stack：** 现有 Python 报告/预跑流水线、静态 HTML、原生 JS/CSS、ECharts、unittest、Node 合同测试及现有发布工具。

**执行者：** GPT-5.3-Codex-Spark。按本文和同目录 `2026-09-07-unified-decision-workbench-spark-handoff.md` 实施；无需重做需求访谈。最新用户指令高于旧文档的授权状态。

## 1. 背景与事实边界

本 spec 面向日常阅读微信推送和日报的项目所有者。2026-09-07 已实际打开线上页面，并读取公开 HTML、数据、资源及本地源代码。以下是当日快照，不能硬编码进产品：

| 已验证事实 | 产品问题 |
| --- | --- |
| 基础候选 11 → 融合候选 2 → 正式主推 0；9 只被均线准入条件过滤，剩余 2 只为 observe | 首页只报空池，缺少可追溯的原因 |
| 待确认 17 只全部是 limit_up / avoid_chase 的启动观察；观察 Top5 实际 2 只与前者重复 | 池名掩盖真实阶段，重复占用注意力 |
| 中远通、斯菱智驱的结构原因与观察原因不同，被 summary 一致性校验判为冲突 | 不同语义字段被误当作同一事实 |
| 列表“正式动作：仅观察”，详情“本期未声明正式动作” | 研究身份与正式动作表达不一致 |
| 盘后无变化文案主要为三个池的计数；发送记录含 pending 与正式结果两次通知 | 推送没有重点，还暴露中间处理状态 |
| 本地已有 f649af6 图表改版；当日线上资源版本 569fe0cbba0f 与本地实现不同 | 已开发不等于已上线，需要整合发布链 |

注意：数据内 decision_engine_v1 的 recommend/observe 不等于用户当前看见的页面动作。各 views 行数相加不等于首屏同时展示数。本次不据此宣称研究列表实际出现买入建议，也不据单日样本判断策略收益好坏。

当日正式市场情绪“66 / 偏强”和融合准入使用的指数 EMA50 条件是不同指标。应分别解释它们的作用，不强行把二者改成同一个市场状态。

## 2. 目标、用户故事与成功指标

| ID | 用户需要 | 验收指标 |
| --- | --- | --- |
| US-1 | 主推为空时也知道原因和后续阅读方向 | 第一屏有结论、原因；正常空选与无法判断不混用 |
| US-2 | 同一只股票不用在多个池反复阅读 | 今日清单内每个规范化代码只有一行，来源仍可追溯 |
| US-3 | 分清正式推荐、等待条件和证据不足 | 列表、详情、推送身份与动作语义一致 |
| US-4 | 点股票先看图，再沿证据理解判断 | 桌面首屏含标题、状态及日 K 主图区；手机详情标题后即全宽图 |
| US-5 | 推送告诉我变化和重点 | 正常 pending 不发送；同语义重试不重复发送 |
| US-6 | 能找到全部候选和策略依据 | 默认突出至多 5 只，不截断底层正式池；全部清单和来源可展开 |

10 秒阅读测试是人工验收目标：至少使用正常正式候选、主推为空、观察条件不足、证据异常四类真实/固定样本；验收记录写出上述问题的答案，不能声称自动测试已证明用户理解。

## 3. 范围与优先级

### 本轮必须完成

1. 整合 f649af6 中已有的简洁候选理由、图表中心布局、四项解释及其防退化测试。
2. 增加按股票归并的展示投影；合并今日页重复入口，保留原始池、各策略独立身份、顺序与分数。
3. 拆开结构原因、观察原因、确认条件和取消条件，修复伪冲突。

### 本轮不做

- 不把观察提升为正式推荐，不平均多个策略分数，不造参考价、失效位或确认价。
- 不合并预跑与盘后数据库、锁、账本、快照、有效期；不延长预跑交易窗口。
- 不新增行情供应商、30 分钟图表请求、两股对比、全新前端框架或数据库迁移。
- 不引入 LLM 生成正式动作或摘要优先级；已有方向研究保留原边界。
- 不处理三个延期 Iwencai/辅助研究脚本，不写历史交易/推荐账本，不回补全量历史日报。

后续独立任务：用近期真实历史样本核验漏选、信号延迟、可成交性、失效和风险，再决定是否调整算法。本轮不承诺收益改善。

## 4. 唯一数据与身份规则

### FR-01：展示投影

新增纯函数模块 `chanlun/decision_workbench.py`，建议入口：

`build_decision_workbench(report, workspace, evidence, *, phase, snapshot_id, previous=None)`

函数无网络、无文件写入、无行情重算、不修改参数；输出 JSON 可序列化、顺序稳定的 `decision-workbench-v1`。可按项目现有命名调整入口，但字段语义与测试不变。

输出至少包含：

| 字段 | 内容 |
| --- | --- |
| schema_version / report_date / phase / snapshot_id / as_of | 版本、交易日、preclose 或 formal、唯一快照、事实时间 |
| health | verified / partial / unavailable / stale 及可读原因、证据引用 |
| summary | 今日结论、正式主推/H4 分别的状态、可验证空选原因、市场摘要 |
| items | 去重股票主体及完整来源；不裁剪成 Top5 |
| featured_ids | 默认至多 5 个主体 ID，允许为空 |
| changes | 同口径相邻快照的变化或明确 comparison_unavailable |

主体键为 `report_date + phase + snapshot_id + normalized_code`，不同日期/阶段/快照不合并。代码保留市场区分能力，不仅靠股票名称；延续现有代码规范化逻辑。

每个主体至少含 name/code、source_refs、strategy_results、page_status、primary_reason、structural_reason、watch_reason、next_confirmation、invalidation、evidence_status、blocking_reasons、chart_ref。

`strategy_results` 分别保存 strategy_id、role、action_semantics、原始 view_rank、各分数名、正式合同和证据引用。正式合同仍归属于特定策略及其周期；不能从其他池借来拼成一套可执行合同。

### FR-02：归并和冲突

- 同股票多次出现只合并展示主体，来源引用去重。底层 `picks_*`、watchlist、workspace 原 views 仍保留，用于历史兼容和研究追溯。
- 正式主推与 H4 均为正式策略；H4 不能因为原来放在“研究池”菜单就降级为研究结果。
- 多策略正式意见一致时，可合并展示动作文字，详情列出各自周期及价格合同；条件只能绑定各自策略。
- 多正式策略给出冲突意见时，显示“策略意见不一致”，并列各自判断；不自动选赢家、不给统一可执行结论。研究意见不会改写正式动作。
- 观察池的引擎 recommend 等作为研究层评分结果保留；今日列表与通知不能把它翻译成正式推荐。

### FR-03：互斥的页面状态与独立的正式动作

| page_status | 条件 | 一级显示 |
| --- | --- | --- |
| evidence_blocked | 所选事实陈旧、真正冲突、健康异常或关键来源缺失 | 暂无法判断，并显示具体阻塞原因 |
| invalidated | 已有同合同明确失效/取消证据，且无状态冲突 | 已失效/已取消，不推导卖出指令 |
| strategy_disagreement | 当前存在互相冲突的正式意见 | 策略意见不一致 |
| formal_ready | 有正式推荐且该策略要求的执行边界完整、事实有效 | 正式推荐 + 条件已完整；盘后仍标注适用时段 |
| formal_incomplete | 有正式推荐但必要执行条件未齐 | 正式推荐 + 执行条件待补充 |
| waiting_trigger | 观察事实可靠，且具体等待条件及适用的取消条件可核验 | 等回踩/等确认等实际阶段 |
| watch_only | 有可靠观察理由，但不足以形成具体跟踪条件 | 研究观察，说明还缺什么 |

按表的阻塞优先级判定，不能用缺数据覆盖成“正常空选”。保留 `formal_action` 原值与 `execution_status` 两个独立字段：缺价格不能抹掉真实正式动作，但必须阻止“可执行”宣称。

数据健康必须检查当前候选证据，不能用报告全局 missing_30min=0 推导每只股票的 30 分钟确认完整。观察策略明确不适用的指标不作为缺失；必须由其合同或来源声明，不能默认忽略。

### FR-04：理由与价格证据

- `structural_reason` 描述结构事实，`watch_reason` 描述观察方式；`primary_reason` 是面向当前阶段的阅读摘要。三者不同不构成事实冲突。
- 一致性校验只比较相同语义字段、同来源规则/快照的声明；真实数值或结构事实冲突仍阻塞。
- “低位放量涨停”与“涨停当日不追，等待次日回踩确认”必须同时保留且不触发 summary conflict。
- 正式参考价/失效位仅来自对应正式合同；观察可展示已有明确的观察参考位，标注来源和用途。没有数值时写“具体回踩参考位待补充”，不能用现价、20 日低点等冒充。
- why 最多 3 条，每条绑定真实证据。通用条件“回踩不破突破位”若没有可验证突破位，只能作为待补充的观察条件，不能进入 waiting_trigger 的重点榜。
- 压力位/目标价仅在策略要求时参与完整性判断。未知/不适用/缺失/冲突必须区分。

## 5. 页面信息架构

### FR-05：默认今日页

```text
交易日 / 阶段 / 更新时间 / 数据状态
今日结论：正式主推状态 + H4 独立状态 + 一句可验证原因
完整展开的大盘证据（指数、五项原始依据、情绪趋势），之后是本期结论与候选
┌ 今日清单（去重） ┬ 选中股票 / 页面状态 / 正式动作 / 关键异常 ┐
│ 一句话关注原因  │ 日 K + 成交量 + MACD                      │
│ 等待条件/风险名 │ 为什么 / 能否执行 / 下一确认 / 失效        │
└────────────────┴──────────────────────────────────────────┘
完整清单、我的跟踪、预跑与盘后对照
研究验证：全部来源池、策略意见、PSY12 影子验证、历史验证、诊断
```

- 保留“今日决策 / 研究验证”两层；今日候选导航改为状态筛选，不再并列“待确认池”和“观察 Top5”。
- 默认展示“优先关注”至多 5 只；“全部”展示完整去重清单，可沿用分页/加载更多与搜索。数量是辅助信息。
- 去重后的默认状态顺序：已跟踪对象的重要失效/风险变化 → formal_ready → formal_incomplete → waiting_trigger。异常对象通过显著摘要和“待核验”筛选可见，不能悄悄消失；只有普通研究观察时明确说暂无明确候选，不凑 Top5。
- 状态内不跨策略比较分数。正式主推和 H4 按既有各自顺序交替取出，代码去重；观察按原观察视图顺序稳定归并。同值按规范代码稳定排序。该顺序仅为阅读顺序，不修改任何源池排序或交易优先级。
- 默认选第一条优先关注；优先关注为空而只有待核验项时，先显示空选/异常解释及查看完整清单入口，不自动把异常候选当成主推。
- 每行：名称代码、页面状态、关注理由、具体等待条件或风险。来源标签紧凑展示；禁用“风险 1 项”替代唯一重要风险名。
- 正式行只显示对应 `decision_engine_v1.total_score` 的“决策分”；无正式分不回退。多正式策略分数不同则首行不显示单一总分，详情分别列出。研究行不强调分数；研究详情注明原生分/池内排序分/引擎分，均不称胜率。

### FR-06：今日结论与空选

- 分别显示正式主推与 H4 的 available / verified_empty / unavailable；不得用一个“无推荐”掩盖 H4 仍有正式结果。
- 正常空选时引用已有漏斗/诊断计数及门控原因；例如当日样本可表达“11 只基础候选经融合筛选剩 2 只，2 只均未达正式推荐条件”。
- 只有同一快照的计数才可连成漏斗；输入不可追溯时显示“本期无正式推荐，筛选原因未完整记录”，不得补造淘汰数。
- 市场情绪与策略门控条件分别命名并解释，不能用“市场偏强”推出一定有推荐。
- 大盘证据必须位于默认“今日决策”，不可折叠、不可藏入“研究验证”。正式日期、状态、六指数、五项原始依据与得分、历史情绪曲线直接显示；综合情绪与指数表现分别命名。PSY12 影子验证保留在研究层。
- 用户已确认持仓风险与个人跟踪状态沿用现有权限/隐藏规则；未配置不显示卖出建议，不新增对外持仓明细。

### FR-07：重要变化

- 从现有相邻有效报告/既有盘后对照读取；同交易日预跑对正式、相邻交易日正式对正式分别命名，不混成一个“今日变化”。
- 比较代码、策略身份、正式动作、页面阶段、明确条件/失效事件；排名小幅变化或说明文案润色不算重要变化。
- 缺前快照、策略版本/价格口径不同、前期不可用时显示“无法同口径对照”；不得把首次读取全标成新增。
- 展示新增正式结果、已确认升级、明确失效以及已跟踪对象风险变化；有证据才输出“新确认/失效”，缺失不能当移出。

### FR-08：图表与四项解释

- 桌面标题与状态后先显示真实日 K、成交量和 MACD；默认最近 30 根日 K，共用缩放时间轴。

- 结构理由与图中真实标记可对应，资金/市场理由对应顶部摘要；没有相应证据不得新增图上标记。

- “证据与审计”折叠；重要 stale/conflict/关键条件缺失始终一级可见，低优先级缺口合并提示。

## 7. 推送协议与生命周期

### FR-10：共用摘要

- 通知格式器消费同一纯投影的 summary/items/changes；不另写一套选股、动作翻译或池内 Top3 合并规则。
- 预跑只能使用该预跑快照已有的主推/H4/加速输入；不为丰富消息调用盘后流程或临时补其他股票池。
- 盘后使用已通过校验的正式报告投影。预跑与盘后共用语义和渲染规则，但不同 phase/snapshot_id。
- 原始协议没有所需字段时，新增可选的展示摘要字段并测试旧快照兼容；不得冒充已有事实或破坏内容 hash/readback 校验。
- 每条消息默认至多 3 只去重股票：先重大失效/风险变化，再有正式条件者，再有具体观察条件者；按网页相同稳定次序选择。其余明细通过链接查看，不逐池凑数。
- 消息顺序：日期与阶段 → 今日结论 → 重要变化（有则展示）→ 候选、原因及关键等待条件 → 有效期/状态 → 对应日期网页链接。
- 研究候选必须带“观察”身份；正式推荐也不能省略关键不可执行原因。纯研究原生推荐字样不进入通知。
- 来源数据只支持无推荐结论时，允许短消息；不得为了生成三只候选而借用其他阶段数据。

示例是格式，不是新增实时交易建议：

```text
【盘后复核 · 2026-09-07】
今日无正式主推，H4 本期正常空选。
融合筛选剩余 2 只，均未达到正式推荐条件。
涨停后观察仍需回踩确认；具体条件不足的对象不列为重点候选。
查看今日详情：对应日期报告链接
```

### FR-11：发送时机、去重与故障

- 保留预跑原有效期和过期限制；页面封存后不恢复可执行状态。盘后是后续参考，不把收盘价包装成当前可成交价。
- 正常 `formal_pending` 只更新页面/运行状态，不发送用户通知、不记成功通知去重键。
- 沿用既有 reconciliation 有界轮询及 15:35 硬截止，不新增常驻轮询、不延长时限。正式结果就绪后发送一次有效盘后摘要，即使无变化也只发送一条简洁结论。
- 到硬截止仍无有效结果，保存失败证据；通过既有错误通知路径至多发送一次明确失败提醒，且遵守剩余时间预算。没有发送预算时必须记录未送达，不延长截止时间或伪报成功。
- 去重键包括交易日、阶段、渠道、语义事件类型和稳定摘要 hash；hash 基于代码/身份/动作/关键条件/有效期，排除生成时间、纯格式、随机 ID。
- 同一语义消息的重试不重复；真实新增/取消/纠错可以形成新的 correction 事件，明确标注更正。pending 的零 hash 不能成为一次正常盘后结果。
- 复用现有 outbox 和锁；追加版本化字段且兼容读取旧记录，不重写/清空历史发送日志。部署后已成功发过的当日正式语义不得因格式升级自动补发。
- 渠道独立判定成功；某渠道失败只重试该渠道。服务端成功记录不等于用户已阅读；无实收证据不得声称微信实收验收完成。

无投影的历史页：优先在受控 staging 中从该日现有事实生成；仅能本地兼容展示时标注旧版证据能力，不能借用当天报告或默认所有字段可用。旧视图和深链不得返回错误日期或错误股票。

不可变边界：原始行情、正式候选代码/顺序/决策/分数、H4 策略结果、正式账本及数据库内容均不因 UI 修复改变。允许新增派生展示字段及修正证据投影，不能要求整个含派生字段的 HTML/JSON hash 不变；应比较明确排除新增投影后的业务载荷以及受保护文件 hash。

源 shell 与预览 shell 的 inline payload 必须同日同快照，HTML/JS/CSS 版本一致。禁止放宽 staging 全部字段白名单来绕过保护。

复用现有 unittest/Node 测试方式。新增 tests/test_decision_workbench.py；对身份、状态、真实与伪冲突、outbox 生命周期写行为回归，不用只匹配源码字符串替代行为测试。保留既有前端静态合同测试作为辅助。
