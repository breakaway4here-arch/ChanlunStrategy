# 辅助决策驾驶舱设计

## 1. 背景与结论

当前“辅助决策中心”把市场情绪、板块资金、涨停情绪、事件驱动、卖出提醒、策略回看和诊断平铺成同权卡片，但用户真正需要的是一条可行动的判断链：

```text
今天发生了什么
→ 哪个方向得到盘面验证
→ 与我的重点观察股有什么关系
→ 下一步等什么条件
→ 什么情况说明判断失效
```

本次不继续扩充卡片数量，而是重构为“证据底座 + 决策摘要 + 重点观察池 + 持仓风控 + 策略验证”的决策驾驶舱。

## 2. 当前问题的证据

### 2.1 涨停情绪是解析失败，不是市场没有涨停

- `fetch_limit_up_pool()` 会把接口字段 `fbt` 交给 `_fmt_btime()`。
- 实际接口已可能返回整数，例如 `92500`；当前实现直接调用 `len(raw)` 和切片。
- 单条解析异常被循环中的 `except` 吞掉，因此接口有名单时仍可能返回空数组。
- 2026-08-20 已发布快照中，情绪证据保存了涨停总数，但 `limit_up_pool` 为空，页面误显示“暂无涨停池”。

### 2.2 事件 LLM 结果丰富，但页面只展示一句话

事件数据已有：

- `analysis`
- `positive_sectors` / `negative_sectors`
- `positive_stocks` / `negative_stocks`
- `impact_score`
- `market_validation`
- `tradability`

当前前端只渲染标题和 `impact.summary`，没有展示板块、个股、盘面证据，也没有与候选池或用户重点池做交叉关联。

### 2.3 卖出提醒没有持仓语义

当前 `sell_signals` 来自全市场缠论结果，只要出现卖点就进入列表，并未与用户真实持仓求交集。全市场风险样本被误命名为“卖出提醒”，会产生并不存在的操作指令。

### 2.4 策略回看无法归因

当前回看把近期信号按代码去重后全量展示，但历史记录缺少：

- 当时的 `decision_code`
- 推荐规则及贡献策略
- 推荐理由快照
- 策略/配置/代码版本
- 市场状态
- 可执行入场与退出口径

因此 observe/reject 也可能被前端标成“推荐日”，且无法回答“哪条策略导致推荐、该策略历史表现如何”。

## 3. 产品目标

1. 用户打开辅助区后，十秒内知道当天最重要的方向、证据强弱和下一确认条件。
2. 用户的五只重点观察股每天都被分析，不依赖它们是否进入选股池。
3. 观察股与真实持仓严格分离，不从观察池推断卖出动作。
4. LLM 参与事件仲裁、方向聚类、关联分析和条件推演，而不是只写摘要。
5. 所有 LLM 结论可追溯到结构化证据；失败时明确降级。
6. 策略回看先展示可解释的策略统计，再允许下钻到单次推荐。

## 4. 非目标

1. 不让 LLM 自由生成行情数字、收益率或无证据的“龙头”。
2. 不把事件催化直接等价为买入信号。
3. 不把历史观察、拒绝信号伪装成推荐样本。
4. 不使用旧的 `holdings/accounts.yaml` 示例作为真实持仓。
5. 不覆盖或混入主工作区现有的未提交改动。
6. 不修改核心选股算法来迎合辅助区展示。
7. 不把 `picks_pure`、`picks_fusion`、强势启动、趋势延续、观察池、次日大涨、罗姐池和 H4 T+3 强行统一为一套候选、评分或准入逻辑。辅助区只消费各池已经形成的身份和证据，不得二次升级池内结论。

核心选股链路在 2026-08-21 复核中发现的语义、归因、标签和兼容性问题，以及“只统一基础合同、不统一各池逻辑”的讨论边界，记录在本文第 13 节。该章节是历史设计记录；其中未被后续实施记录取代的研究与审计边界继续作为追溯依据。

## 5. 信息架构

### 5.1 市场证据底座

保留现有“市场情绪”和“板块资金”，新增可审计的涨停生态：

- 涨停总数、跌停总数
- 解析数量、覆盖率、数据状态和时间
- 最高连板、最早封板
- Top 题材及数量
- 龙头候选的事实角色
- 与重点观察池的交集

### 5.2 今日决策摘要

最多展示三个方向簇，允许少于三个，也允许明确显示“今日无有效主催化”。每个方向按以下证据链展示：

```text
事件/催化
→ 方向与板块
→ 资金/涨停验证
→ 被新闻点名、涨停领先或板块强势的股票
→ 候选池/重点观察池交集
→ 下一确认条件
→ 失效条件
```

至少保留一个负向或风险方向的展示能力，避免只呈现利好叙事。

负向或风险方向必须独立列出具体风险原因，不能只在摘要、证据链、下一确认或失效条件中隐含表达，也不能用“风险成立”四个字代替原因。每条原因至少说明风险事实、可能影响和证据引用；风险原因属于解释合同，未经单独回看验证不得直接充当选股硬门。

### 5.3 我的重点观察池

初始配置：

| 优先级 | 代码 | 名称 | 角色 |
| --- | --- | --- | --- |
| 1 | 300139 | 晓程科技 | strong_watch |
| 2 | 002281 | 光迅科技 | strong_watch |
| 3 | 300308 | 中际旭创 | strong_watch |
| 4 | 688041 | 海光信息 | strong_watch |
| 5 | 688525 | 佰维存储 | strong_watch |

每只股票固定展示：

- `as_of` 与数据状态
- 相对上一交易日的事实变化；新加入时显示“新增关注”
- 关联方向、事件和板块证据
- 当前结构摘要
- 状态：`可计划 / 等确认 / 回避 / 数据不足`
- 下一确认条件与失效条件
- 用户 thesis 与 LLM 判断分栏

“可计划”必须通过确定性硬门控；LLM 只能解释，不能单独升级状态。

### 5.4 持仓风控

只有 `fresh + confirmed` 的真实持仓才参与卖出提醒。持仓合同至少包含：

- `source`
- `as_of`
- `confirmed_at`
- `stale_after`
- `code`
- 可选成本、数量和仓位

页面只展示真实持仓与全市场 `sell_signals` 的交集。未配置或已过期时，不显示任何个股卖出动作。

### 5.5 策略验证

默认 cohort 同时要求当时 `decision_code=recommend`、`publication_status=published`、`user_action=recommendation`；内部观察池即使门控为 recommend 也不计入策略收益。observe/reject 与 watch/none 分开作为门控和发布效果展示。主屏按策略展示：

- 成熟样本数与样本不足状态
- T+1 / T+3 / T+5 胜率
- 中位收益、均值、相对基准超额
- MAE / MFE
- 代表性正负样本

每次推荐写入不可变推荐账本：

```json
{
  "recommendation_id": "...",
  "signal_id": "...",
  "decision_code": "recommend",
  "reason_snapshot": [],
  "strategy_contributions": [
    {"strategy_id": "...", "role": "primary", "version": "..."}
  ],
  "policy_version": "...",
  "config_hash": "...",
  "code_commit": "...",
  "market_regime": "...",
  "entry_rule": "...",
  "entry_price": null
}
```

收益统计必须先锁定可执行口径：前复权、权威交易日历、入场时点、显式 horizon、推荐/入场/目标日终局性、停牌/涨停不可成交、成熟样本、逐期限基准日期对齐、右删失、重复 episode 和跨策略归因。个股缺 K 线不得把下一根 K 线顺延成目标交易日；日报验收通过前只能形成 provisional batch，不能进入永久账本。

## 6. 数据合同

### 6.1 `limit_up_snapshot`

```json
{
  "date": "2026-08-20",
  "as_of": "2026-08-20T15:10:00+08:00",
  "generated_at": "...",
  "source": "eastmoney_limit_pools",
  "status": "verified_complete",
  "raw_total": 79,
  "limit_down_total": 12,
  "parsed_count": 79,
  "parse_error_count": 0,
  "coverage": 1.0,
  "items": [],
  "theme_groups": [],
  "leaders": [],
  "error": ""
}
```

状态枚举：

- `verified_complete`
- `verified_empty`
- `partial`
- `missing`
- `error`

只有 `raw_total=0 + verified_empty` 才表示确实没有涨停。空 `items` 不能单独解释为零。接口总量超过单页上限时必须分页或标记 partial。

旧的 2026-08-20 报告只用于证明“总量非零但名单为空”的矛盾。当前重新抓取的名单属于历史重建，必须标记 `historical_reconstruction`，不得覆盖或冒充原始快照。

### 6.2 `decision_brief`

```json
{
  "status": "ok",
  "model": "...",
  "prompt_version": "...",
  "schema_version": "1",
  "generated_at": "...",
  "theses": [
    {
      "thesis_id": "...",
      "direction": "positive",
      "stage": "confirmed",
      "confidence": "medium",
      "evidence_refs": [],
      "sector_links": [],
      "stock_links": [],
      "risk_reasons": [
        {
          "reason": "...",
          "impact": "...",
          "evidence_refs": []
        }
      ],
      "watchlist_impacts": [],
      "next_trigger": [],
      "invalidation": []
    }
  ],
  "arbitration": []
}
```

每条事件仲裁记录保留：

- `rule_score`
- `rule_result`
- `llm_result`
- `arbitration_result`
- `arbitration_reason`
- `model`
- `prompt_version`
- `schema_version`

`stock_links` 必须带 `link_type` 和 `evidence_ref`。允许的事实角色包括：新闻点名、涨停领先、板块强势、重点池交集、候选池交集。仅通过代码名称校验不能称为龙头。

`risk_reasons` 是独立必显字段：当 `direction` 为负向或页面显示“风险成立”时至少有一条；每条必须是可理解的具体原因，并带影响说明和证据引用。摘要、`next_trigger`、`invalidation` 或通用风险标签都不能替代该字段。非负向方向允许为空数组。

### 6.3 重点池配置与分析快照

配置态与分析态分离：

- canonical 配置保存用户想关注什么。
- 日报快照保存本次生成时真正分析了哪个 revision。

配置至少包含：

- `schema_version`
- `revision` / `etag`
- `updated_at` / `updated_by`
- `enabled`
- `added_at`
- `code`
- `role`
- `priority`
- `tags`
- `note` / `thesis`

股票名称由代码映射生成，不信任任意输入名称。

## 7. LLM 工作边界

### 7.1 LLM 负责

- 新增催化与盘面复盘的语义区分
- no-impact 复核与可审计仲裁
- 多事件语义去重和方向聚类
- 事件、板块、候选池、重点池的关联解释
- 确认/失效条件的自然语言组织
- 基于确定性聚合数据生成策略复盘摘要

### 7.2 规则和代码负责

- 行情、涨跌幅、收益和统计计算
- 股票代码/名称校验
- evidence ref 存在性校验
- 事实角色和龙头资格计算
- “可计划”硬门控
- 持仓 freshness 和交集
- LLM 输出 schema、枚举和降级

### 7.3 降级

LLM 失败时展示规则聚类和事实证据，并明确标记“LLM 分析不可用”。不得使用规则文本伪装成 AI 结论，也不得清空可用事实。

## 8. 动态维护

### 8.1 运行时真相与故障回退

Cloudflare Worker 后的单一 SQLite-backed Durable Object 是版本化配置的 live truth；仓库内版本化配置只作为首次部署和远端不可用时的 bootstrap/fallback。日报生成必须先读取并严格校验远端完整版本，成功后整体替换本地版本，禁止逐项静默合并。远端连接或校验失败时，使用本地回退版本，并在 `data_quality.personal_watchlist_config` 中披露来源、revision 和错误。Workers KV 仍服务原有 Top10 数据，但因 eventual consistency 且没有原子 CAS，不参与重点池的 ETag 版本锁。

日报始终嵌入本次真正使用的不可变分析快照。页面保存只更新下一次运行要读取的配置，不得改写已经生成的日报。

### 8.2 页面管理

最后阶段扩展现有 Cloudflare Worker：

- GET 返回配置 revision。
- PUT 通过 Worker 端秘密或短时会话鉴权。
- 使用 ETag/乐观锁避免覆盖他人更新。
- 校验代码、角色、最大数量、schema 和 CORS。
- 保留审计与回滚所需的 revision。
- 静态页面不保存可写凭据。
- 日报生成从同一 Worker GET 接口读取配置，确保页面保存与下次分析之间存在真实闭环。

重点池的 current revision、完整 revision 快照和审计记录必须在单一 Durable Object 的事务内写入。不能用 Workers KV 的非原子 read-check-write 冒充 ETag 并发保护。调试报告不注入可写的重点池地址，避免从 debug 页面误改生产配置。

保存后的新配置只显示“等待下次日报分析”，不能混入当天快照并伪装已分析。

## 9. 视觉与交互

采用 Swiss 方向：白/冷灰底、单一蓝色强调、细网格和左对齐信息层级。核心差异化是横向“证据链轨道”，不是装饰。

交互遵循 scan-first：

- 默认只展开最多三个方向和五只重点股摘要。
- 一次只展开一个详情。
- 桌面端展示证据链，手机端改为纵向步骤。
- 风险、partial、LLM 失败和数据不足使用不同语义状态，不仅依赖颜色。

## 10. 分期与验收门

### P0：涨停解析与状态合同

- 整数 `92500` 解析为 `09:25`。
- 接口名单、总数、日期和覆盖率可核对。
- 解析失败不再展示“暂无涨停”。

### P1：重点池 canonical 配置和事实快照

- 五只股票不论是否入选都出现。
- 新加入股票显示“新增关注”。
- 无新鲜数据时不输出具体价位和强动作。

### P2：方向簇、LLM 仲裁与证据链

- 2026-08-20 冻结事件中，“海外光通信”可关联中际旭创。
- `no_impact=true` 的收评不进入主催化前三。
- LLM 失败、冲突和引用错误均可见且可降级。

### P3：推荐账本与策略 scorecard

- 默认 cohort 全部是 `decision_code=recommend`。
- observe/reject/unknown 分栏。
- 每个成熟样本能追到推荐账本、贡献策略和收益口径。
- 旧数据只标 `legacy_inferred/unknown`，不伪造版本。

### P4：页面关注池管理

- 新增、删除、排序、启停可持久化。
- revision 冲突不会静默覆盖。
- 保存后明确显示何时生效。
- P4 失败不影响 P0-P3 已发布能力。

## 12. 选股池、页面角色与收益回看合同（2026-08-26 确认）

### 12.1 共同上游不等于统一策略

`picks_pure` 是所有选股策略的共同上游全集，只收原始缠论结构候选。共同上游只统一输入边界，不统一任何策略的门槛、排序、空选、持有期或风险判断。每个策略必须从 `picks_pure` 独立筛选并产出自己的池；一个策略可正常空选，禁止从其他策略池回填。这个子集合同同时覆盖融合主推、强势启动、趋势延续、次日爆发、罗姐主题与 H4 T+3；关注池是用户观察配置，不是选股策略输出。

正式生产策略输入不健康时 fail closed：页面保留原始池用于事故追溯，但正式 Tab 清空、正式动作封闭、收益样本排除。研究池和上游全集始终不得输出正式买入动作。历史策略视图只要含有任一 `picks_pure` 全集外代码，整个视图都标记 `strategy_upstream_contract_mismatch` 并封闭，禁止删除全集外代码后擅自重排成一份“看似有效”的榜单。

`selection_input_health.schema_version=2` 必须为 `daily_fusion / h4_t3 / luojie_pool` 分别记录状态、阻断原因和受影响代码，并允许按 `by_view` 登记历史展示层的上游合同事故。融合策略的 30min 事故不得自动封闭健康的 H4；H4 自己的上游合同错误也不得归因为融合策略故障。旧快照缺少策略级健康证明，或出现 `status != verified` 但仍带允许标记的矛盾输入时，除 `baseline` 基础候选外的策略视图全部按不可用处理并清空列表。

| `h4_t3_pool.candidates` | `h4_t3` | H4 T+3 | 正式策略 | H4 独立门槛与排序；输入健康时可显示正式策略动作 |

| `observation_watchlist` | `observation_top5` | 观察 Top5 | 研究观察 | 只能观察；不得静默改用其他池 |

| `luojie_pool.candidates` | `luojie` | 罗姐池 | 研究观察 | 只能观察；使用自己的 15min 生命线合同 |
| `startup_watchlist` | `confirming` | 等确认 | 研究观察 | 只能观察 |
| 上述四个研究池的高弹性二次排序 | `growth_quality` | 高弹性观察 Top10 | 研究观察 | 只能观察 |
| `picks_pure` | `baseline` | 基础候选 | 上游全集 | 仅作为策略上游；不代表任何策略结果 |

`decision_watchlist` 是用户动态重点观察配置，显示在“重点观察池 / 关注池管理”，不属于上述九个选股 Tab，也不参与正式策略回填。

### 12.3 页面状态必须回答“对不对”

每个 Tab 同时展示角色、来源池、数量、可用状态和页面动作权限。状态枚举固定为：

- `available`：数据可用。
- `verified_empty`：策略已正常运行但没有候选通过门槛。
- `disabled`：策略今日按规则未启用。
- `partial`：部分证据可用，只能降级观察。
- `unavailable`：证据缺失、过期或合同错误；对应策略视图必须封闭并清空，原始池只留作追溯。

缺失字段、错误类型和合法空数组不能在序列化时合并。旧快照缺少新元数据时，按 Tab key 使用兼容合同回退，不显示“来源池未登记”一类内部字段。

### 12.4 收盘价研究与高收益轨迹

本项目只研究收盘后决策，不模拟实际成交：

- 入场价统一使用信号交易日收盘价。
- T+1 / T+3 / T+5 统一使用对应第 1 / 3 / 5 个交易日收盘价。
- 每个周期同时展示期间最高收益 MFE、期间最低收益 MAE，以及是否盘中触及 `+5%`。
- 只有日期与终局状态核验通过的收盘证据可以进入计算；缺失时显示“数据不可用”，不得向后顺延交易日或使用泛化现价替代。
- `0.00%` 只表示真实零收益；“等待到期”“正常空选”“今日未启用”“数据不可用”必须分别展示。

正式推荐、`picks_pure` 基线、独立研究策略和只做分流的门控诊断分区展示，禁止把不同角色混成一个平均收益。

### 12.5 历史输入事故与样本排除

历史账本保持不可变；事故修复通过版本化排除登记实现。登记必须精确到日期、策略、股票代码、错误码和原因，页面展示信号数、收益合同样本数、可评数、非收益样本数、事故排除数、去重回合数及事故编号。补齐价格不能解除“策略输入过期或未核验”的排除。

事故样本若仍出现在只读复盘面，候选行必须显示“策略输入过期·仅复盘”，原始规则判定统一改称“事故前原始判定”，评分与分项分不得作为有效分数展示，过期分钟级理由不得继续写成当前有效证据；图表中的图钉和参考线也必须标成“事故前·仅追溯”，不能让图表层重新把失效参考价包装成当前依据。跨日报正式表现比较同样必须逐日核验对应策略的 schema v2 健康证明；缺证明时该日正式列表为空，不能只依赖事故代码表过滤。

2026-08-26 已登记的已知事故包括：

- 罗姐策略 2026-08-24 至 2026-08-26 的 15min 输入过期或非终局，相关贡献排除。
- 日线融合策略 2026-08-25 的 `300473` 30min 输入过期或非终局。
- 日线融合策略 2026-08-26 的 `300697` 30min 输入过期或非终局。
- H4 T+3 在 2026-08-26 的历史快照使用 `picks_fusion` 作为上游，与已确认的 `picks_pure` 共同上游合同不一致；该日 H4 独立标记 `strategy_upstream_contract_mismatch`，不归因为融合策略 30min 故障。

日期和代码必须拆成独立规则，禁止跨日期误伤同一代码或同一日期的其他代码。

### 12.6 整页信息架构与已标注待办

页面阅读顺序固定为：收盘版与输入健康状态 → 今日方向摘要 → 分组后的选股 Tab → 当前池候选 → 证据驾驶舱 → 分角色记分牌。移动端折叠大盘概览；大池首次只渲染 20 条，支持搜索、“加载更多”及候选行的上下方向键 / Home / End 导航。这是展示分页，不限制 `picks_pure` 或任何策略池数量。

记分牌每张卡必须固定拆成三条可对账口径：“今日运行”只说当日任务，“账本累计”必须带起止日期与累计分流，“收益评测”必须单列合同样本、可评样本、非收益样本、事故排除和去重回合。禁止用一个“信号数”同时指代三种分母。

风险必须提供结构化原因、证据编号、确认条件和失效条件；“风险成立”“负向待核验”“模型提取待核实”不得混用。

**已标注待办 / 不确定项：**当前只完成 DOM 渐进渲染，整份日报 JSON/HTML 仍包含完整候选与图表数据，网络载荷尚未按股票拆分为按需加载。该问题影响首屏性能，不改变选股结果和池数量；后续需单独设计静态 Pages 的摘要清单与个股详情分片合同。

### 12.2 问题背景与用户需要

当前系统已经存在多条来源、使命和持有周期不同的候选通道，但它们在后半段被部分合并到相同的评分、决策、页面和回看合同中。问题不是“池子太多”，而是池子的独立语义在合并过程中被削弱：

1. 某个池子内部已经标记为观察的信号，仍可能被通用决策层升级为推荐。
2. 趋势、低位反转和强势启动使用了不完全兼容的趋势、位置和确认先验。
3. 页面、漏斗和推荐账本对“进入候选池”“通过池内门槛”“最终推荐”使用了不一致的口径。
4. T+1、T+3、T+5 的标签与可执行收益没有完全分开，无法确认每个池子到底在优化什么。
5. H4 T+3 使用冻结的 v1 特征语义，不能在修改通用决策字段后继续沿用旧模型身份。

用户需要的是：每个池子保留自己的策略定义；能逐只回答来自哪个池、为什么入池、通过了哪条池内规则、面向哪个周期、为什么成为或没有成为最终推荐；最终优化选股质量，而不是把不同策略包装成看起来一致的分数。

#### 12.3.2 已授权的推荐边界

2. **趋势延续**：保留现有独立日线结构、量能、追高风险和 30min 至少两项确认的路线；位置评价改为趋势参考位、延伸度、跳空和过热语义，不接受低位反转分位惩罚。跌破趋势参考位、30min EMA 转空或高位放量破坏结构时失效。
3. **加速 Tab**：定位为独立 T+1 观察榜。在 T+1 标签、入场方式和 OOT 结果独立验收前，不进入“主推”、推荐账本或用户动作统计；当前上证涨幅阈值和 Top5 只视为待验证策略参数。
4. **罗姐池 Tab**：保持主题与 15min 生命线观察池身份；未完成独立历史回看和执行合同前不得晋级“主推”。
5. **H4 T+3 Tab**：继续使用冻结 v1 独立生产合同，真实空池即为空，不设上限、不回填、不增加主推分；通用决策字段修改不得原地改变 v1 特征，v2 必须重新训练、OOT 和验收。
6. **多池同票**：页面并列显示来源策略、各自原因、状态和周期，不合成“多池共振”分，也不因多池命中自动升级；最终是否进入“主推”仍只由融合最终合同决定。
7. **页面名称**：“基准” Tab 应改成用户能理解的“基础候选”，候选卡必须显示来源策略；“主推”是唯一默认表达可执行推荐的综合 Tab，其他 Tab 除非以后独立验收，不使用可买入措辞。
8. **主推持有周期**：允许不同主推股票采用不同的主要持有周期，但每只必须在主推卡片、详情和推荐账本明确标注 `T+1`、`T+3` 或 `T+5`。主要周期只能来自对应来源策略已经验收的周期合同，不能由通用分临时猜测；无法给出唯一且已验证主要周期的候选只能观察。多来源同票时保留各来源周期，同时明确一个用于用户动作和归因的 `intended_horizon`。
9. **统一研究价格**：本项目只优化选股，不建模实际交易。统一沿用 `entry_mode=immediate_close`（页面标签“信号日收盘价”）作为研究入场价；`T+1`、`T+3`、`T+5` 分别使用对应未来交易日收盘价作为主收益。同时展示从入场收盘价到周期窗口内最高价的“期间最高收益（MFE）”，以及到窗口内最低价的“期间最低收益（MAE）”。券商委托、是否成交、真实成交价、实盘止损止盈、持仓和实盘盈亏全部不进入本轮设计，也不得反向污染选股标签。
10. **主推数量**：不设人工固定上限，不截 Top3/Top5。每个周期所有通过自身最终门槛的股票都进入“主推”，真实结果可以很多、很少或为零；不得为了数量好看回填，也不得把过门股票因名额不足降级。Top-K 曲线只用于评估排序、边际质量和门槛是否合理，不直接充当生产数量开关。

周期窗口必须从信号日之后的第一个交易日开始，禁止把信号日盘中的最高价或最低价计入入场后的表现：

- `T+1 收盘收益 = C(D+1) / C(D) - 1`
- `T+1 期间最高收益 = H(D+1) / C(D) - 1`
- `T+3 期间最高收益 = max(H(D+1..D+3)) / C(D) - 1`
- `T+5 期间最高收益 = max(H(D+1..D+5)) / C(D) - 1`
- 各周期“期间最低收益”使用同一窗口内 `min(L)` 计算。

例如信号日收盘价为 10 元，D+1 收盘价为 10.5 元、盘中最高价为 11 元，则页面显示“`T+1 收盘 +5%｜期间最高 +10%`”。收盘收益仍是主要验收指标，期间最高收益用于识别上冲潜力和退出空间，不能替代收盘收益；期间最低收益用于同时暴露路径风险。

这些决定只完成设计收口，不授权直接修改代码。具体阈值先保持可审计并进入影子评测，除明确的状态越权和标签错误外，不凭主观猜测调参。

### 12.5 可以统一与不能统一的边界

可以统一的只有基础合同与验收协议：

1. 股票身份、交易日、`as_of`、数据来源、数据状态和证据引用。
2. 策略版本、配置版本、代码版本、池版本与模型版本。
3. 标签命名和收益计算公式；同名字段不得表达两种收益。
4. 面向页面和账本的外层发布状态枚举，例如候选、观察、推荐、拒绝和数据不足；池内阶段、等级和状态机仍由各池自定义。
5. 漏斗事件结构：来自哪个池、通过了哪些池内门、失败在哪个池内门。
6. 防未来泄漏、确定性双跑、真实数据、缺失 fail-close 和 OOT 锁定。
7. 公共评测输出格式：样本数、活跃日、每日数量、mean/median、上涨/下跌率、`>=5%`、`<=-5%`、worst、时序稳定性和 Top-K 曲线；只在相同池、相同周期和明确版本边界内比较，不把不同池的原始分数横向混排。

不能统一的是各池的策略语义：

1. 各策略在合流前的扫描宇宙、召回来源和候选成立规则；`picks_pure` 只统一承载确认后的候选全集。
2. 信号成立、确认、取消和失效条件。
3. 低位、高位、突破、回踩和追高风险的解释。
4. 市场状态是否参与、参与哪个阶段以及影响方式。
5. 池内评分、排序、阈值、每日数量和持有周期。
6. 从观察到候选、从候选到推荐的晋级规则。
7. 失败后的回退状态和用户动作。

任何跨池共享的字段都必须保持“事实字段”或“审计字段”身份，不能偷偷变成统一的策略含义。跨池汇总层只能保持或降低池内状态，不能把池内观察升级为推荐。

### 12.6 备选方案与最终选择

| 方案 | 描述 | 优点 | 主要问题 |
| --- | --- | --- | --- |
| A：统一总分和门槛 | 所有池映射到一套 decision score | 实现和页面简单 | 低位反转、趋势延续、启动加速先验冲突；无法归因 |
| B：完全独立 | 每个池连数据、字段、收益和回看都独立 | 策略隔离最彻底 | 数据身份和收益口径易漂移，重复建设，无法公平比较 |
| C：共享合同、逻辑独立 | 公共层只负责真实数据、证据、版本、标签、状态和评测；池内自行决策 | 保留策略差异，同时可追溯、可比较、可回滚 | 需要逐池补齐正式定义；实施复杂度高于 A |

最终选择方案 C。它不追求一张统一总榜；同一只股票可以同时出现在多个池，但必须并列保留每个池各自的原因和状态，不能合并成一句模糊的“多池共振所以推荐”。本方案只批准设计边界，不等于已经授权实施。

### 12.7 异议、权衡与风险

- 用户明确反对把各池强行统一为一套逻辑；这条边界优先于前一版“统一分周期选择器”的表述。
- 主分析 agent 原建议“统一类型化信号合同”，现修正为：只统一基础数据和审计字段；任何带策略含义的类型、确认和分数仍由池内定义。
- 独立复核 agent 支持先修合同再优化，但其“最终分周期选择器”同样不能覆盖池内晋级逻辑；分周期汇总只能消费各池已经形成的输出。
- 接受页面和研究结果更复杂、逐池讨论节奏更慢、部分池长期为空或停用，以及 v1/v2 并存一段时间；这些成本低于再次混淆策略语义。
- 主要风险是公共字段再次承载策略含义、汇总层偷偷升级、策略版本污染和修复 v1 后破坏 H4。缓解方式分别是字段所有权、只降不升、强制非空池版本，以及冻结 H4 v1。

该边界可以逐池实施和回滚。若后续证据证明两个池确实可以共享某项规则，也必须在两者各自评测通过后显式复用，不能因为字段同名自动合并。

### 12.8 已确认的选股研究语义

以下问题会改变标签和回看收益，现已全部确认；本项目不讨论实际交易：

已确认：主推股票可以具有不同的主要持有周期，但必须逐只明确标注；无已验证主要周期不得进入主推。

已确认：本项目只评价和优化选股，不考虑实际交易。主推统一使用 `immediate_close`，以信号日正式收盘价为研究入场价；`T+1`、`T+3`、`T+5` 统一以对应未来交易日收盘价作为主收益，并展示从 D+1 开始到对应周期为止的期间最高收益和期间最低收益。页面使用“收盘收益／期间最高／期间最低”中文名称，不只显示 MAE/MFE 缩写。

已确认：主推不设人工每日数量上限，所有过门股票全部展示，允许零只、不回填；Top-K 只做研究诊断，不截断生产结果。

已确认：版本选择偏好为高收益优先，不以尾部风险最低作为第一目标。`<=-5%` 比例、worst、期间最低收益和时序稳定性仍必须完整披露，但不因风险指标相对更差就自动否决收益明显更高的非支配版本；数据真实性、防泄漏、成熟标签和 OOT 等研究硬门不得降低。

已确认：高收益版本以每只股票 `intended_horizon` 对应的平均收盘收益为第一主指标；中位收盘收益与 `>=5%` 命中率是稳健性支持指标，用来识别是否只由少数极端样本拉高均值。若候选版本均值更高、但中位数与 `>=5%` 命中率相对基线同时变差，则标记为“异常值驱动”，不得直接替换生产版本；至少一项不差时，才进入非支配版本比较。期间最高收益只用于展示上冲空间和诊断，不作为第一优化目标。

已确认：生产替换只使用按时间顺序锁定、调参后不再回看的 OOT 窗口，并按“同一来源池 + 同一 `intended_horizon` + 同一入场模式”分别验收。每个切片至少需要 100 个 primary 完整成熟样本、20 个有候选且可形成 primary 完整样本的指标日期，并覆盖 2 个非重叠自然月；30–99 个成熟样本或 10–19 个指标日期只能标记为影子观察，低于该范围为数据不足。不得通过跨池、跨周期合并样本或缩短门槛宣布高收益版本胜出；数据不足时保留现版本并继续积累样本。

据此冻结最终标签、评测目标和实施计划。任何阈值变化仍须先以历史重放、时序 OOT 和按周期分层结果证明，不得为了提高均值直接降低研究硬门。

## 14. 2026-08-27 涨跌停选股合同（已确认、禁止隐式改动）

### 14.1 用户确认的固定规则

本节是核心选股合同，不是可自由调参的策略偏好。后续不得以“提高收益”“减少候选”“降低追高风险”“统一逻辑”或页面展示优化为由，重新引入统一 `9.5%` 涨跌停阈值，也不得在未明确说明的情况下改变以下状态流转：

| 交易状态 | 基础候选 Tab（`picks_pure`）及正式策略 | 观察区 | 固定含义 |
| --- | --- | --- | --- |
| `normal` | 按原始缠论结构及各策略自身门槛继续筛选；即使涨幅超过 9.5%，只要没有达到该股票真实涨停价，也不得因涨幅本身提前删除 | 可按各策略近失规则观察 | 例如创业板 301629 涨 13.71% 仍是正常交易状态，不是涨停 |

### 14.2 唯一允许的判断方式

涨跌停必须根据上一交易日收盘价、证券代码、名称/风险标识、交易板块、交易所价格精度和无涨跌幅限制状态，调用统一事实函数 `chanlun.market_sentiment.classify_price_limit` 判断。当前基础规则为主板 10%、创业板/科创板 20%、北交所 30%、适用的 ST 规则及新股无涨跌幅限制规则；最终状态以交易所价格取整后的真实涨停价或跌停价为准，禁止使用 `change_pct >= 9.5`、`<= -9.5` 或任何跨板块百分比捷径。

该统一仅属于市场事实合同，不会统一原始缠论结构、强势启动、趋势延续、融合 admission、评分、确认、排序、周期或失效逻辑。股票被判定为 `normal` 只表示允许继续参加各池自己的筛选，不代表自动入选或推荐。

### 14.3 与共同上游合同的关系

正式策略继续遵守 `codes ⊆ picks_pure`，真实空池允许为空且不得回填。`limit_up` 是唯一明确登记的非正式观察例外：它可以绕过正式共同上游，仅供强势启动和趋势延续生成观察项及只读观察派生视图；该例外必须同时满足 `view=observation`、`tier=watch`、`price_limit_state=limit_up`，主推和 H4 T+3 等正式视图不得使用该旁路。`limit_down` 和涨幅较大但状态为 `normal` 的股票都不适用该例外；后者必须先正常进入 `picks_pure` 共同上游。

### 14.4 变更治理与回归门槛

本合同只有在交易所规则发生变化，或用户明确要求重新设计时才能修改。修改前必须同时完成：

1. 在本文记录变更原因、适用板块、旧规则和新规则。
2. 获得用户明确确认；普通选股优化、影子分数或收益提升不能视为授权。
3. 回归覆盖主板 10%、创业板/科创板 20%、北交所 30%、ST、真实跌停、无涨跌幅限制，以及“涨幅超过 9.5% 但未真实涨停”的反例。
4. 验证正式候选仍受 `picks_pure` 共同上游约束，涨停旁路只能生成观察项，不能进入主推和推荐账本。

301629 是本合同的固定回归样本：2026-08-27 前收 255.92 元、收盘 291.00 元，涨幅 13.71%，创业板真实涨停价约 307.10 元，因此状态必须为 `normal`，应继续进行日线结构、趋势延续及 30 分钟确认；是否最终推荐仍由后续策略门槛决定。
