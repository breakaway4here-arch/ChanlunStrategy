# 14:45 预跑封存回看设计

## 背景

当前预跑快照在 14:56:30 到期后同时发生两件事：

1. Worker 将状态切为 `expired` 并清空公开三池；
2. 前端只显示“预跑已失效”，隐藏股票、代码和参考价。

第一件事原本用于阻止 14:57 后依据旧清单新增动作，但第二件事让已经产生的结果无法回看。用户需要保留安全边界，同时把当日预跑结果折叠保存。

## 目标

- 14:56:30 后不再依据预跑结果新增动作，既有时间边界不变。
- 到期结果改称“已封存”，默认折叠，但仍可只读展开。
- 展开后仅显示公开三池中的股票名称、代码和参考价。
- 根页展示上海当天的快照；下一交易日由新日期自然替换。
- 历史日期页可永久回看对应交易日的封存快照。
- 不改变盘后正式任务、正式三池、账本、数据库、Pages 正式数据、PSY12、右侧启动 shadow 或微信通知门槛。

## 不做事项

- 不延长预跑的可操作时间。
- 不让封存结果参与 14:57 后的动作、评分或正式推荐。
- 不把预跑数据写入正式报告或正式数据库。
- 不增加新闻、LLM、iWencai、15 分钟或报告生成依赖。
- 不修改 Durable Object migration 或现有 Top10 Worker。

## 方案比较

### 方案 A：仅由前端在内存中保留

到期时不清空当前 DOM，只折叠已有内容。实现最少，但页面刷新、换设备或打开历史日期页后，Worker 仍返回空池，结果依然丢失。因此不采用。

### 方案 B：Worker 保留公开三池，前端将到期快照封存折叠

Worker 继续返回 `status=expired`、`is_final=false`、`affects_formal=false` 和原始 `expires_at`，但不再清空已经过公开字段白名单的三池。前端把 `expired` 映射成“已封存”，默认折叠并保留只读详情。该方案同时满足刷新后回看和动作关闭，采用此方案。

### 方案 C：盘后把预跑结果合并进正式 Pages 数据

历史回看最直观，但会让预跑写入正式发布链路，破坏现有隔离和复核边界，且增加正式任务失败面。因此不采用。

## 数据合同

到期前公开响应保持现状：

- `status=available`；
- 三池为公开候选；
- 页面默认展开；
- 文案明确有效截止时间。

到期后公开响应调整为：

- `status=expired`，作为不可操作的唯一判断依据；
- `is_final=false`、`affects_formal=false`；
- `snapshot_id`、`content_hash`、`trade_date`、`generated_at`、`expires_at` 保持不变；
- `pools.main`、`pools.h4_t3`、`pools.acceleration` 保留；
- 每只候选仍只允许 `code`、`name`、`reference_price`；
- `message` 改为“预跑已封存，仅供回看；14:57后不再依据预跑清单新增动作”。

禁止公开诊断、失败门槛、审计历史、评分、内部原因、凭证或其他研究池字段。快照内容哈希和 Durable Object 存储结构不变。

## 前端交互

预跑卡片使用原生 `<details>`：

- 活跃期默认展开，标题保持“14:45预跑”；
- 到期后默认折叠，标题为“14:45预跑 · 已封存”；
- 折叠摘要显示“主推 N只｜H4 T+3 N只｜加速 N只”和快照短哈希；
- 展开后显示生成时间、封存时间、只读三池和安全提示；
- 候选继续使用非交互 `<div>`，不得出现买入按钮、链接或任何执行控件；
- 三池都为空时仍显示统一空态“本期未选出推荐票”。

盘后复核卡保持独立。复核 hash 必须与封存快照一致，才能显示保留、正式新增和预跑有但正式无的差异。

## 日期与保留规则

- 根页按 Asia/Shanghai 当天日期请求快照，不回退到前一交易日。
- 下一交易日尚未生成预跑时，根页显示当天暂无快照，不冒用旧结果。
- `/YYYY-MM-DD/` 历史日期页请求其日期对应的 Durable Object，因此可长期展开回看。
- 本次不引入删除、归档期限或数据迁移。

## 失败处理

- Worker 404：保持“预跑暂不可用”，不伪装为空池。
- Worker 403/网络失败：不覆盖正式候选区域。
- 到期快照字段不完整或三池不合法：继续 fail closed，不展示候选。
- 快照 hash 与盘后复核不一致：隐藏复核差异，不拼接不同快照。
- 前端计时器到点只切换为封存视图，不修改或删除快照对象。

## 测试与验收

1. Python 公共合同测试证明到期状态仍为 `expired`，三池保留且正式字段不变。
2. Worker 测试证明到期 GET 保留白名单候选、无内部字段、`no-store`、正确 CORS，恶意 Origin 仍为 403。
3. 前端合同测试证明到期卡默认折叠、摘要计数正确、展开内容只读、没有按钮或执行控件。
4. 活跃期、到期边界和页面刷新后均保持同一 `snapshot_id/content_hash`。
5. 正式数据库、账本、日报、scorecard、comparison index 和 Top10 Worker 非回归。
6. 生产发布后，用真实线上页面检查 1440×900、1366×768、390px：默认折叠、展开无横向溢出、统一空态和盘后复核可读。
7. Cloudflare 只做普通 Worker 版本发布，无 migration；回退采用向前部署上一公开投影逻辑，不能承诺 Durable Object 生命周期变化后的简单回滚。

## 完成定义

只有代码、测试、Git、Pages、Worker 生产回读和真实线上三视口截图全部通过，且 14:57 后动作仍被禁止，才可认为“封存回看”上线。该变更不替代完整 goal 中真实微信到达和其余生产验收门槛。
