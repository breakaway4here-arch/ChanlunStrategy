# 行情单库与强股召回优化整体设计

**状态：** 已确认，作为后续实施基线
**确认日期：** 2026-07-15
**适用范围：** `ChanlunStrategy` 日报、ongoing 行情读取、候选召回、决策展示与历史回测

## 1. 目标

本设计同时解决四类问题：

1. 修复错误决策、错误分页和非正式收盘数据发布。
2. 建立 ongoing 与回测共用的本地行情事实源。
3. 把候选入口从 Top20 板块并集扩大为“全 A 基础池 + 热板块增强”。
4. 将低位、趋势延续和观察名单分流，并用严格 `as_of` 的样本外回放决定阈值。

本设计不以“多推股票”为目标。召回扩大后，主推荐仍须经过结构、位置、量价、30 分钟确认、市场环境和风险准入；观察名单只承接可恢复的近失样本。

## 2. 证据基线

### 2.1 7 月 13 日强股漏票

对 `2026-07-13 Top20 <- 2026-07-10` 的真实行情审计显示：

| 首个失败位置 | Top20 数量 |
| --- | ---: |
| 不在 Top20 板块并集 | 9 |
| 板块成分页截断 | 5 |
| 日线信号或强启动门 | 4 |
| 30 分钟升级门 | 2 |

也就是说，14/20 在日线分析前已经消失。首先需要修入口和分页，而不是只调最终排序。

### 2.2 “全部高位风险”不是市场结论

当前决策引擎在位置距离缺失时扣分，并以 `position_score < -10` 输出“不推荐（高位风险）”。缺失数据因此被错误翻译为已确认高位。

同时，报告序列化阶段才可能计算的“距参考买点”并不是股票绝对位置。未经校准把该字段直接喂回决策，会把错误从“几乎全部拒绝”反转成“几乎全部推荐”。

### 2.3 本地数据容量

基于现有 3150 只股票、251975 根 30 分钟 K 线实测：

| 数据范围 | 估算落盘量 |
| --- | ---: |
| 全 A 5537 只 x 500 根，原始 JSON | 约 314 MB |
| 每股 gzip JSON | 约 54 MB |
| 紧凑 SQLite，股票与日期双索引 | 约 137 MB |
| 每年新增约 1107 万根 30 分钟线 | 约 547 MB/年 |

数据规模不是阻碍。更重要的是增量、去重、复权口径、正式收盘状态和 `as_of` 防未来数据。

## 3. 文档优先级与继承关系

本设计是整合规范，不复制已有信号算法。优先级如下：

1. 本设计：行情事实源、上游召回、通道分流、观察视图、统一验收。
2. `2026-06-30-chanlun-data-contract-quality-v1.md`：数据质量、manifest、fail-closed。
3. `2026-06-30-report-workspace-field-contract-fix.md`：workspace 字段和展示契约。
4. `2026-06-29-fusion-recommendation-optimization-roadmap.md`：A/B/C、质量层级、期限、排序和解释。
5. `2026-05-26-chanlun-candidate-coverage-optimization-spec.md`：低位 swing seed 与 30 分钟升级。
6. `2026-05-26-chanlun-strong-startup-candidate-spec.md`：低位强势启动与涨停观察。
7. `2026-05-26-chanlun-multilevel-candidate-upgrade-spec.md`：基础信号层级和升级语义。

### 3.1 继续继承

- 交易日窗口、增量重叠抓取、按时间去重、新数据覆盖旧数据。
- 正式报告不静默接受 stale/fallback 数据。
- `formal/candidate/reference/seed/watch/blocked` 信号层级。
- raw reference/seed 不得直接推荐，blocked 不得升级。
- 日线种子 -> 30 分钟确认 -> candidate 的多级别升级顺序。
- 涨停只观察、不当日追；观察项必须有升级和取消条件。
- `fusion_strict_startup_rescue_v1` 继续作为生产基线，实验不得自动修改生产入口。
- recommendation score 只排序，不替代执行准入。

### 3.2 本设计明确取代

- JSON 作为长期最终行情存储。
- 30 分钟数据只物理保留 10 个交易日。
- ongoing 在本地数据完整时仍无条件请求远端尾部数据。
- 仅使用 `picks_fusion` 幸存样本评估 3%、12%、量比和 MA 门。
- Feature Layer 只能在已有 pool 之后工作。
- 静态 feature 权重和简单同池 A/B 验收。
- `decision_engine_v1` 中“距离缺失按 999 处理”和“位置扣分即高位风险”的语义。

展示用 `distance_from_reference_pct` 不自动升级为绝对位置特征。距离决策在校准完成前保持关闭。

## 4. 总体架构

```text
远端行情源
  -> 增量抓取、完整性校验
  -> 20 逻辑分片暂存 / ongoing 单写队列
  -> market_history.sqlite
       -> ongoing：DB 优先，缺失或过期才补齐
       -> backtest：冻结快照，只读 as_of，禁止联网

ongoing
  -> 全 A 低成本日线特征
  -> 基础 800 + 热板块 overlay <= 400
  -> 一次日线分析
  -> low_position + trend_continuation 两类种子
  -> 去重后的 30 分钟目标 <= 450
  -> pure/fusion/A-B-C 下游准入
  -> main + observation_top5 + reject/data_unknown
```

## 5. P0 正确性修复

### 5.1 区分位置缺失与高位风险

- 距离缺失、无效、`NaN`、`Inf`：输出“暂不判断（位置信息不足）”，`decision_code=observe`。
- 只有存在明确、已校准的位置特征时才能输出“不推荐（高位风险）”。
- 真实显式高位样本继续拒绝。
- 不自动以 `best_buy_point.price + closes[-1]` 推导绝对位置并触发推荐。
- 若安全开关关闭，隐藏决策摘要，不能回退到旧错误标签。

### 5.2 正式收盘发布门

在既有 `data_quality` 上增加或收紧：

- `generated_at`
- `as_of`
- `bar_state = intraday | closed`
- `is_official` 必须包含 `bar_state=closed`

14:35 等盘中结果只能作为预览；收盘任务必须刷新。生成后、Git 提交或推送前再次运行 validator。

### 5.3 板块分页

- 页大小使用 100。
- 依据接口 `total` 与累计唯一代码数判断结束。
- `seen_codes` 去重。
- 本页无新增时停止并记录异常。
- 使用稳定代码字段排序，避免盘中涨幅变化造成跨页漂移。
- 分页未完整时标记 `stock_pool_incomplete=true`，正式报告 fail-closed。

### 5.4 决策、操作与 Top10 一致

- `decision_code=reject` 时操作最多“仅观察”，不能“可上车”。
- `observe` 或数据不足时不能包装成推荐。
- Top10 以 workspace 为事实源，不另建重排和 fallback 语义。
- 看点、异动与可执行推荐在名称和数据结构上分开。
- 保留 workspace 既有字段解析优先级，禁止新增第三套距离字段。

## 6. 统一行情事实源

### 6.1 数据库

一个可配置路径的 `market_history.sqlite`，同库分表：

- `instruments`
- `stock_meta_asof`
- `trade_calendar`
- `bars_day`
- `bars_30m`
- `bars_15m`
- `ingest_runs`
- `shard_manifests`

K 线表使用 `(instrument_id, ts)` 主键；记录 OHLCV、数据源批次、复权口径和 `is_final`。按 `(ts, instrument_id)` 增加横截面索引。

### 6.2 首期回填

- day：全 A。
- 30m：全 A，每只最多回填 500 根。
- 15m：仅对罗姐池、主池、观察池及实际需要股票按需保存。

新股、停牌导致不足 500 根必须有结构化原因，不能被当成普通抓取失败。

### 6.3 ongoing 读取

统一 `KLineRepository` 对上层保留当前调用形状：

1. 根据 `period/code/count/required_date/as_of` 查询数据库。
2. 日期、根数、`is_final` 满足要求时直接返回。
3. 缺失、过期或未最终收盘时，拉取 1-2 个交易日重叠窗口。
4. 通过单写队列批量 UPSERT。
5. 重新查询并返回，同时携带 verified/stale/missing 状态。

运行内可以增加小型内存缓存，但不再保留第二套长期文件事实源。

### 6.4 backtest 读取

- 补齐后生成版本化 SQLite 快照和 hash。
- 以只读模式打开，所有查询强制 `ts <= as_of`。
- 缺数据时标记不可评估，禁止自动联网。
- 相同数据库 hash、配置 hash 和代码版本必须产生相同结果。

### 6.5 迁移

旧 JSON 在影子阶段仅用于数值对比：

1. SQLite 与 JSON 同输入输出比较。
2. 覆盖率、数值、状态和日报结果通过验收。
3. ongoing 切换 SQLite 为唯一事实源。
4. 下线 30 分钟 JSON 读写；不长期双写。

## 7. 全 A 召回层

### 7.1 合格全 A

以历史时点可知的信息过滤：

- 非 ST、非退市整理、非上市不足 60 个交易日。
- 日线窗口满足最低分析要求。
- 流动性达到既有最低成交额门。
- 股票状态来自 `stock_meta_asof`，不能用当前名称快照替代历史状态。

### 7.2 基础 800

仅使用低成本日线特征，不跑缠论和 30 分钟：

- 低位预筛 Top350：位置、缩量回踩、量价启动、流动性。
- 趋势预筛 Top350：20 日突破、MA 保持、相对强度、量价持续。
- 中性兜底 Top100：高流动性、结构完整。

三池去重后不足 800，按 `max(low_position_retrieval_score, trend_retrieval_score)` 顺延补足。

`retrieval_score` 只负责召回，不表示可买；它与下游 `recommendation_score` 必须分开。

### 7.3 热板块 overlay

完成分页后，Top20 资金板块最多新增 400 只：

- 板块 1-5：每板块最多 30 只。
- 板块 6-10：每板块最多 20 只。
- 板块 11-20：每板块最多 15 只。
- 每个板块按低位分和趋势分各取一半。
- 上下级重复板块和重复股票去重。

最终池硬范围为 800-1200。若超出，保留基础 800，再裁剪 overlay；不能反向删除基础池。

## 8. 信号与展示分流

以下字段相互正交：

```text
source_channel = low_position | trend_continuation
tier           = formal | candidate | reference | seed | watch | blocked
category       = A | B | C
quality_tier   = A+ | A | A-
view           = main | observation
```

### 8.1 低位通道

继续复用既有 formal 买点、swing seed、低位强势启动和 30 分钟升级规则。3% 与 12% 只代表低位策略的风险偏好，不跨用到趋势通道。

生产初始值：

- 30 分钟升级距离暂留 3%。
- 追高保护暂留 12%。
- 强启动量比暂留 1.5。

### 8.2 趋势延续通道

新增独立 `trend_continuation`，不修改旧低位强启动语义：

- 20 日平台突破、站稳 MA5/MA10，或离开中枢后回拉保持强势。
- 参考位使用突破线、平台上沿、MA10 或当前有效向上破坏点。
- 30 分钟确认看突破位不破、EMA 保持和缩量回踩。
- 不使用旧底背驰源价计算 3%/12%。
- 量比可条件化降到 1.3，但必须有更强趋势结构或 30 分钟确认。
- 涨停、显著跳空、远离突破位或加速末端只进入观察。

### 8.3 观察 Top5

后端完整保留 watch 和 first-failure 记录，前端派生 `workspace.views.observation_top5`。Top5 不是新买点类型，也不计入主推荐胜率。

可进入观察的近失样本：

- 量比在 1.2-1.5，但结构完整。
- MA 轻微不满足。
- 低位或趋势通道只缺一个 30 分钟确认。
- 旧源价距离失败，但趋势参考位仍健康。
- 当日过度延伸，等待回踩。

限制：

- 总数最多 5。
- 同行业最多 2。
- 同一失败原因最多 2。
- 每只显示失败门、实际数值、升级条件和取消条件。
- 不单独全量推送；只有升级主池或重大风险变化时提示。

## 9. 决策数据模型

兼容保留三种 `decision_code`：

- `recommend`
- `observe`
- `reject`

增加细粒度 `reason_code`，至少覆盖：

- `missing_position`
- `stale_data`
- `high_position`
- `structure_broken`
- `overextended`
- `waiting_30m_confirm`
- `ma_near_miss`

位置信息不足属于 observe；明确高位、结构破坏和无法执行的风险属于 reject；只有通过主池准入的 recommend 可以显示可执行动作。

## 10. 门前漏斗与实验数据

每天记录全量门前特征，而不是只保存幸存推荐：

```text
全 A 覆盖
-> 合格股票
-> 基础 800
-> overlay 增量
-> 最终 800-1200
-> 日线低位/趋势种子
-> 30 分钟目标
-> 低位/趋势升级
-> fusion/A-B-C
-> main/observation/highlights
```

`gate_events` 至少保存：

- run/date/code/source_channel
- retrieval source 与分数
- 首个失败门
- 3%/12% 相关原始距离
- 成交量比和成交额比分列
- MA 间距和方向
- 30 分钟确认及强度
- 决策、原因、数据质量

## 11. 三日复盘和样本外回放

### 11.1 三日工程验证

固定三组，不逐日调参：

- `2026-07-13 Top <- 2026-07-10 signals`
- `2026-07-14 Top <- 2026-07-13 signals`
- `2026-07-15 Top <- 2026-07-14 signals`

每组只使用 T 日 15:00 前正式数据。三日只验证分页、召回架构、趋势增量和观察池价值，不确定最终阈值。

### 11.2 20 日 walk-forward

500 根 30 分钟线约覆盖 62 个交易日：

- 前约 30 日：滚动开发和选参。
- 中间 3 日：T+3 标签隔离。
- 最后 20 日：5 个连续 4 日样本外测试块。
- 每块只能使用此前已形成完整标签的数据。
- 2026-07-13 至 2026-07-15 在完整 T+3 标签形成前只参与召回审计。

扫描范围：

- 低位距离：2、2.5、3、3.5、4、5、6%。
- 追高保护：8、10、12、14、16、20%。
- 量比：1.2、1.3、1.4、1.5、1.6、1.8、2.0。
- MA：严格多头；最弱间距 > -0.25% 且 EMA5 向上；最弱间距 > -0.5% 且站上 EMA10；仅排序扣分。

先做单因子扫描，再组合每门表现最好的两个相邻档位，避免全笛卡尔积过拟合。

## 12. 指标与验收

### 12.1 数据硬门

- 合格全 A 覆盖率 >= 98%。
- 重复主键和非法 OHLC 为 0。
- backtest 网络请求为 0。
- `ts > as_of` 结果为 0。
- 相同快照、配置和代码版本可重复。

### 12.2 召回目标

| 指标 | 最低线 | 绿色目标 |
| --- | ---: | ---: |
| 最终池 Top20 三组平均召回 | 60% | 70% |
| 最终池 Top30 三组平均召回 | 55% | 65% |
| 低位 + 趋势 + 观察 Top20 召回 | 30% | 35% |
| 观察数量 | 每日 <= 5 | P95 <= 5 |

### 12.3 风险与稳定性

- T+3 跌幅 <= -5% 比例不得比基线恶化超过 2 个百分点。
- 收益中位数不得明显下降。
- 5 折至少 4 折选择同一或相邻阈值。
- bootstrap 95% 置信区间不能显示明显负收益。
- 低位主通道不能靠扩大数量牺牲原有尾部风险。
- 观察池不计入主推荐胜率。

## 13. 并行执行

全 A 按稳定排序后的 `codes[i::20]` 分成 S00-S19：

- 当前最多 3 个 Spark 同时运行，分别处理 7、7、6 个逻辑分片。
- 每个 Spark 内使用 6-8 个 HTTP 线程，总请求并发约 18-24。
- 首次回填每个逻辑分片写独立 staging SQLite 和 manifest。
- 主控逐个 `ATTACH`，单写事务合并正式库。
- ongoing 使用读连接池 + 单写队列，不允许多个线程直接争写正式 SQLite。

首次全量数据、校验、回放和参数扫描预计在 API 稳定时 20-40 分钟；限流时允许延长，但不得降低覆盖率或绕过校验。

## 14. 发布与回滚

实施顺序：

1. 冻结当前行为和三日基线。
2. 修复决策、正式收盘、分页和 Top10 语义。
3. 建 SQLite、回填工具和 `as_of` 只读接口。
4. JSON/SQLite 影子对比，通过后切换单库。
5. 上线全 A 召回、热板块 overlay 和漏斗，但不改变正式推送。
6. 上线趋势和 Top5 观察的 shadow 视图。
7. 完成三日复盘和 20 日 walk-forward。
8. 按样本外结论固化阈值。
9. 新旧策略并行至少 3 个交易日，再切换正式推送。

模块分别受开关控制，可退回旧股票池或关闭新通道。P0 错误语义不能回滚；新决策不可用时应隐藏，而不是恢复“缺失即高位”。

## 15. 非目标

- 不修改缠论核心走势、笔、线段、中枢算法。
- 不一次性全 A 回填 15 分钟数据。
- 不以三日样本确定最终阈值。
- 不使用 LLM 替代可复现的行情抓取、门前记录和回测计算。
- 不让实验结果自动修改生产配置。
- 不在本设计阶段修改任何生产代码。
