# 辅助决策驾驶舱上线后审计与选股优化方案

> 日期：2026-08-22
> 状态：影子评测已上线；本文件记录上线后审计结论、修复边界与分阶段落地方案。
> 总目标：在不降低、不改写现有正式选股输出的前提下，提高方向判断的准确性、风险解释的可追溯性和策略收益研究的可信度。

## 1. 已确认的产品边界

1. `picks_pure` 是所有策略可使用的共同上游全集，含义是“原始缠论结构候选”。
2. `picks_pure` 不是统一筛选器。H4、次日爆发、罗姐等策略仍保留各自独立的条件、排序、模型和策略池，不能强行统一逻辑。
3. 当前正式选股不得因为本轮研究被直接替换。新上游、新权重和新排序必须先走影子评测，只有在样本充分且收益、回撤和稳定性达标后，才讨论晋级。
4. 研究入场价格统一使用信号日收盘价；T+1、T+3、T+5 使用对应交易日收盘价，同时记录各窗口内盘中最高收益 MFE 和最低收益 MAE。
5. 目标是高收益研究，不对候选输出设置任意数量上限。为了页面可读性允许默认折叠，但不得因展示截断而丢失研究样本。
6. `stock_links` 是“与方向相关的个股证据”，不是选股池，也不要求全部属于 `picks_pure`。
7. 实际下单与成交模拟不在本轮范围内。

## 3. 问题严重性与根因

### P0：影子合同与真实调用链不一致

当前正式 H4 使用 `picks_fusion`，但影子合同标注 `upstream_pool=picks_pure`，实际影子结果又只是复制正式 H4 池。这样得到的评测并不能回答“从 `picks_pure` 共同上游出发是否更优”。

修复原则：

- 保持正式 H4 输入和正式结果不变。
- 影子 H4 必须从 `picks_pure` 重新运行同一版 H4 策略。
- 正式结果明确标注 `upstream_pool=picks_fusion`；影子结果明确标注 `upstream_pool=picks_pure`。
- 增加集合包含关系和来源计数测试，禁止再次出现“标签是 pure，数据却来自 fusion”。
- 次日爆发和罗姐池暂不盲目迁移；分别建立版本化影子变体后再比较。

### P0：混合收评被整篇判成负向

事件先被归入单一 `event_category=risk`，随后所有关联主题被强制设为 `negative`。2026-08-21 收评明确同时包含 CPO 正向、创新药负向，却导致 AI 算力、光模块也显示“风险成立”。

最优修复：

- 收评、午评等混合 recap 必须按 `positive_sectors` / `negative_sectors` 逐主题判向。
- recap 中未命中主题级正负证据的方向返回 `neutral`，不能继承整篇 risk。
- 只有减持、立案、退市等非 recap 硬风险事件，才允许事件类别兜底为 `negative`。
- 英文缩写 `AI/AR/VR/MR/CPO/GPU/HBM` 使用单词边界与上下文匹配，避免公司英文名子串误命中主题。
- 资金、涨停和置信度必须按主题计算，禁止一个主题的强证据给其他主题加分。

### P0：风险条件语义倒置

当前负向方向把“风险减弱、结构止跌”写为下一确认，把“风险继续扩散”写为失效条件，页面展示后会直接反向引导人工决策。

最优修复：

- `confirmation_conditions` / 兼容字段 `next_trigger`：风险扩散、资金转负、结构破坏。
- `invalidation_conditions` / 兼容字段 `invalidation`：风险减弱、资金回流、结构止跌。
- 负向页面标签显示“风险升级条件 / 风险解除条件”；正向继续显示“下一确认 / 失效条件”。
- 条件由确定性规则拥有，LLM 只解释摘要，不得覆盖条件语义。

### P1：没有独立、具体的风险原因

风险信息目前散落在摘要、事件、证据链和条件文本中，没有独立的 `risk_reasons` 合同，因此用户看到“风险成立”时仍要自己推断原因。

新增合同：

```json
{
  "risk_reasons": [
    {
      "reason_code": "negative_stock",
      "title": "关联个股出现明确负面事件",
      "detail": "事实、影响路径和涉及对象",
      "severity": "high",
      "verification_status": "verified",
      "source_type": "event",
      "evidence_refs": ["event:example"],
      "affected_codes": ["688223"]
    }
  ]
}
```

硬约束：

- 正向方向固定 `risk_reasons=[]`。
- 负向方向没有非空、可追溯的风险原因时，不得显示“风险成立”，只能显示“风险待核验”。
- 原因由确定性代码从负向板块、负向个股、硬风险事件中提取；LLM 不得自由补充事实。
- 每个 `evidence_ref` 必须属于当前方向的证据链。

### P1：收益评分口径可能混算

正式账本的历史记录主要是 `delay1_open`，新影子研究是 `immediate_close`；当前策略记分牌仅按策略名与版本分组，既不展示入场口径，也可能把不同周期混在一起。

修复原则：

- 评分身份至少包含 `(strategy, strategy_version, entry_mode, intended_horizon)`。
- 页面明确显示“入场=T+1 开盘”“入场=信号日收盘”或“入场口径未知”。
- 历史 `legacy_unknown` 保留但不参加版本优劣结论；新研究从下一 cohort 起明确版本和收盘价口径。

### P1：诊断、状态与标签会造成误解

- 数据诊断只要有键就显示“正常”，即使快照内存在 warning。
- `picks_fusion=79` 被影子卡称为“正式主推”，但页面真正主推只有 4 只。
- 持仓风险数组为空时整卡消失，无法区分未配置、空仓、无风险或隐私隐藏。
- `candidate_intersection` 被错误兜底为“事件点名”。
- 关注池“股票名称”输入框实际保存的是备注。
- 涨停生态只显示前 5 项，却未说明总数。

以上都属于展示语义修复，不改变任何策略候选和排序。

### P1：正式决策“不推荐”却没有原因

部分正式选股详情同时显示“不推荐”和“暂无标记风险标签”。这是决策原因与风险原因未分层造成的矛盾。

后续应拆分：

- `decision_reasons`：低分、门槛未通过、结构未确认等“不推荐原因”。
- `risk_reasons`：高位、破坏点、数据异常等真实风险。
- 页面在 reject 且原因未结构化时，至少显示“拒绝原因未结构化”，不能显示成“没有风险”。

### P2：可后续处理

- 临时 Top10 当日未运行时接口返回 404，页面实际已按“未运行”处理；它不影响辅助决策驾驶舱。
- 证据注册表需要补齐 `source`、事件时间和 `evidence_as_of`，避免生成时间与晚到证据时间线倒置。
- 数据质量字段需区分正式 active pool 与全量 retrieval universe，避免 count 与 code list 作用域不一致。
- 今日方向默认 Top3 的策略会让风险占满页面；后续改为“最佳正向 + 最强风险 + 综合第三条”，并允许展开全部，但不得截断研究数据。

## 4. 分阶段落地

### 阶段 A：立即修复，不改正式选股结果

1. 修复混合收评逐主题判向、风险条件语义与独立 `risk_reasons`。
2. 修复 H4 影子评测，使其真实从 `picks_pure` 重新计算；正式 H4 保持原样。
3. 修复变量与页面标签、诊断状态、入场口径、持仓状态、关联个股角色和截断提示。
4. 用冻结的 2026-08-21 报告做回归；预期方向为“光伏风险、创新药风险、半导体正向”，不再把 AI 算力和光模块误报为风险。
5. 全量测试、独立规格/质量复核、重新发布并核验远端原始 JSON 与桌面/移动页面。

### 阶段 B：策略逐一建立 `picks_pure` 影子变体

| 策略 | 正式池现状 | 影子方案 | 晋级前置条件 |
|---|---|---|---|
| H4 T+3 | `picks_fusion` | 已先行建立 `picks_pure` 上游变体 | 样本、T+3 收益、MFE/MAE、尾部风险均达标 |
| 次日爆发 | `picks_fusion + startup_watchlist`，且有 Top5 | 新建无任意数量截断的版本化变体 | 明确版本、移除研究样本硬截断、T+1/T+3 对照 |
| 罗姐池 | 全市场 15 分钟预处理 | 先定义 pure 上游所需的等价特征与覆盖率 | 不损失策略所需 15 分钟特征，且收益优于原版 |

各策略分别评测、分别晋级；共同上游不等于共同逻辑。

### 阶段 C：高收益优化

1. 对每个策略版本记录 T+1/T+3/T+5 收盘收益、窗口内 MFE/MAE、胜率、盈亏比、尾部亏损与样本覆盖率。
2. 先判断“候选覆盖是否提高”，再判断“排序是否提高”，避免把来源改善与打分改善混为一谈。
3. 只在正式输出保护通过、样本量达到预设门槛、收益提升不是由少数极端值贡献时提出晋级。
4. 晋级仍需人工确认；影子系统不自动改写正式策略。

## 5. 当前不确定项及处理方式

1. 次日爆发的 Top5 是产品展示限制还是策略硬约束：本轮不猜测、不删除；先在影子变体中保留全量研究样本，再对比 Top5 的边际收益。
2. 罗姐策略是否允许只在 `picks_pure` 上计算 15 分钟特征：需要先验证覆盖率与漏掉的高收益样本，不能直接迁移。
3. 今日方向是否永久限制三条：本轮先保证判向正确和风险原因完整；展开全部的交互单独验收。
4. 历史正式账本没有明确策略版本：保留为 `legacy_unknown`，不追溯伪造版本。

## 6. 验收标准

- 正式选股保护摘要在影子计算前后完全一致。
- 影子 H4 结果有真实 `picks_pure` 来源证明，且候选代码全部属于当日 `picks_pure`。
- 2026-08-21 混合收评不再把 AI 算力、光模块误判为风险；负向方向必须有具体风险原因。
- 风险升级/解除条件在数据合同与页面标签中语义一致。
- 不同入场口径、周期和版本不混算。
- 数据告警不能显示为“正常”；持仓空状态不能无声消失。
- 全量自动化测试通过，远端 `main`、Pages 原始 JSON、桌面与移动页面均完成验收。
