## 1. 文档状态

- 日期：2026-08-27
- 状态：设计方向已确认，等待单独实施授权
- 范围：桌面端优先，390px 仅要求不退化；市场情绪增加 PSY12 影子权重评测；增加 14:47 预收盘三池预跑、简洁推送和盘后差异提醒
- 目标页面：ChanlunStrategy 日报主页面与个股详情工作台
- 版本边界：上述能力作为同一版综合优化交付，不拆成相互独立的产品版本
- 非授权事项：本文不授权修改盘后正式选股算法、正式推荐门槛、策略池身份或现有正式市场情绪分；预跑只能作为独立的盘中建议链路

## 2. 背景与结论

当前页面并不是“数据太少”，而是信息层级错误：

1. 页头同时承担报告标题、市场摘要、指数卡和临时 Top10 操作。
2. 候选区有九个并列视图，用户难以区分主推、待确认、观察与研究池。
3. 个股详情依次展示结论、价格、图表、决策、理由、风险、细节，多个区块重复回答同一个问题。
4. 辅助决策区一次铺开市场情绪、板块资金、今日方向、重点观察、涨停生态、持仓风险、策略记分牌、影子评测和数据诊断，造成长页面、同权卡片和大面积空白。
5. 图表把历史信号、现价、参考价和动作标签同时放入有限空间，桌面端最右侧出现严重叠压。
6. 现有市场情绪由当日广度、涨跌停生态、指数、成交额和趋势构成，能够描述当日状态，但缺少最近 12 个交易日上涨持续性的独立证据。
7. 现有完整日报要等收盘终局数据，还包含新闻、LLM、研究材料、完整页面生成和 Git 发布，无法承担 14:47 启动、14:49 前输出的盘中交易时效。
8. 预跑结果与盘后正式结果目前没有同口径对照，用户无法主动获知哪些股票被正式保留、新增或移出。

本次选择“渐进式决策工作台”，不继续增加卡片，也不做全量多页面重构。默认页只回答：

```text
今天市场主线是什么
→ 当前候选里哪只值得看
→ 这只股票唯一正式动作是什么
→ 为什么
→ 下一步等什么
→ 什么情况说明判断失效
```

研究、实验、影子和诊断信息迁移到二级视图，不再与今日动作同权展示。

同一版本额外提供一条 14:47 预收盘建议链路，只计算主推池、H4 T+3 和加速池，并在盘后正式结果生成后主动推送差异。该链路与正式日报共享经过测试的纯策略模块，但不共享可写数据、锁、产物、账本或发布状态。

## 3. 参考页面的借鉴边界

参考页面只用于截图级视觉分析，不采用其源码、接口或不可验证指标。

### 3.1 借鉴

1. 策略/证据通过切换逐层展开，而不是同时覆盖在图上。
2. 当前动作、周期状态、仓位和关键价格形成短决策链。
3. 热门板块以紧凑标签展示，点击后直接筛选股票列表。
4. 策略比较使用统一指标列，用户可以快速识别差异。

### 3.2 不借鉴

1. “有庄控盘”等不可验证标签。
2. 主升浪视图中大量 `J`、`B`、`4高`、`7低`、`11变` 等永久文字标注。
3. 综合结论与单策略仓位相互冲突却没有仲裁关系。
4. 小样本累计收益排行榜和“采纳推荐”按钮。
5. AI 产生第二套正式动作或仓位建议。

## 5. 一级信息架构

1. `今日决策`：默认页，面向当日筛选、个股动作与条件确认。

`研究验证` 的页面顺序：

1. 正式策略状态
2. 同口径策略比较
3. 影子评测
4. 数据诊断与版本详情

## 8. 资金主线与热门板块

### 8.1 P0：资金主线

现有 `sector_flow` 只覆盖资金流入/流出榜，不代表完整市场板块涨幅排名，因此 P0 必须命名为“资金主线”，不能直接称为“热门板块”。

每个标签最多展示：

- 板块名称
- 当日涨跌幅（仅在现有事实中已提供时显示）
- 净流入额
- 当前候选池命中数量

默认 Top5，并提供“全部”清除筛选。

筛选规则：

1. 点击板块只过滤当前候选池。
2. 顶部显示当前过滤条件和结果数，例如 `主推 · 工业金属 · 2/4`。
3. 同一标签再次点击或点击“全部”清除筛选。
4. 非空结果自动选择过滤后的第一只股票。
5. 空结果显示明确空态，不自动切换到其他候选池。
6. 筛选不能改变股票池身份、正式动作或排序字段。
7. P0 仅允许标准化后的精确板块名称匹配，不做模糊字符串猜测。

### 8.2 P1：热门板块

P1 新增完整 `sector_heat` 后，界面才可以命名为“热门板块”。

```json
{
  "sector_code": "BK0000",
  "sector_name": "工业金属",
  "change_pct": 3.21,
  "rank": 1,
  "up_count": 42,
  "total_count": 51,
  "limit_up_count": 6,
  "as_of": "2026-08-27T15:10:00+08:00",
  "source": "...",
  "status": "verified_complete"
}
```

涨幅、资金、涨停数分别展示，不合成一个难以解释的“热度总分”。

## 9. 候选导航与列表

一级候选导航调整为：

- `主推`
- `待确认`
- `观察`
- `研究池 ▾`

研究池继续保留各池独立名称和身份，例如：

- 基础候选
- H4 T+3
- 次日爆发
- 罗姐池
- 高弹性观察
- 加速

不再使用“看点”和含义不清的“更多”。研究池不得合并为一套统一策略语义。

候选行只显示：

- 小序号
- 名称、代码
- 当日涨跌幅
- 唯一正式动作
- 已验证的主要周期
- 一行主要理由或风险数量

每行最多两个标签。来源、共振、动作、风险和评分不能全部并列常驻。

### 9.1 主推荐区统一空态

当本期主推荐池为空时，今日决策页统一显示：

```text
本期未选出推荐票
```

以下内部状态都映射为同一条用户文案：

- 本期按正式规则正常得到空池。
- 推荐依赖数据不可用，正式流程按 fail-close 不输出推荐。
- 正式动作已封闭，候选不能升级为推荐。

展示边界：

1. 今日决策页不得出现“数据不可用”“正式动作已封闭”“校验失败”“fail-close”等内部校验术语。
2. 不得把内部 `status`、`reason_code`、异常信息放入空态正文、悬浮提示、`title` 或无障碍文本。
3. 底层 JSON 继续保留真实状态和原因；研究验证页与数据诊断可按权限展示，用于排障和审计。
4. 板块筛选后的零命中仍显示当前筛选条件和零结果，不伪装为全局无推荐。
5. 整份报告加载失败属于页面级故障，必须显示加载失败或重试入口，不能伪装成“本期未选出推荐票”。
6. 空态不得触发从待确认、观察或研究池回填推荐票。

## 11. 个股详情合并

当前 `01结论 / 02价格 / 03图表 / 04决策 / 05理由 / 06风险 / 07细节` 调整为：

1. 决策头：身份、动作、价格和已验证周期。
2. K 线工作区。
3. 图下三栏：为什么、下一确认、失效条件。
4. 证据与审计抽屉：来源、评分、策略版本、信号日期、内部字段和完整风险原因。

三栏数量限制：

- 为什么：最多 3 条。
- 下一确认：最多 2 条。
- 失效条件：最多 2 条。

风险具体原因不能删除，只能从重复区块合并到上述三栏或审计抽屉。

## 12. 图表设计与碰撞治理

### 12.1 工具栏

只有真实数据存在时才显示相应入口：

- 周期：日 / 周 / 60 分钟。
- 图层：决策位 / 结构 / 趋势。
- 历史信号开关。

图层互斥，不允许把全部策略和历史标注同时画在主图上。

### 12.2 右侧标签车道

右侧留白使用：

```css
clamp(96px, 12%, 144px)
```

治理规则：

1. 常驻价标优先级：失效位 > 现价 > 参考价 > 压力位。
2. 最多两个常驻价标，其他价位只画细线，具体数值放入图上方价格条。
3. 两个标签纵向距离小于 24px 或价格差小于 0.6% 时合并。
4. 只允许一个最新动作文字标记；历史信号只显示小点，悬停后显示详情。
5. 可视区每 40 根 K 线最多三个带文字标注。
6. 最后五根 K 线不得被标签覆盖；标签进入右侧车道，并以引线连接真实价格。
7. 价格线不能为避让而改变 y 值，只允许移动标签。
8. 当前价、参考价和信号来自不同日期时必须显示日期。

## 13. 正式动作、策略分歧与 AI

页面只有一个正式动作，来源于正式融合策略合同。

其他策略只显示相对正式动作的立场：

- 支持
- 保留
- 反对
- 样本不足

首屏分歧摘要示例：

```text
正式动作：观察
策略分歧：2 支持 / 1 反对
```

点击后才能查看各策略原因、周期和证据。各策略不得分别输出多个仓位区间。

AI 只能输出：

- 支持正式结论
- 风险提醒
- 证据不足

示例：

```text
正式结论：观察
AI证据：偏多，但确认条件未满足；不改变正式动作
```

AI 不得生成新的正式动作、仓位、目标价或“采纳推荐”按钮。

## 14. 策略比较与样本门

策略比较必须按以下身份隔离：

```text
strategy + version + source_pool
+ entry_mode + intended_horizon + research_tier
```

只有股票池、入场、周期、成本、基准和研究层级一致时才允许横向比较。

样本门：

- 不足 100 个成熟样本、20 个活跃交易日或 2 个非重叠自然月覆盖：只显示采集进度。
- 右删失样本不进入收益统计。
- 未过门时不得显示收益排行、累计收益或胜率结论。
- 成熟后以中位收益为主、均值为辅，同时展示样本数、区间、基准超额、最大回撤、MFE 和 MAE。
- 不提供无法解释的综合分；未来若引入，必须公开公式和版本。

## 16. 错误与降级状态

1. 板块数据缺失：隐藏板块条并显示“板块数据不足”，不能用空列表解释为无热点。
2. 板块数据过期：显示数据日期，不允许筛选后声称是当日主线。
3. 筛选零结果：明确显示当前池零命中，不自动换池。
4. 主推荐池为空：统一显示“本期未选出推荐票”，内部原因保留在研究验证和数据诊断，不得回退到最乐观的单策略动作。
5. 周期/仓位合同缺失：主页面省略对应字段，内部缺失原因只进入研究验证和数据诊断。
6. 策略样本不足：只显示成熟进度，不显示收益结论。
7. 图表数据不足：保留决策头与条件，图表显示明确空态。
8. AI 不可用：正式结论照常显示，AI 区标记“未采用”，不得影响动作。

## 17. PSY12 市场情绪影子优化

### 17.1 目标与边界

PSY12 用于补充最近 12 个交易日的上涨持续性，不替代当日广度，也不直接切换正式市场情绪分。第一阶段只生成影子结果：

- 现有 `market_sentiment.score`、`label`、`market_temperature` 和正式决策门控保持不变。
- 新增可审计的 PSY12 证据和 `shadow_score_with_psy12`。
- 影子字段只能进入“市场证据”或“研究验证”，不得冒充正式市场状态。
- 满足影子观察门后仍需单独评审、单独授权，禁止自动转正。

### 17.2 指标定义

统计窗口包含报告日及此前 11 个有效交易日。每日沿用市场情绪指数组件的同一组代表指数，以该日 `average_change_pct` 判断：

```text
上涨日：average_change_pct > 0
非上涨日：average_change_pct <= 0
PSY12 = 上涨日数量 / 12 × 100
```

约束：

1. 必须恰好取得 12 个按交易日升序、日期唯一且不晚于报告日的有效样本。
2. 0 涨幅计为非上涨日，不能按上涨日处理。
3. 少于 12 日、日期重复、顺序异常或任一日指数证据不可验证时，PSY12 状态为 `unavailable`。
4. PSY12 不可用时，`shadow_score_with_psy12` 同样为空；不得用 50 分补齐，也不得重新归一化剩余权重伪造影子结果。
5. 每次输出窗口起止日期、上涨日数、有效日数和逐日涨跌方向，保证历史复算不引用未来数据。

### 17.3 影子权重

| 组件 | 现有正式权重 | PSY12 影子权重 |
| --- | ---: | ---: |
| 当日广度 `breadth` | 30% | 25% |
| 涨跌停生态 `limit_ecology` | 30% | 30% |
| 指数 `index` | 15% | 10% |
| 成交额 `turnover` | 15% | 15% |
| 趋势 `trend` | 10% | 10% |
| `psy12` | 0% | 10% |

PSY12 与当日广度和指数存在信息重叠，因此分别从两者降低 5 个百分点；涨跌停生态、成交额和趋势权重保持不变。第一阶段不评估 15% 及以上权重，避免中短周期指标过度覆盖当日真实状态。

影子总分公式：

```text
shadow_score_with_psy12 =
  breadth × 0.25
  + limit_ecology × 0.30
  + index × 0.10
  + turnover × 0.15
  + trend × 0.10
  + psy12 × 0.10
```

### 17.5 影子观察门

连续积累至少 20 个可完整计算 PSY12 的交易日后，生成一次独立评审：

1. 20 日逐日复算一致率必须为 100%，无未来数据、重复日期或缺口补分。
2. 展示正式分与影子分的逐日差值、均值、最大绝对差和标签变化次数。
3. 单列影子分若转正式会造成的 `market_temperature` 或决策门控变化，逐日人工复核，不以收益或主观涨跌事后挑选权重。
4. 检查 PSY12 与 `breadth`、`index` 的相关性和重复计权；若高度重复，只保留展示证据或降低权重。
5. 影子观察通过也不得自动转正；正式切换需要新的设计确认、回归测试和发布授权。

## 18. 14:47 预收盘三池预跑与盘后差异提醒

### 18.1 产品定位

14:47 链路是“预收盘建议”，不是把现有盘后正式日报提前运行，也不冒充正式收盘推荐。它的目标是尽可能在 14:57 收盘集合竞价前给出一份可执行时间更充足的短清单，同时保证 15:05 之后的正式任务、正式结果和正式账本完全不受影响。

本能力与页面、空态和 PSY12 优化同属一版综合优化，但运行时必须保持两条独立链路：

```text
14:47 预跑链路
  → 盘中非终局行情
  → 主推池 / H4 T+3 / 加速池
  → 预跑快照与简洁提醒

15:05 盘后正式链路
  → 正式收盘终局行情
  → 现有完整策略与正式发布
  → 正式结果冻结

独立盘后复核器
  → 只读两份冻结结果
  → 计算差异
  → 主动发送复核提醒
```

### 18.2 预跑范围

14:47 只执行得到三个目标池和当前正式决策门控所必需的确定性步骤：

1. 读取历史日线和盘中行情，形成带 `as_of` 的当日日线临时快照。
2. 执行日线缠论分析、日线结构池、融合准入和现有统一评分。
3. 仅对日线初筛后的目标股票读取 30 分钟行情，沿用现有候选升级和强势启动确认规则。
4. 在预跑隔离对象中构建指数、上涨家数、涨停生态、成交额、趋势和板块等确定性市场输入，并沿用当前正式市场情绪组件权重；不读取新闻、LLM 或 PSY12 影子结果。
5. 为融合候选附加盘中只读行情形成的仓位/结构证据，调用当前纯函数 `chanlun.decision_engine.evaluate_stock()`；公开 `main` 只保留 `decision_engine_v1.decision_code == "recommend"` 的候选，保证预跑主推与页面正式主推的展示语义一致。
6. 从预跑 `picks_pure` 上游生成 H4 T+3，保持 H4 自身的生产模型、门槛和健康检查。
7. 从预跑主推和强势启动观察输入生成加速池，并读取其门槛所需的指数盘中涨跌幅；加速池仍是研究/观察建议，不得在推送中冒充正式主推动作。

明确跳过：

- 新闻搜索、公告解读、研报、LLM 和 AI 材料构建。
- 罗姐池及其 15 分钟行情。
- 等确认榜、观察 Top5、成长质量榜、Top10 编排和其他研究池。
- 完整日报 HTML/JSON 生成、策略记分牌、历史回看和影子 finalizer。
- Git fetch、commit、push 和 GitHub Pages 构建。
- iWencai skills 及任何不在三个池确定性输入合同内的外部研究调用。

预跑不得直接调用会向正式 `MarketHistoryStore` 写入涨跌停证据的 `_build_market_sentiment_history()`。允许复用其中的纯计算规则，但盘中市场证据必须来自独立快照，并只写预跑命名空间。

当前策略不读取 1 分钟线。预跑仍只读取日线和 30 分钟行情；不得为了补造 14:47 的 30 分钟柱而暗中引入 1 分钟聚合。若行情源能返回正在形成的 30 分钟柱，则将其原样标记为 `is_final=false`；若当前 30 分钟证据不可用，依赖该确认的候选必须 fail-close，正式日线买点仍按现有信号政策处理。

### 18.3 时间状态机

| 时间/状态 | 动作 | 硬约束 |
| --- | --- | --- |
| 14:47:00 | 获取盘中快照并启动三池预跑 | 单日只允许一个活动 run；不等待新闻或 LLM |
| 14:49:00 | 输出硬截止 | 到点未完成则对外只显示“本期未选出推荐票”，底层保留真实失败原因 |
| 输出后至 14:56:30 | 清单有效 | 页面与提醒使用同一 `snapshot_id` 和 `content_hash` |
| 14:56:30 | 自动失效 | 页面停止展示可执行动作；不得继续依据清单新增委托 |
| 14:57:00 后 | 禁止新增预跑动作 | 预跑快照仅保留审计用途 |
| 15:05 后 | 现有正式任务独立运行 | 不读取预跑数据库、缓存、锁、快照或环境状态 |
| 正式结果校验完成后 | 独立复核器计算并推送差异 | 复核失败不得改变正式任务退出码、结果或发布状态 |

预跑运行目标为 120 秒内完成。性能预算按阶段记录：行情快照、日线分析、30 分钟候选确认、三个池构建、发布与通知。任一阶段超过预算必须能从诊断中定位，但用户提醒不展示内部超时术语。

### 18.4 非终局行情语义

预跑快照必须显式声明：

- `mode=preclose_advisory`
- `as_of=实际行情水位时间`
- `bar_state=intraday`
- `is_final=false`
- `affects_formal=false`
- `expires_at=当日 14:56:30+08:00`

不得把 14:47 的盘中日线或正在形成的 30 分钟柱写成正式 `verified/final`，不得复用盘后 `daily-*-close-v1` 的正式策略版本名。预跑策略版本独立使用 `preclose-1447-v1`，以便盘后对照和后续胜率评估。

### 18.5 正式链硬隔离

“不影响盘后正式结果”必须由结构和自动化测试共同保证：

1. 预跑使用独立入口、进程、锁和配置，不复用 `daily_run.sh` 或日报发布锁。
2. 预跑行情写入独立的只读输入快照或 `preclose` 数据命名空间，禁止写入正式 `market_history.sqlite`。
3. 预跑产物只写 `.cache/chanlun/preclose/<trade_date>/` 和独立 `preclose-worker` Durable Object，禁止写入 `docs/data/*.json`、`docs/index.html` 或正式日报目录。
4. 预跑禁止写入正式 `recommendation_ledger.jsonl`、策略记分卡、comparison index、shadow ledger 或 finalizer 状态。
5. 预跑可以调用现有策略模块的纯函数，但所有输入均使用独立对象；禁止修改 `run.py` 正式流程中的共享全局对象或为正式流程切换环境开关。
6. 盘后正式任务不导入预跑入口，不读取预跑路径；即使预跑失败、超时或 Worker 不可用，正式任务也必须照常运行。
7. 固定行情 fixture 下，先运行预跑再运行正式任务，与只运行正式任务相比，正式 `picks_pure`、`picks_fusion`、H4、加速池、正式动作、顺序和规范化 SHA-256 必须完全一致。
8. 预跑执行前后，正式数据库、正式账本和正式日报产物的内容 hash 与 mtime 必须不变。

第一版不在实现预跑时顺手重构正式 `run.py` 的选股阶段。即使存在编排重复，也优先保护正式链；共享核心的后续抽取需要单独的生产不变性设计和授权。

### 18.9 盘后差异口径与主动提醒

盘后复核器是独立只读进程，不嵌入 `daily_run.sh`，也不作为正式发布成功条件。它等待当日正式日报通过现有校验后，读取：

- 预跑：`main`、`h4_t3`、`acceleration` 三个冻结列表。
- 正式：对已通过正式日报校验的 JSON 调用现有 `chanlun.report_view_model.build_workspace()`，只比较页面实际展示的 `workspace.views.main`、`workspace.views.h4_t3` 和 `workspace.views.acceleration`。

不得直接把原始 `picks_fusion` 当作正式主推：当前页面会继续按 `decision_engine_v1.decision_code == "recommend"` 和输入健康状态过滤；绕过该投影会把“原始融合候选存在、用户界面没有正式推荐”误报为盘后差异。正式内容 hash 同样以这三个可见列表和正式合同字段规范化后计算。

每个池按股票代码计算：

- `retained`：预跑和正式均存在。
- `added_after_close`：预跑没有、正式新增。
- `removed_after_close`：预跑存在、正式未进入。
- `unchanged`：三个集合均无成员变化。

排名、参考价、信号类型和输入水位变化写入详细差异 JSON 和网页，不进入默认提醒，避免信息过载。同一股票跨池移动按“原池移出 + 新池新增”记录，不能静默合并。

有差异时：

```text
【盘后复核】与14:47预跑有变化
主推：保留 宁波方正｜正式新增 新朋股份｜预跑有、正式无 A股
H4 T+3：无变化
加速：正式新增 B股
```

完全一致时也必须主动提醒：

```text
【盘后复核】
正式结果与14:47预跑一致
主推2只｜H4 T+3 1只｜加速1只
```

若正式结果尚未成功生成，不得把故障伪装成空池，也不得发虚假的“无差异”：

```text
【盘后复核】
今日正式结果尚未生成，暂不继续参考预跑清单
```

提醒以 `trade_date + formal_content_hash + channel` 作为幂等键。正式任务重试但结果 hash 不变时不得重复发送；hash 变化时发送新的复核提醒，并在底层保留前后版本。

## 21. 测试边界

自动化测试至少覆盖：

- workspace 一级导航与研究池分组。
- 正式动作唯一性。
- 候选行标签上限。
- 主推荐空池在正常空池、数据不可用和正式动作封闭三种原因下均输出同一用户文案。
- 今日决策页 DOM、`title` 和无障碍文本不泄露内部状态或原因码，研究验证仍保留审计证据。
- 板块筛选不改变池身份和动作。
- 缺失/过期板块数据的 fail-close。
- 缺失正式合同字段不伪造值。
- 图表价标优先级、合并和数量上限。
- 策略样本门和右删失边界。
- PSY12 的 12 日窗口、零涨幅、日期去重、样本不足和防未来数据边界。
- PSY12 影子分不改变正式分、市场温度和决策门控。
- 预跑只调用日线、30 分钟和三个目标池的策略依赖，不调用新闻、LLM、iWencai 或 15 分钟链路。
- 预跑主推经过当前确定性市场情绪和 `decision_engine_v1` 门控；固定 fixture 下与 `workspace.views.main` 的公开筛选语义一致。
- 预跑成功、失败、超时和未运行四种场景下，正式结果规范化 hash 均与基线相同。
- 预跑执行前后，正式数据库、正式账本和正式日报产物 hash 与 mtime 不变。
- 14:49 输出硬截止、14:56:30 服务端与浏览器双重失效。
- 三池差异的保留、新增、移出、跨池变化、完全一致和正式未生成状态。
- 盘后提醒按正式结果 hash 幂等；正式重试不重复发送相同提醒。
- 盘后比较只消费 `build_workspace()` 投影的三个用户可见池，不直接比较原始 `picks_fusion`。
- 资产复制与日报 HTML/JSON 引用。

视觉验收必须使用真实生成页面和真实桌面截图，不能仅通过字符串测试宣布完成。

## 22. 主要风险

1. 为了让首屏“不空”又把所有指标搬回默认视图。
2. 把 `sector_flow` 误称为全市场热门板块。
3. 为补齐参考页面样式而临时推导仓位、周期和压力位。
4. 用多个策略结论替代唯一正式动作。
5. 仅增加图宽或图高，不实现标注车道和碰撞治理。
6. 将不同池、不同周期或不同入场口径的策略做统一排名。
7. 移动研究模块时丢失风险、版本和证据审计字段。
8. PSY12 与当日广度、指数重复计权，放大同一类上涨证据。
9. 历史复算误用报告日之后的数据，产生前视偏差。
10. PSY12 数据不足时用中性分补齐，制造不可验证的影子总分。
11. 为隐藏内部术语而删除底层失败原因，导致研究验证和排障失去证据。
12. 将整份报告加载失败误显示为“本期未选出推荐票”，掩盖真正的页面故障。
13. 预跑把盘中日线或正在形成的 30 分钟柱写入正式行情库，污染盘后输入。
14. 为复用代码重构正式 `run.py`，导致同一版本难以证明盘后结果不变。
15. 把预跑结果写入正式推荐账本、记分卡或比较索引，使研究和正式收益混算。
16. 盘后差异通知失败反向阻塞正式日报或改变正式任务退出码。
17. 向现有 Top10 Worker 增加预跑 Durable Object migration 或复用其 KV 合同，扩大回滚半径并导致快照串日或语义混淆。
18. 将 PSY12 影子分提前用于预跑选股，无法区分交易时点变化和新权重造成的信号漂移。
19. 盘后直接比较原始 `picks_fusion`，绕过页面正式动作和健康门控，产生虚假新增/移出。
20. 通知只检查 HTTP 200，不校验 WxPusher/企业微信业务 JSON，误报发送成功。

每个常驻字段都必须回答以下至少一个问题：

```text
它是否改变正式动作？
它是否改变下一确认条件？
它是否改变失效判断？
```

三个答案都是否定时，该字段不应常驻首屏。

## 24. 最终收口 Review 结论

**结论：Build small，可以实施，但必须按 P0-P4 的分阶段门槛上线。** 需求证据来自用户当前盘后交易难以成交的真实工作流，属于 L3 工作流阻塞；最高风险是 R1 信任/完整性风险——预跑污染正式链、错误比较正式可见池或把推送失败当作成功，会直接误导交易决策。

实现前已锁定四项关键修正：

1. 预跑主推不是原始融合列表，必须运行无新闻/无 LLM 的确定性市场情绪和当前决策引擎门控。
2. 盘后差异以 `build_workspace()` 的三个用户可见池为准，不以原始 `picks_fusion` 为准。
3. 预跑使用独立 `preclose-worker`，不修改现有 Top10 Worker 的路由、KV 或 Durable Object migration。
4. 手机提醒以本机已有凭证能力对应的 WxPusher 为主通道，企业微信仅作可选适配；成功必须校验供应商业务响应，密钥不得入库或写入日志。

上线验证顺序固定为：隔离 fixture → 全量回归 → Worker dry-run/真实回读 → `notify=false` 的真实交易日 14:47 影子运行 → 正式结果不变核对 → 启用真实提醒并做供应商响应验收。未完成真实交易日触发、盘后差异提醒和线上页面回读前，只能称为“已部署待生产验收”，不得称为“完全上线”。

具体执行步骤见同目录下的 `2026-08-27-decision-workbench-ui-optimization-implementation-plan.md`。
