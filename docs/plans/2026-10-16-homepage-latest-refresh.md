# 首页最新版本自动检查 Implementation Plan

**Goal:** 首页打开、返回及重新可见时检查已发布的新版本，发现更新后完整加载；覆盖同日开盘啦补更，历史日报保持固定日期。

**Architecture:** 在现有首页初始化中增加小型、有限的更新检查，不替换报告数据模型。以同源首页的 HTTP Last-Modified 与浏览器当前 document.lastModified 比较，取得有效更新证据后整页重载，避免新 JSON 与旧 bootstrap 混批；保留当前查询参数、页面锚点和访问授权。

**Tech Stack:** 现有原生 JavaScript、Fetch/AbortController、Python pytest/Node 离线夹具及真实浏览器验收；不新增依赖。

## 已验证问题与方案选择

1. resolveInitialData 优先内联数据。给定 14 日内联数据时不发任何新版查询；当前没有 pageshow/visibilitychange 检查。
2. 线上首页 Cache-Control:max-age=600；旧标签页可继续显示旧文档。当前服务端首页已为 16 日，用户客户端的具体缓存来源未被证明。
3. data/index.json 只有最新日期，没有同日版本；reportPublication 受现有题材补更保护，不能用它识别同日题材更新。
4. 真实浏览器验证：已加载旧版 document.lastModified=10/16/2026 15:58:12，补发后同源 HEAD 返回 Last-Modified=Fri, 16 Oct 2026 09:01:57 GMT；Date.parse 分别1792137492000与1792141317000，重新加载后文档时间对应17:01:57且题材可见。
5. 选择“HEAD 检查 + 必要完整重载”，避免每次拉取数MB JSON并改写旧页面上下文。HTTP元信息缺失、不可信、网络失败或离线时保留当前报告；CDN仍可能有传播窗口，不承诺查询参数能绕过所有缓存。

## 实施与验证步骤

### 1. 先红后绿复现更新检查缺失

文件：chanlun/report_assets/report-v2.js；新增 tests/test_homepage_latest_refresh.py，或复用仓库既有 Node/JS 行为夹具。

- 使用真实源 JS 的入口与事件注册，不以仅搜索字符串替代行为测试。
- 旧首页14日至新版16日、同日题材变更触发完整重载；新版未变化不重载。
- 历史日期页、比较页、file离线页不检查也不改日期；原访问权限保护不放宽。
- 网络失败、非成功HTTP、缺失/非法/不更新的Last-Modified、超时均保留当前页面。
- 首次加载、pageshow恢复、visibilitychange重新可见有效；隐藏时不主动拉取，事件重复去重，有限超时与节流，不开常驻轮询。
- 保留现有query（包括授权参数）与hash，不拼接跨源导航；同一目标版本失败重载不得循环。
- 关注/表单编辑未保存时不自动丢失内容，可等待安全时机。结合现有界面状态选择最小安全检测。
- 先运行专测并记录基线失败，再实施最短修复并运行通过。

### 2. 实现最短更新路径

- 新增纯逻辑/控制器可测试边界，复用现有init入口；不重构整个init或新增通用加载框架。
- 只在在线首页安装事件；同源HEAD使用cache:no-store及有限超时，可加请求级查询参数避免浏览器复用旧响应。
- 比较有效的服务器时间与当前文档时间；不使用只含日期的manifest作为唯一判断，不将新增数据塞进旧bootstrap。
- 整页导航保留页面位置和参数；记录有限版本标记，防止CDN暂时回旧内容形成重载循环。
