# 2026-09-22 分钟数据诊断与研究观察修复设计

## 1. 本批目标与基线

本批以 `origin/main@3fd510c4e98e7727489105b8474dc9c072010c76` 为唯一代码基线，固定使用 2026-09-21 已保存的 29/60/56 范围做回归，不重跑、不覆盖当日已发布报告、冻结清单或正式账本。

交付拆成两个可独立回滚的提交：

- A：补齐分钟行情失败证据，修正强启动诊断与候选漏斗语义。
- B：把 56 只既有强启动观察对象投影到现有观察入口，明确研究属性并阻断正式链路。

不能退化的能力：现有正式选股、排序、执行资格、L1 v0、B0、H4、次日确认、已有观察项和历史报告读取。允许的局部降级：外部行情源失败时分钟输入继续缺失，但报告必须能解释失败和缓存弃用原因。

## 2. 方案比较

### 方案一：扩展现有诊断合同，只扩大最终观察展示（采用）

分钟抓取沿现有 provider → repository → run 诊断链透传受限证据；观察侧保留当前 `startup_watchlist`，只把被共同上游过滤掉的研究对象按身份合并进 `observation_watchlist`。L1 与其他正式消费者显式拒绝研究投影。

优点：调用链最短、原正式入口不变、无新池、可分别回滚。代价：需在多个既有层增加少量兼容字段和边界测试。

### 方案二：新增研究观察池（不采用）

单建一个 56 只研究池，前端再增加入口。实现清晰，但违反“复用现有观察入口、不新增重复推荐池”，还会增加来源映射、页面与发布合同。

### 方案三：直接扩大 `startup_watchlist`（不采用）

将共同上游过滤前结果直接作为启动观察列表。改动最少，但 `next_day_boom`、L1 原始池及其他消费者会读取该列表，容易把研究对象带入正式或后续确认链路。

## 3. A 批设计：分钟数据失败证据

### 3.1 证据采集与隐私

每次分钟源尝试仅保存以下字段：交易日、标准化标的身份、周期（15m/30m）、provider、尝试序号、结果类型、HTTP 状态码、响应 `Content-Type`、受限响应摘要或异常类别。

- 有 HTTP 响应但无法使用时，保存截断且净化后的文本摘要；不保存完整正文。
- 无响应时区分 timeout、connection、HTTP、decode、validation 和 unknown 等类别。
- 不保存 URL、请求头、Cookie、token、完整查询参数或原始异常堆栈。
- 摘要先去控制字符并截断；任何疑似凭证值都不得进入结果。

四次交替尝试仍沿用现有策略，不增加 provider，不默认增加重试，也不改成无上限重试。

### 3.2 失败透传

远端尝试全部失败时，由抓取层抛出携带安全诊断的专用异常；repository 捕获后把诊断写入本次 `KLineResult.diagnostics`。它不是业务异常外泄，不改变数据库结构，也不把失败结果伪装成有效 K 线。

批量 15m/30m 读取增加可选的诊断接收参数，保持现有返回值兼容。对最终缺失项补充：

- 最后可用缓存日期、缓存状态、是否过期、缓存条数；
- 最终是否采用；
- 拒绝原因（例如缓存过期、当日数据缺失、所有远端源不可用）。

`sublevel_input_health` 在原计数和代码列表之外增加按标的保存的失败证据。只记录本次缺失项，不回写历史报告。

### 3.3 强启动三分法与兼容字段

强启动诊断新增三个互斥计数：

- `startup_candidate`：30 分钟输入有效且独立确认成立；
- `watch_missing_30min`：分钟输入无效或缺失；
- `watch_valid_no_confirm`：分钟输入有效但独立确认不成立。

保留旧字段：`watch_due_to_no_30min_confirm` 等于后两项之和；`dropped_no_30min_confirm` 保留为兼容别名并明确它仅表示分钟输入缺失数量。新消费者必须使用新字段。

### 3.4 候选漏斗语义

观察不再等同于通过 30 分钟门。漏斗分别保存：

- `minute30_input_status`：有效、缺失或未要求；
- `minute30_confirmation_status`：已确认、待确认或未评估；
- `final_display_state`：正式候选、观察或未展示。

只有真正完成确认的候选才能通过 `minute30`。缺失输入是“未评估/数据不足”，有效但未确认是“评估未通过/待确认”，两者都不能记录为通过。

## 4. B 批设计：研究观察投影

### 4.1 投影范围

从本次运行中共同上游过滤前的强启动观察结果生成研究投影，不在产品代码中硬编码 56 只股票。固定 56 清单只用于回归验收：52 只显示“待确认”，4 只（`002845`、`600392`、`600683`、`688410`）显示“分钟数据不足”，且保留日线依据。

### 4.2 身份去重与合并

投影与现有 `observation_watchlist` 按标准化证券身份去重。若同一身份已存在：

- 合并来源、状态、风险、条件和日期；
- 保留既有更具体的字段，不用空值覆盖；
- 研究投影只追加其来源与研究状态，不复制成第二条推荐。

投影项明确写入：`research_observation_projection=true`、`affects_formal=false`、`is_executable=false`、`eligible_for_l1_v0=false`，并给出稳定的展示状态与中文标签。

### 4.3 正式链路隔离

不修改 `picks_pure`、`picks_fusion`、正式身份、评分、排序、可执行资格或 H4。`startup_watchlist` 保持当前受限结果，避免影响次日确认。L1 原始列表和 workspace 视图均显式过滤 `eligible_for_l1_v0=false` 的投影项；B0 与冻结 L1 输出在固定输入下保持不变。

## 5. B01—B10 影响边界

- B01 行情与缓存：A 批影响，保持旧缓存不冒充当日数据。
- B02 资格与召回：A 仅修诊断；B 仅扩研究展示，不扩大正式召回。
- B03 信号与确认：A 修正“缺输入/无确认/已确认”语义；不改确认阈值。
- B04 评分与排序：不适用；固定输入前后必须相同。
- B05 观察跟踪：B 批影响；只复用现有观察入口。
- B06 预跑与盘后：只增加本次运行诊断和研究投影，不回写历史。
- B07 正式数据与身份：不变；以 `affects_formal=false` 和消费者过滤保护。
- B08 报告与推送：报告展示新状态和失败证据；本批不授权发送通知。
- B09 数据安全与幂等：无数据库迁移、重建或正式写入；按身份去重。
- B10 发布与回滚：A/B 独立提交；未获得发布授权时只交付代码和证据。

## 6. 验收标准

- 固定 29/60 缺失范围能产生逐标的、逐周期、逐 provider 的安全失败证据，缓存日期和弃用理由可追溯。
- 强启动诊断能区分缺失输入、有效未确认、已确认，旧字段仍可读且解释同步。
- 候选漏斗不再把观察项统一记为通过 `minute30`。
- 固定 56 范围为 52 个“待确认”加 4 个“分钟数据不足”，按身份无重复。
- 研究投影不进入 L1 v0、B0、正式候选、评分、可执行动作或 H4；正式统计在固定输入前后不变。
- 保留 `dropped_risk_guard=123` 为尚未定位的既有风险尝试，不据此补跑历史或推断原因。
