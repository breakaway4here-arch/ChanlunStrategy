## 1. 用户可见的最终结果

### 1.1 顶部只保留一个「主推」入口

原“正式推荐／正式主推”“正式结果”“优先关注”不再分别占一个同级入口，也不再作为三个重复的快捷卡片。

原“正式待确认”移为「主推」内的状态筛选或状态标签，不再铺出一组重复同级名单。其他“全部”、研究来源选择、风险查看和现有业务模块保持，不重新设计整站导航。

**这是入口合并，不是把三个概念强行改成一个新的策略。**内部来源标识、策略角色、原始正式结果统计、状态和通知语义保留。详细审计中仍允许出现“正式主推”等历史来源原名。

### 1.2 不展开就能看见命中数量与池名

股票卡片及详情头部使用同一摘要，建议结构：

```text
XD立昂微  605358                         [命中 2 池]
[等确认]  [罗姐池]
研究观察 · 当前条件/风险……
```

- 数量徽标紧邻名称，颜色醒目、数字加粗。
- 池名各有固定颜色；有几个已确认来源池，就显示几个来源标签。
- 图表上方的详情头部也直接显示，不放进“来源策略与完整证据”的折叠区。
- 风险、条件及原有评分仍显示，不为腾地方删除或遮住它们。
- 手机可以自然换行；命中数及已知来源池名不能只靠悬停、点击或展开才能看到。

## 2. 「主推」的集合约定——不能只改名字或丢掉原名单

### 2.1 使用三个旧入口的并集，按证券身份去重

本批确定：

```text
新主推 = 旧正式推荐入口集合 ∪ 旧正式结果集合 ∪ 旧优先关注集合
```

三个输入都从同一报告日期、同一阶段、同一快照的现有有效展示记录读取，保持原有可见范围和来源安全处理。不是无条件把所有原始融合候选塞进主推。

- 按现有规范证券身份去重，不只按名称去重；一只股票一张卡。
- 新主推不沿用旧优先关注“至多5项”的全局截断。旧优先集合本身可仍为最多5项，但不能用它替换整个并集。
- 主推/H4等正式结果继续保留各自策略身份和分数。
- 旧优先关注未来若含 `waiting_trigger` 的研究对象，该对象仍标“研究待条件”，不能因进入合并入口变成正式推荐或可执行。
- 主推首先是一个阅读入口。计数是该入口去重股票数，不替代正式主推、H4等业务统计。存在正式与研究混合时，用一行简短说明区分数量，不再增加多个同级池。
- 原优先排序只影响旧集合成员，不新增评分或重新排名。并集中的规范对象沿用现有统一清单的相对顺序；只有旧入口中的合法记录尚无规范对象时，保留其原顺序并采用已有旧版详情路径，不为补标签重建策略数据。
- 并集为空时，正常显示“本期暂无主推”；不给它从全部研究池自动补票，不影响日报发布。

**9月16日固定样本预期：主推仍只有华伍股份300095、莱特光电688150；分数分别61、71；两只都仍为条件待补充、不可执行。**这些数值是回归样本，不是以后每天必须满足的固定数量。[S1/S2]

### 2.2 导航、计数和点击用同一集合

更新范围限于本次直接关联：入口名称与默认选中、列表集合、计数、首页候选快捷入口、主推内状态筛选、搜索和清空搜索、分页/加载更多、比较选择、详情返回及旧入口状态恢复。

推荐复用现有 `decision_formal` 作为唯一主推的**导航内部键**并扩展其列表选择语义；若当前代码已有等价主入口，复用即可。不得用“未知 key 默认返回全部”的行为承载主推。

旧 `decision_focus`、旧 `main` 等导航链接或本地保存选择，应在**导航解析边界**转到主推；旧待确认链接进入主推并选中对应状态筛选。源策略键 `main`、`h4_t3`、`sources`、`source_refs`、原报告字段绝对不能全局替换。

旧正式来源的统计、账本、通知或可执行判断若依赖共享函数，必须保持它们原有语义；主推并集另用局部阅读选择函数，不改变底层 `isFormalWorkbenchItem` 的定义。原 `featured_ids` 可继续存在于报告和通知中，隐藏重复入口不等于删除它。

## 3. 彩色标签的计数约定

### 3.1 「命中 N 池」统计实际来源池，不统计页面出现次数

计数来自当前快照统一对象的 `strategy_results`、`source_refs`、`sources` 等已有关系；不只读默认 `candidate.source_labels`，也不把它们的数组长度相加。

同一股票在同一池重复记录或多个版本中出现，摘要按一个来源池计数，原版本、合同、风险和详细记录仍分别保留。颜色及数量只表达归属，不生成新的“共振评分”，也不宣称独立策略一致看多。

本批固定分类：

| 来源类别 | 典型已有标识 | 计入N | 显示规则 |
|---|---|---:|---|
| 融合/正式主推来源 | `main` / `picks_fusion` | 是 | 正式身份明确时标“主推策略”；否则标“融合候选”，不升级身份 |
| H4来源 | `h4_t3` / `h4_t3_pool` | 是 | “H4”，保留正式策略自身状态 |
| 加速来源 | `acceleration` / `next_day_boom` | 是 | “加速池”，保留研究身份 |
| 罗姐来源 | `luojie` / `luojie_pool` | 是 | “罗姐池” |
| 启动/等确认来源 | `confirming` / `startup_watchlist` | 是 | “等确认” |
| 基础来源 | `baseline` / `picks_pure` | 是 | “基础候选·上游”；算来源，不算第二次独立正式推荐 |
| 看点榜 | `highlights` | 否 | 独立淡色“收录：看点榜”标签 |
| 观察Top5 | `observation_top5` | 否 | “收录：观察Top5”，不因其物理ref不同额外算一个池 |
| 高弹性榜 | `growth_quality` | 否 | “收录：高弹性观察”，不额外增加来源命中数 |
| 主推/全部等导航 | `decision_*` 等 | 否 | 页面入口不是策略来源 |

可用已有明确ref识别派生榜单背后的来源，例如看点榜明确引用 `luojie_pool`，其底层来源可计一次罗姐。不能凭“观察Top5”名称反推出并未记录的启动池来源；没有可核对底层来源时显示“来源待补”。

这里的 N 包含基础候选等上游来源，是**来源池数量**，不是N套相互独立的策略共识。模块首次说明处写一句“按来源池计数，含上游基础池；榜单重复收录不叠加”，无需每只股票重复免责声明。

### 3.2 固定样本的目标输出

### 3.3 过滤、旧视图与缺失数据

- 搜索或切到罗姐专用页时，仍能看见该股票同日报告里的全部已知来源；不能因当前页面仅一个池，就把“命中2池”变成“命中1池”。
- 对专用页的旧行，按当前报告/阶段/快照及证券身份查回已有统一对象，仅读取来源摘要；不换默认图表ref，不用另一个来源覆盖现有价格和合同。
- 不跨日期合并来源；昨天入选不能算今天命中。
- 未识别来源保留灰色原始标识；确定来源数只统计已识别且有依据的部分，写“已知命中N池 · 有来源待识别”。完全缺失时写“来源待补”，不伪造“0池”或默认“一池”。
- 不因标签缺失、映射未知或来源摘要异常，阻止该股已有信息或整份日报输出；仅此来源行降级，原因可见或可追踪，不吞掉其他产品异常。

## 4. 视觉规格：颜色固定，数量醒目

以下颜色是本批建议设计令牌，不是市场涨跌含义。

### 4.1 数量徽标

| 状态 | 样式 |
|---|---|
| 命中1池 | 浅蓝底、深蓝字，仍显示实际数字 |
| 命中2池 | 蓝色实底 `#1D4ED8`、白字，数量加粗 |
| 命中3池及以上 | 紫色实底 `#6D28D9`、白字，始终显示真实N，不只写“多池” |
| 来源待补/待识别 | 灰色边框与明确文字，不用红色警报占满卡片 |

数量徽标是位置和信息强度区分，不代表池越多收益越高或自动更安全。风险色不被替换，不能用“多池命中”覆盖“条件待补充”。

### 4.2 来源池标签

| 标签 | 文字色 | 背景色 | 视觉识别 |
|---|---|---|---|
| 主推策略/融合候选 | `#1D4ED8` | `#EFF6FF` | 蓝色 |
| H4 | `#4338CA` | `#EEF2FF` | 靛蓝 |
| 罗姐池 | `#7E22CE` | `#FAF5FF` | 紫色 |
| 等确认 | `#0F766E` | `#F0FDFA` | 青绿 |
| 加速池 | `#9A3412` | `#FFF7ED` | 橙色 |
| 基础候选·上游 | `#475569` | `#F1F5F9` | 蓝灰 |
| 榜单收录 | `#52525B` | `#FAFAFA` | 中性灰、细边框/虚线，不与来源池混排计数 |

标签有可读文字、适度边框和内边距，不能只有彩点。数量徽标建议14px加粗，池名13px左右；可根据现有样式微调，以桌面和手机实际可读为准。颜色映射在列表、比较标题及详情中一致。

卡片名称行和来源行使用可换行布局、`min-width: 0`；来源标签自身不逐字拆开。不要用固定卡片高度裁掉最后几个池；不依赖hover tooltip；不把标签塞进图表工具栏。

## 5. 实现落点与最短步骤

依据上轮已核查结构，主要文件是：

- `chanlun/report_assets/report-v2.js`：`decisionRows`、`decisionNavigation`、默认入口/旧状态迁移；`renderCandidateList` 及身份行；统一详情头部；旧视图来源摘要适配。
- `chanlun/report_assets/report-v2.css`：数量徽标、池标签、来源行及小屏换行。JS/CSS均使用局部类名，避免改变所有tag样式。
- 对应的现有前端定向测试；必要时增加一个小测试文件，不重建测试体系。
- `docs/assets` 及相关页面的资源引用：只通过现有发布资源同步流程更新。

建议只新增/复用两组局部纯读取函数（名称可贴合现有代码）：`selectPrimaryDisplayItems()` 负责主推集合，`getPoolHitSummary()` 负责来源摘要；渲染器不各写一套计数规则。

实施顺序：

1. 固定最新工作树和这批差异；读项目规则。现有改动如果已实现某项，复核后跳过，不回退旧代码。
2. 用冻结16日数据记录旧三个集合与统一80只身份集合；按第2节做主推入口和别名适配。
3. 用第3节样本实现来源计数，再挂到列表、详情和比较对象标题的可见位置；先读关系，不动原始对象。
4. 按第4节加局部CSS，实际打开桌面/手机看换行及风险信息是否被挤掉。
5. 按第6节验证直接关联；按现有有效授权发布。给出真实源码、资源和线上数据日期，不用“本地通过”代替上线。

禁止将本批扩展为：新共振分、按命中数重排、正式/研究合同自动归约、策略权重调整、补全均线分钟数据、新实时接口、重跑生产日报、回写历史报告/账本或新增通知。
