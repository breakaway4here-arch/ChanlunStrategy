## 2. 本批目标

让下列场景形成闭环：

> 一笔真实发布的观察已经到期，但本地缺少起点或目标收盘 → 分类为可恢复的行情缺口 → 在既有预算内复用本地证据或尝试取得合格响应 → 经现有价格及身份校验重算 → 获得结果或保留明确缺口。

保留尚未到期、明确排除、日期未知、证券冲突、确证没有有效成交收盘等不同状态；不能将全部 `missing_price` 无条件发到网络请求队列。

## 3. 开工时只做必要核对

读取当前 `AGENTS.md` 和直接相关规则；确认工作树、分支及提交，保留用户改动和已上线修复。参考 SHA 仅为定位，不要求回退本地更新版本。

先用本地已保存的派生结果，按周期与 reason_code 列出 `missing_price`、`price_basis_unverified`、`waiting`、`excluded` 等数量；核对一只证券跨周期重复计数，另列独立证券数量。

随后用实际正常入口及最小合成夹具复现“已到期可恢复缺价没有进入恢复链”。行情网络响应可以用明确标记的固定测试响应替代，不对生产发请求。若最新代码已有等价恢复能力，应给出正常入口的反例通过证据，避免重复实现。

当前真实数据没有可恢复缺价样本时，标明“本次真实命中数为 0，修复面向已复现的缺价场景”；不能伪造一笔真实缺价，也不将这一点扩大为整站阻断。

## 4. 最短修改链

### 4.1 统一恢复资格判断

复用现有帮助函数或增加一个小型、可测试的恢复资格函数，供候选选择、待补状态及新响应采纳共同使用。不要在三个地方各维护一套互相不同的状态白名单。

| 情况 | 本批处理要求 |
|---|---|
| 已发布、已到期，有收盘价但缺同序列证明 | 保留现有恢复路径与保护 |
| 已发布、已到期，本地没有起点或目标收盘记录 | 在身份、日历可核验且没有确定无成交依据时，允许进入受限恢复 |
| 目标尚未到或目标日尚未收盘 | 不补未来价格，保留待到期 |
| 历史目标日已过，但已有记录未确认 | 区分采集未完成和确证无有效收盘；不得自行盖章 final |
| 目标停牌或确证零成交量，无合法目标收盘 | 不伪造结果；不因每次构建无限重试 |
| 证券冲突、日历无法定位、明确事故排除 | 继续按原保护隔离，不能当成普通价格缺失 |
| 原因信息不足 | 保留缺口，不填零；已有信息足以定位可尝试端点时可有界尝试，不以新必填字段误拒绝全部旧记录 |

资格按实际状态、原因和目标日期判断；日期依据为数据集的 `evaluation_as_of`，不是浏览器或任务运行当天。

### 4.2 有界获取，不扩大采集工程

沿用现有“优先已保存证明，再补取”的路径；同证券一次合格响应供多个观察和周期复用。不得把六周期变成六次独立请求。

默认继续限制为每次更新最多 1 只证券、最多 2 次请求，并沿用现有 20 秒请求预算。它不是整个表现重建耗时的上限；交付时分别记录网络请求/等待与重算耗时。已有尝试轮转和失败处理继续有效，不新增无限循环，不硬编码验证用股票。

本任务书不另授实际联网权限。实现与测试可先用本地固定响应；实际联网、生产目录同步及部署按当前任务有效授权执行，不自动援引其他任务的历史授权，也不逐步骤重复询问已有有效授权覆盖的动作。

### 4.3 采纳以缺口真正解决为准

不能只将选择器改成 `status in (...)`，而保留后续仅识别 `price_basis_unverified` 的旧判断。

新响应应按已有规则检查证券身份、请求窗口、前复权序列、原始响应、实际起止日期、已确认且有合法成交依据的收盘。不能借其他证券、另一根 K 线或另一份不相容序列补端点。

验证它是否真正让目标缺口变为可计算结果。残缺响应、零成交量端点或存在冲突的证明，不因 HTTP 成功就停止必要的备用尝试。期间缺中间 K 线不能无故使已核验端点收益失败，除非受影响的是另一个需要完整路径的指标。

保留 `evaluation_as_of` 与实际取证时间的区别；后取历史证明不推进收益截止。

### 4.4 重算、状态与发布

合格响应进入正常构建器，修复对应样本/周期的结果和必要聚合。复用现有派生写入与成组三文件发布，不能只打印“补齐成功”而不更新实际消费的数据集。

不改变明确排除来源的结果；同股另一有效来源的可用结果不被误清空。缺价未解决时保留原因及尝试情况，不能显示为“无需补齐”。

既有 `status=ready` 可继续表示数据集成功生成，但必须与 `evidence_fill` 及逐周期状态分开解释，不把它重新定义成所有样本均可计算。失败不得将旧可用结果替换成全零，亦不得用旧结果假冒新截止。

| M05 | 未到期、盘中目标、日期未知、明确排除、确证无成交收盘 | 不误生成收益，不用下一根 K 线顶替 |
| M06 | 第一响应残缺，第二响应满足真实采纳条件 | 仍在原请求/时间预算内采用合格结果 |
| M07 | 两次请求均失败、证明冲突或响应未解决目标缺口 | 缺口和尝试状态准确，旧有效结果不丢；不称无需恢复 |
| M08 | 同证券多周期/多入选日，只有部分到期缺口被解决 | 精确更新对应结果；其余状态及总数能核对 |
| M09 | 同证券存在事故排除来源及有效来源 | 各来源、总体、题材、策略聚合沿用现有正确隔离 |
| M10 | 合格证明已经保存，再次调用正常入口 | 目标复用本地证明；不为同一已解决缺口重复请求。其他待补证券是否请求按既有策略说明 |
| M11 | 已通过的长期保存、热点导航、原正式三周期与六周期基本计算 | 定向回归通过，不重新修改页面结构或策略分数 |
